# Спецификация: интеграция с doc-html-translate (EPUB_2_HTML) - перевод изображения в браузере

Статус: реализовано (сборка 2026-07-14) - см. §14 «Итог реализации»
Дата: 2026-07-14, ревизия 1

Замороженный контракт запуска на стороне компаньона (авторский, не менять из этого
репозитория): `P:\WINDOWS\EPUB_2_HTML\docs\integration-image-translate.md`.

---

## 0. Что послужило триггером / идея

У нас уже есть свой путь «OCR + перевод»: распознавание текста Tesseract и наложение
перевода плашками прямо в приложении (кнопка «Перевод», горячие клавиши `T` / `Shift+T`,
пайплайн в `src/Main_Form.OcrTranslate.vb` / `src/Main_Form.OcrOverlay.vb`). Перевод
идёт через локальную LLM (Ollama) или LibreTranslate.

У того же автора (SZA) есть отдельный продукт **doc-html-translate** (репозиторий
`P:\WINDOWS\EPUB_2_HTML`). Он умеет то, чего у нас нет и что нам дорого делать самим:
**отдать картинку браузеру и перевести её бесплатным переводчиком Chrome/Edge**
(«Перевести страницу» = движок Google), наложив распознанный текст настоящими
HTML-плашками поверх изображения - без API-ключа и без аккаунта. Это тот же механизм,
что в их браузерном расширении, но выставленный наружу как обычный вызов
`doc-html-translate.exe <путь-к-картинке>`.

**Позиционирование (продуктовая рамка).** В рамках нашего проекта doc-html-translate
подаётся как компаньон: (а) просмотрщик документов с переводом и (б) «сотрудник» для
демонстрации изображений с бесплатным переводом от Google. Связь взаимная: README
самого doc-html-translate уже отсылает пользователя к Fast Media Sorter для одиночных
картинок - два продукта задуманы как дополняющие друг друга.

**Суть фичи.** При показе **изображения**, если doc-html-translate установлен, показать
рядом с кнопкой «Перевод» вторую кнопку - с его иконкой, - которая открывает **текущее
изображение** в doc-html-translate (бесплатный перевод в браузере). Это не замена нашему
встроенному OCR-оверлею, а второй, альтернативный маршрут перевода «наружу, в браузер».

Попутное требование от владельца: кнопку «Перевод» (и новую кнопку-компаньон) показывать
**только для статичных изображений** - не для видео и не для анимации.

## 1. Цель и рамки

В рамках:

1. Добавить в тулбар вторую кнопку перевода - **«Перевод в браузере»** с иконкой
   doc-html-translate, открывающую текущее изображение вызовом `doc-html-translate.exe`
   (headless-маршрут, выбран владельцем: конвертация идёт напрямую, результат
   открывается сразу в браузере по умолчанию).
2. Показывать **обе** кнопки перевода только когда текущий носитель - статичное
   изображение (не видео, не анимированный GIF). Это изменение существующего поведения:
   сейчас кнопка «Перевод» видна всегда.
3. Кнопку-компаньон показывать только когда doc-html-translate **обнаружен** (по ТЗ
   владельца: «если эта программа установлена - показать кнопку»).

Вне рамок:

- Любые изменения кода doc-html-translate / EPUB_2_HTML. Их контракт запуска заморожен
  (раздел 2) и живёт в их репозитории.
- Браузерное расширение doc-html-translate (его нельзя вызвать запуском exe с путём -
  не наш маршрут).
- Изменение нашего собственного OCR-оверлейного пайплайна (Tesseract/Ollama/Libre).
- Тег/релиз. Это обычная **сборка** (`build.ps1`), без `v*`-тега.

## 2. Замороженный контракт запуска (сводка; первоисточник - у компаньона)

Полностью описан в `P:\WINDOWS\EPUB_2_HTML\docs\integration-image-translate.md`. Ниже -
только то, что нужно нашей стороне. **Если сводка разойдётся с первоисточником -
первоисточник главнее.**

**Формат вызова:**

```
doc-html-translate.exe [флаги] <путь-к-изображению>
```

- Путь к картинке - **позиционный** аргумент (не флаг). Кавычить, если есть пробелы.
- Поддерживаемые типы: `.png .jpg .jpeg .webp .gif .bmp .tif .tiff`.
- Для изображения **OCR + оверлей включаются автоматически** - флаг `-ocr` не нужен.
- Без флага перевода (`-google` / `-ollama`) приложение само не переводит - открывает
  страницу, а перевод делает браузер. Это и есть целевой «бесплатный» поток.

**Рекомендованный вызов (наш):**

```
doc-html-translate.exe -ocr-lang <языки> -folder <кэш-папка> "<путь к изображению>"
```

**Флаги, значимые для нас:**

| Флаг | Назначение | Наше решение |
|------|-----------|--------------|
| `-ocr-lang <коды>` | язык(и) Tesseract текста на картинке (`eng`, `rus`, `eng+rus`, `jpn`..). Определяет точность OCR. | Передаём, маппим из наших настроек OCR (раздел 6.2). |
| `-src <lang>` | подсказка исходного языка, запасной для `-ocr-lang`. | Не используем - `-ocr-lang` прямее. |
| `-folder <dir>` | выходная папка. По умолчанию - подпапка **рядом с картинкой**, названная по ней. | **Обязательно задаём** свою кэш-папку (раздел 6.3), чтобы не мусорить рядом с файлами пользователя. |
| `-force` | переOCR даже если результат уже есть. Без него повторный вызов просто заново открывает закэшированную страницу (быстро). | По умолчанию **не** передаём (хотим кэш). Опционально - по `Shift`+клик (раздел 6.4). |
| `-noopen` | конвертировать, не открывая браузер. | **Не передаём** - нам нужно, чтобы браузер открылся. |

**Что происходит при вызове:** картинка копируется в выходную папку и оборачивается в
`index.html`; Tesseract распознаёт текст → он становится непрозрачными плашками, точно
позиционированными поверх картинки; `index.html` открывается через ОС-обработчик по
умолчанию (`cmd /c start "" <index.html>`), то есть **браузером по умолчанию**. Чтобы
всплыло предложение перевода, браузером по умолчанию должен быть **Chrome или Edge**.
Плашки - настоящие текстовые узлы HTML, поэтому «Перевести страницу» переписывает их на
месте. Если Tesseract недоступен, страница всё равно открывается и показывает картинку
без плашек (оверлей - best-effort, никогда не фатален).

**Коды выхода:** `0` - успех; `1` - плохие аргументы (нет входного файла); `2` -
ошибка ввода-вывода; `3` - ошибка разбора/извлечения; `4` - ошибка API перевода (в
бесплатном потоке изображения недостижима).

**Зависимость Tesseract (на стороне компаньона).** Портейбл/winget-сборка
doc-html-translate **не тащит** ни `tesseract.exe`, ни языковые данные - только два exe.
Движок ищется так: env-переменная `DOCHT_TESSERACT` (полный путь к `tesseract.exe`) →
папка `tesseract\tesseract.exe` рядом с `doc-html-translate.exe` → `tesseract` в `PATH`.
Языковые данные (`*.traineddata`) берутся из tessdata этой установки Tesseract; их можно
дотянуть на месте (`doc-html-translate.exe -ocr-download rus`). Это забота компаньона,
не наша (см. раздел 6.5 про то, почему мы **не** задаём `DOCHT_TESSERACT`).

## 3. Пользовательский сценарий

1. Пользователь листает картинки в Fast Media Sorter.
2. На статичном изображении в тулбаре рядом с «Перевод» видна вторая кнопка с иконкой
   doc-html-translate (только если он установлен).
3. Клик по ней → приложение вызывает `doc-html-translate.exe` с текущим файлом → через
   пару секунд в браузере по умолчанию открывается страница: картинка + распознанный
   текст плашками. Пользователь жмёт «Перевести страницу» (Chrome/Edge) - и видит
   перевод от Google поверх изображения, бесплатно.
4. На видео и на анимированном GIF **обе** кнопки перевода скрыты.
5. Если doc-html-translate не установлен - кнопки-компаньона нет (поведение по
   умолчанию; необязательная «витрина установки» - раздел 7).

## 4. Поведение: видимость обеих кнопок перевода (изменение существующего)

### 4.1 Единое определение «статичного изображения»

Сейчас видимость `btn_Translate` не трогается нигде - кнопка есть всегда (проверено в
`src/Main_Form.OcrTranslate.vb`; клик по не-картинке просто выставляет статус «не
изображение»). Вводим одно определение и завязываем на него обе кнопки.

Новый хелпер рядом с `IsCurrentFileEligibleImage()` (`src/Main_Form.OcrTranslate.vb`):

```vb
' Статичное изображение: расширение картинки, файл существует, показывает PictureBox,
' и это НЕ активная анимация (мульти-кадровый GIF крутит gif_Restart_Timer).
Private Function IsCurrentStillImage() As Boolean
    Return IsCurrentFileEligibleImage() AndAlso gif_Restart_Image_Ref Is Nothing
End Function
```

Обоснование сигнала анимации: `gif_Restart_Image_Ref` выставляется только для
мульти-кадрового GIF (`StartGifLoopPlayback`, `src/Main_Form.GifPlayback.vb`: требует
`RawFormat = Gif` и `GetFrameCount > 1`); для статичного (одно-кадрового) GIF и любых
не-GIF он `Nothing`. `StartGifLoopPlayback` вызывается внутри загрузки картинки, **до**
финального хука (раздел 4.3), так что к моменту пересчёта видимости сигнал уже верный.

Крайний случай: анимированный WEBP сейчас отображается как один статичный кадр (у net48
нет декодера анимации WEBP - см. `SPECIFICATION_DOTNET10_MODERN_BUILD.md`), поэтому он
трактуется как статичная картинка. Это приемлемо: пользователь видит один кадр, его и
переведём.

### 4.2 Правила видимости

- `btn_Translate` (наш OCR-оверлей): `Visible = IsCurrentStillImage()`.
- Кнопка-компаньон `btn_TranslateBrowser`:
  `Visible = IsCurrentStillImage() AndAlso DocHtmlTranslate.IsAvailableCached()`.

`DocHtmlTranslate.IsAvailableCached()` - **кэшированный** флаг доступности компаньона
(раздел 5.2), чтобы на каждой навигации не дёргать реестр/PATH.

### 4.3 Единая точка пересчёта

Пересчитывать в `OnMediaDisplayed()` (`src/Main_Form.OcrTranslate.vb`) - это финальный
хук, вызываемый в конце `UpdateCurrentFileAndDisplay` (`src/Main_Form.MediaLoading.vb`)
после обоих путей (картинка/видео) и после ветки «нет файлов». Там уже вызывается
`UpdateOcrButtonVisual()`; добавляем рядом установку `.Visible` обеих кнопок. После
изменения ширины/видимости вызвать `LayoutToolbar()` (перекладка тулбара) - как это уже
делает `UpdateOcrButtonVisual`.

> Не использовать `UpdateControlVisibility` (`Main_Form.MediaLoading.vb`) - она срабатывает
> несколько раз в процессе загрузки, до финальной фиксации кадра.

## 5. Обнаружение doc-html-translate и его иконка

### 5.1 Новый модуль-лаунчер

Новый файл `src/DocHtmlTranslateLauncher.vb`, модуль по образцу `OllamaManager`
(`src/Translate/OllamaManager.vb`) - тот же паттерн «найти exe → проверить установку →
запустить». Публичная поверхность:

```vb
Public Module DocHtmlTranslate
    Public Function FindExe() As String      ' путь к doc-html-translate.exe или ""
    Public Function IsInstalled() As Boolean  ' FindExe().Length > 0 (может лезть в реестр/PATH)
    Public Function IsAvailableCached() As Boolean  ' кэш для UI-потока (раздел 5.2)
    Public Sub RefreshAvailabilityAsync()     ' фоновой пересчёт кэша
    Public Function TranslateImage(imagePath As String, ocrLang As String, force As Boolean, ByRef err As String) As Boolean
End Module
```

### 5.2 Порядок поиска exe (в `FindExe`)

По убыванию надёжности (первый успех выигрывает; см. контракт §3-4 и
`OllamaManager.FindExe`):

1. **Наш бандл (если решим класть рядом):** `<папка приложения>\doc-html-translate\doc-html-translate.exe`.
   Самый надёжный вариант - абсолютный путь, детект не нужен. (На старте фичи можем не
   бандлить; пункт зарезервирован.)
2. **winget-алиас:** `%LOCALAPPDATA%\Microsoft\WinGet\Links\doc-html-translate.exe`
   (портейбл/winget-установка кладёт алиасы туда, они же в `PATH`).
3. **Скан `PATH`** на `doc-html-translate.exe` (эквивалент `where doc-html-translate`).
4. **Реестр (HKCU):** `HKCU\Software\Classes\Applications\doc-html-translate.exe\shell\open\command`
   - записывается, когда GUI (`doc-html-ui.exe`) хоть раз запускался; из строки достать
   путь к exe. (У doc-html-translate нет ключа `App Paths` и классической записи
   деинсталляции - админ-установщика нет, поэтому этот HKCU-ключ - полезная доп-зацепка.)

Возврат `""`, если ничего не нашли. Реестр читаем через уже импортируемый
`Microsoft.Win32.Registry` (прецеденты - `src/Main_Form.FileAssociation.vb`).

> Store/MSIX-сборку doc-html-translate **игнорируем**: она GUI-first, не даёт CLI-алиаса,
> и её ассоциации файлов не включают типы изображений - для программного запуска не
> годится (прямо сказано в контракте §4).

### 5.3 Кэш доступности (не блокировать UI)

`FindExe` лезет в файловую систему/реестр - не гонять на каждой навигации. На старте
(после инициализации тулбара) и по желанию периодически вызывать
`RefreshAvailabilityAsync()` на фоне (`Task.Run`), он кладёт `Boolean` в поле; UI-поток
читает дешёвый `IsAvailableCached()`. Если бандлим exe рядом (вариант 5.2.1) - флаг
константа, фон не нужен.

### 5.4 Иконка кнопки

Владелец просит именно **иконку** doc-html-translate на кнопке.

- **Основной путь:** извлечь иконку из найденного exe -
  `System.Drawing.Icon.ExtractAssociatedIcon(exePath).ToBitmap()`, вписать в ~16 px
  (высота кнопки тулбара `row_H` ≈ 24 px, `ApplyModernStyling` ставит
  `ImageAlign = MiddleCenter`). Плюс: всегда актуальная реальная иконка установленной
  программы, ничего не бандлим, нет рассинхрона версий.
- **Запасной путь (если извлечение не удалось):** встроенный PNG-ресурс. Скопировать
  `P:\WINDOWS\EPUB_2_HTML\extension\icons\icon32.png` в
  `assets\icons\doc-html-translate.png`, зарегистрировать `EmbeddedResource` с
  `LogicalName = FmsPayloadicons/doc-html-translate.png` (блок рядом с флагами в
  `src/FastMediaSorter.vbproj`), читать через
  `RuntimeBootstrap.OpenBundledAsset("icons/doc-html-translate.png")` (прецедент -
  `OcrLanguageCatalog.LoadOrDraw`).

Так как кнопка видна только когда exe найден, `ExtractAssociatedIcon` почти всегда
сработает; встроенный PNG - страховка.

## 6. Запуск (headless `doc-html-translate.exe`)

### 6.1 Точка входа

Клик по `btn_TranslateBrowser` → собрать аргументы → `DocHtmlTranslate.TranslateImage(...)`.
Использовать `Current_File_Name` как путь к картинке (тот же источник, что у нашего OCR).

### 6.2 Маппинг языка OCR (`-ocr-lang`)

Переиспользуем настройку исходного языка OCR - `ocr_Settings.SourceLang`
(`src/OcrTranslateSettings.vb`, коды уже в форме Tesseract: `rus`, `eng`, `ukr`..):

- конкретный язык (например `rus`) → `-ocr-lang rus`;
- `auto` → соединить первые ~3 кода из `OcrTranslateSettings.OcrAttemptCodes("auto")`
  через `+` (например `rus+ukr+eng`); либо, если список пуст, `-ocr-lang` не передавать
  (компаньон сам возьмёт `eng`).

Ограничить число языков (≈3), иначе Tesseract заметно медленнее и менее точен.

### 6.3 Выходная папка (`-folder`) - обязательно

По умолчанию компаньон создаёт подпапку **рядом с картинкой** (`C:\pics\cat.png` →
`C:\pics\cat\index.html` + `page_001.html` + копия картинки). Для сортировщика медиа это
недопустимо - мы бы засоряли рабочие папки пользователя чужими подпапками.

Поэтому всегда задаём свою кэш-папку под LocalAppData, по образцу того, куда уже пишет
приложение (`%LOCALAPPDATA%\SZA\FastMediaSorter`):

```
%LOCALAPPDATA%\SZA\FastMediaSorter\browser-translate-cache\<hash>
```

`<hash>` - стабильный хеш полного пути картинки (у нас - SHA1 от `путь|время-записи`,
первые 20 hex-символов), чтобы обновлённый файл переOCRился в свежую папку. Один и тот
же файл при повторном клике попадает в ту же папку → компаньон переиспользует результат
без повторного OCR (контракт §1: без `-force` повторный вызов просто заново открывает
закэшированную страницу).

> Проверено на сборке 2026-07-14: при заданном `-folder <dir>` компаньон всё равно кладёт
> результат в **подпапку по имени картинки** внутри `<dir>` -
> `<dir>\<имя-картинки>\index.html` (+ `page_001.html` + копия картинки), а не прямо в
> `<dir>`. Для нас это несущественно - мы лишь передаём `-folder` в наш кэш; главное, что
> рядом с исходным файлом пользователя подпапка не создаётся.

### 6.4 Запуск процесса

- `ProcessStartInfo` с **абсолютным** путём exe (из `FindExe`); аргументы -
  `-ocr-lang <lang> -folder "<cache>" "<Current_File_Name>"`; корректно кавычить пути с
  пробелами/юникодом (прецедент сборки аргументов - `src/Main_Form.ShareLauncher.vb`).
- `UseShellExecute = False`, `CreateNoWindow = True` - doc-html-translate.exe **консольный**,
  иначе на секунду мигнёт окно консоли. (Открытие браузера компаньон делает сам через
  `cmd /c start`; наш `CreateNoWindow` этому не мешает.)
- **Неблокирующе:** не ждать в UI-потоке. Сразу показать статус «Открываю в браузере..»
  (`SetOcrStatus`/`lbl_Status`).
- **Коды выхода:** `EnableRaisingEvents = True`; в обработчике `Exited` при `ExitCode <> 0`
  через `BeginInvoke` показать понятную ошибку (маппинг кодов из раздела 2). Прецедент
  «показать сообщение, а не молча упасть» - `ShareLauncher`.
- Всё в `Try/Catch`; при исключении запуска - статус/`MessageBox`, не падать.

`Shift`+клик (опционально) → передать `-force` (свежий проход, игнор кэша).

### 6.5 Про `DOCHT_TESSERACT` - намеренно не задаём

Соблазн: у нас уже есть tessdata (`Prepare-OcrOfflinePayload.ps1` тянет
`tessdata_fast`/`best`), передать бы их компаньону. Но мы бандлим **`tesseract50.dll`**
(нативную либу для .NET-обёртки Tesseract), а `DOCHT_TESSERACT` ждёт **`tesseract.exe`**
(консольный бинарник, компаньон парсит его TSV-вывод) - это разные вещи, `tesseract.exe`
у нас нет. Поэтому `DOCHT_TESSERACT` не выставляем; поиск движка - забота компаньона по
его контракту. Если в будущем начнём бандлить `tesseract.exe` рядом с нашим exe - тогда
переключить запуск на передачу `DOCHT_TESSERACT` в окружение дочернего процесса (это уже
требует `UseShellExecute = False`, что у нас и так). Пока - примечание на будущее.

## 7. Если doc-html-translate не установлен (вторичная «витрина», опционально)

По ТЗ владельца поведение по умолчанию простое: **нет установки - нет кнопки-компаньона**
(она завязана на `IsAvailableCached()`, раздел 4.2).

Но у нас есть цель «позиционировать компаньон», а скрытая кнопка ничего не рекламирует.
Поэтому - **необязательный** режим дискаверабилити (по умолчанию выключен; решение
владельца - раздел 13):

- Не плодить видимую кнопку, а добавить пункт в **ПКМ-меню кнопки «Перевод»** (у неё уже
  есть right-click → настройки OCR, `btn_Translate_MouseUp`) или отдельную строчку на
  вкладке «OCR и перевод» настроек: «Перевод в браузере (doc-html-translate)..».
- По клику, если не установлен, предложить установку по контракту §4:
  - winget: `winget install --id SerZhyAle.DocHtmlTranslate -e --source winget --accept-package-agreements --accept-source-agreements`
    (прецедент запуска установщика/URL - `OllamaManager`); после установки переразрешить
    путь (алиас появится в `WinGet\Links`, но **уже запущенный процесс не увидит новый
    `PATH`** - звать по полному пути или обновить кэш из `WinGet\Links`);
  - либо открыть страницу Store: `https://apps.microsoft.com/detail/9PMHSWQPR6V1`
    (только для ручной установки человеком - для запуска Store-сборка не годится, §5.2).

## 10. Крайние случаи и решения

- **Пробелы/юникод в пути** - кавычить и `Current_File_Name`, и `-folder` (UTF-путь).
- **Файл на сетевом диске `\\server`** - просто передаём путь; открытие/чтение - забота
  компаньона; при недоступности вернётся ненулевой код выхода → покажем ошибку.
- **Компаньон без Tesseract** - страница откроется, но без переводимых плашек (контракт
  §2). Не наша ошибка; при желании - разовая подсказка в статусе. Не блокируем.
- **Store-сборка компаньона** - `FindExe` её не найдёт (нет CLI-алиаса) → кнопки нет; это
  корректно.
- **Повторный клик по той же картинке** - переиспользование кэша (`-folder` + без
  `-force`), быстро, без повторного OCR.
- **Мусор рядом с файлами пользователя** - исключён требованием `-folder` в кэш
  (раздел 6.3). Кэш периодически можно чистить (не обязательно в первой версии).
- **doc-html-ui vs doc-html-translate** - для кнопки берём **консольный
  `doc-html-translate.exe`** (headless, выбор владельца), а не GUI `doc-html-ui.exe`.

## 11. Инварианты / что не трогаем

1. Не менять контракт запуска doc-html-translate и его файлы (репозиторий EPUB_2_HTML).
2. Не менять существующий OCR-оверлейный пайплайн (Tesseract/Ollama/Libre, `T`/`Shift+T`).
   Новая кнопка - **отдельный** маршрут «в браузер», рядом, не вместо.
3. Не задавать `DOCHT_TESSERACT` (раздел 6.5), пока не бандлим `tesseract.exe`.
4. Не создавать `v*`-тег: это сборка, не релиз.
5. Соблюдать текст-стайл (дефис/ё/`..`) во всех строках UI, комментариях и этом
   документе.
6. Не блокировать UI-поток обнаружением/запуском (кэш + фон + неблокирующий `Process`).

## 12. Тест-план (ручной)

1. Собрать (`build.ps1`), запустить.
2. **Без установленного компаньона:** на картинке видна только «Перевод»,
   кнопки-компаньона нет.
3. Установить doc-html-translate (`winget install --id SerZhyAle.DocHtmlTranslate ..`),
   перезапустить приложение → на картинке рядом с «Перевод» появилась кнопка с иконкой
   doc-html-translate.
4. Клик по ней → в браузере по умолчанию открылась `index.html` с картинкой; при
   Chrome/Edge доступно «Перевести страницу», плашки перевелись на месте (если у
   компаньона есть Tesseract).
5. Проверить, что рядом с исходной картинкой **не** создалась подпапка (вывод ушёл в
   кэш LocalAppData).
6. Повторный клик по той же картинке - быстро (кэш), `Shift`+клик - переOCR.
7. **Видео** - обе кнопки перевода скрыты.
8. **Анимированный GIF** - обе кнопки скрыты. **Статичный GIF/JPG/PNG/WEBP** - видны.
9. Пути с пробелами и кириллицей в имени файла - работает.
10. Overflow: сузить окно так, чтобы кнопки уехали в «» - обе доступны из выпадающего
    меню с читаемыми подписями.
11. Ненулевой код выхода (например убрать входной файл гонкой) - показывается понятная
    ошибка, приложение не падает.

## 13. Открытые вопросы / решения по умолчанию

1. **Бандлить ли `doc-html-translate.exe` рядом с нашим приложением?** По умолчанию -
   нет (детектим установленный winget/портейбл). Бандл дал бы абсолютный путь и работу
   «из коробки», но раздувает установщик и требует синхронизации версий. Решение
   владельца.
2. **Режим дискаверабилити при отсутствии установки** (раздел 7) - по умолчанию
   **выключен** (буквально по ТЗ «показывать кнопку, если установлен»). Включать ли
   пункт «установить компаньон» в ПКМ/настройках - решение владельца.
3. **`-folder`: единая кэш-папка с очисткой или per-image без очистки** - по умолчанию
   per-image по хешу, без активной очистки в первой версии.
4. **Бандлить ли `tesseract.exe` для компаньона** (чтобы плашки работали «из коробки») -
   по умолчанию нет; тогда `DOCHT_TESSERACT` не задаём (раздел 6.5).

## 14. Итог реализации (сборка 2026-07-14)

Решения владельца по разделу 13: (1) **не бандлить** exe - детектим установленный
winget/портейбл; (2) режим дискаверабилити - **пункт в ПКМ-меню** кнопки «Перевод»;
(3) иконка кнопки - **только встроенный PNG-ресурс** (без `ExtractAssociatedIcon`).

Что сделано:

- Новый модуль `src/DocHtmlTranslateLauncher.vb` (`DocHtmlTranslate`): `FindExe` (бандл →
  `WinGet\Links` → PATH → HKCU-команда), `IsAvailableCached`/`RefreshAvailabilityAsync`
  (фон + кэш), `TranslateImage` (неблокирующий запуск с `-ocr-lang`/`-folder`, разбор кода
  выхода через `Exited`), `StartWingetInstall`/`OpenStorePage` для дискаверабилити.
- Новый partial `src/Main_Form.BrowserTranslate.vb`: кнопка `btn_TranslateBrowser` с
  иконкой из встроенного PNG, `IsCurrentStillImage()`, `ApplyTranslateButtonsVisibility()`,
  ЛКМ/`Shift`, `HandleTranslateRightClick` (меню установки, когда компаньон не найден).
- Иконка `assets\icons\doc-html-translate.png` (копия `icon32.png`) + `EmbeddedResource`
  `FmsPayloadicons/doc-html-translate.png` в `src/FastMediaSorter.vbproj`.
- Тулбар: `BuildBrowserTranslateToolbarControls` в `Main_Form.ModernLayout.vb`;
  `btn_TranslateBrowser` в `toolbar_Row2_Items` + подпись в `OverflowText`
  (`Main_Form.ToolbarOverflow.vb`); хуки `InitializeBrowserTranslate`
  (`Main_Form.Lifecycle.vb`) и `LocalizeBrowserTranslate` (`Main_Form.Localization.vb`).
- Видимость обеих кнопок - в `OnMediaDisplayed` (`Main_Form.OcrTranslate.vb`) через
  `ApplyTranslateButtonsVisibility`. **Нюанс раскладки:** `LayoutToolbar`/`PlaceControl`
  принудительно ставят `Visible=True` каждому элементу строки, поэтому скрытие идёт не
  через `.Visible=False`, а через новый `SetToolbarItemHidden` + набор `toolbar_Hidden_Items`
  (скрытый элемент исключается и из строки, и из overflow-меню).

Тестирование (ручное, сборка Release):

- Сборка LITE - без ошибок (только предсуществующие MSB3277 о версиях сборок).
- Контракт запуска end-to-end: путь с пробелом и кириллицей, `-ocr-lang eng -folder <кэш>`
  → **код выхода 0**, браузер открылся, вывод - только в кэше LocalAppData, **рядом с
  картинкой подпапка не создана**.
- Статичный PNG: видны обе кнопки (компаньон - с иконкой). Видео: **обе кнопки скрыты**.
  (Анимированный GIF использует тот же сигнал `gif_Restart_Image_Ref`.)
