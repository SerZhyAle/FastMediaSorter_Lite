# Specification - resume the last played file at startup (.NET 10)

> Status: **реализовано** (2026-08-18; спецификация - 2026-08-17, revision 1). Одна новая настройка, **по умолчанию выключена**,
> плюс один новый ключ профиля. Позиция видео уже хранится - эта задача её только *применяет при
> старте*.
>
> Scope: **только mainline** (`FastMediaSorter_LITE.exe`, .NET 10 x64). Фолбэк `FastMediaSorter_x86.exe`
> не меняется вообще - см. §2.2. **Без новых зависимостей, без изменений установщика, без изменений
> Companion.**
>
> Related: [SPECIFICATION_SETTINGS_EXPANSION.md](SPECIFICATION_SETTINGS_EXPANSION.md) (§7.1 -
> `StartupOpenMode`; §"видео" - `RememberVideoPosition` и `VideoPositionHistory`, на которых эта
> задача стоит), [SPECIFICATION_ALLOW_NEW_WINDOWS_DOTNET10.md](SPECIFICATION_ALLOW_NEW_WINDOWS_DOTNET10.md)
> (вторичное окно и запрет писать профиль), [SPECIFICATION_ARCHIVE_BROWSING_DOTNET10.md](../SPECIFICATION_ARCHIVE_BROWSING_DOTNET10.md)
> (инвариант «никакой временный путь не переживает сессию»),
> [SPECIFICATION_SLOT_HEALTH_AND_HONEST_FAILURES_DOTNET10.md](../SPECIFICATION_SLOT_HEALTH_AND_HONEST_FAILURES_DOTNET10.md)
> (проба пути вне UI-потока - тот же приём, что здесь).

## 0. Зачем это нужно

### 0.1 Сегодня «последний файл» - это индекс, а не файл

Настройка «Что открывать при запуске» ([ModernViewerPreferences.vb:60](../../../src/ModernViewerPreferences.vb#L60),
значения `home` / `lastFolder` / `lastFile`) в режиме `lastFile` восстанавливает **порядковый номер**
внутри папки: [Main_Form.Lifecycle.vb:730-737](../../../src/Main_Form.Lifecycle.vb#L730-L737) читает
`LastCounter` и открывает папку по `ImageFolder`. Это не тот же файл, а тот же **номер**: стоило
удалить, переместить или отсортировать что-то раньше по списку - и открывается сосед. Файла как
такового приложение при старте не помнит нигде.

### 0.2 Позиция видео уже хранится - и уже теряется при перезапуске

`RememberVideoPosition` + `VideoPositionHistory` ([ModernViewerPreferences.vb:52,69,201-220](../../../src/ModernViewerPreferences.vb#L201-L220))
хранят до 200 записей `путь + время записи + размер + позиция`, пишутся в
`RememberCurrentVideoPosition` ([Main_Form.ModernPreferences.vb:296-306](../../../src/Main_Form.ModernPreferences.vb#L296-L306))
и применяются в `QueueRememberedVideoPosition` / `ApplyPendingVideoPosition`
([Main_Form.VideoPlayer.vb:318-323](../../../src/Main_Form.VideoPlayer.vb#L318-L323),
[Main_Form.VideoMenu.vb:156-172](../../../src/Main_Form.VideoMenu.vb#L156-L172)). То есть **внутри одной
сессии** досмотр с того же места работает. После перезапуска этот запас не используется никем: файл
просто не открывается.

Полутора часовой фильм, закрытое окно, повторный запуск - и пользователь вручную ищет папку, файл и
место. Всё, чего не хватает, - решения «открыть при старте именно тот файл».

### 0.3 Почему провал должен быть молчаливым

Восстановление при старте - не действие пользователя, а догадка приложения. Файл мог быть удалён,
переименован, лежать на отключённом NAS или на вынутой флешке. Модальное окно или красная строка
статуса на пустом окне за действие, которого пользователь не совершал, - шум. **Решение владельца:
недоступен - тихо пустой экран** (ровно то же состояние, что при `StartupOpenMode = home`), запись
только в `Debug`/`current.log`.

---

## 1. Решение в одном абзаце

Добавляется **отдельный чекбокс** «Продолжать с последнего файла» (ключ `ResumeLastPlayback`,
**по умолчанию выключен**). Когда он включён, приложение при каждом показе медиафайла запоминает его
**полный путь** (ключ `LastPlayedFile`), а на старте - если нет аргумента командной строки - проверяет
этот путь вне UI-потока и открывает его: папку файла, полный список файлов этой папки, курсор на самом
файле. Для видео/аудио дополнительно применяется уже существующий механизм `VideoPositionHistory`, то
есть воспроизведение продолжается с сохранённой позиции. Если путь недоступен по любой причине - окно
остаётся пустым, без сообщений.

## 2. Границы

### 2.1 Что эта задача НЕ делает

- **Не трогает `StartupOpenMode`.** Список остаётся из трёх значений, `lastFile` продолжает означать
  ровно то, что означал (папка + индекс). Смешивать их нельзя: `StartupOpenMode` - это «что открыть»,
  новая опция - «и довести до того же кадра».
- **Не заводит второе хранилище позиций.** Позиция берётся из `VideoPositionHistory` как есть.
- **Не добавляет периодического сохранения позиции.** Позиция по-прежнему пишется при смене файла и
  при закрытии (`StopVlcPlayback` → `RememberCurrentVideoPosition`,
  [Main_Form.Lifecycle.vb:920](../../../src/Main_Form.Lifecycle.vb#L920)). Аварийное завершение теряет
  позицию текущего видео - как и сегодня. Кандидат в Ф2, §9.
- **Не восстанавливает зум, поворот, полноэкранный режим, слайдшоу, OCR-оверлей** - только файл и
  позицию видео.

### 2.2 net48 x86

Опции там нет. Вся логика - `#If Not NETFRAMEWORK`, в `#If NETFRAMEWORK`-блоке
[Main_Form.ModernPreferences.vb:335-353](../../../src/Main_Form.ModernPreferences.vb#L335-L353) добавляется
заглушка `ResumeLastPlaybackEnabled() = False`, чтобы общий код собирался. Поведение фолбэка после этой
задачи побайтово прежнее (он и так стартует в режиме `lastFile`).

## 3. Поведение

### 3.1 Порядок решений при старте

В [Main_Form.Lifecycle.vb:712-741](../../../src/Main_Form.Lifecycle.vb#L712-L741) сегодня две ветки. Станет
три, в этом порядке:

| # | Условие | Что происходит |
| --- | --- | --- |
| 1 | есть аргумент командной строки | `ProcessArgument(..)` - как сейчас. Явный файл всегда сильнее любой памяти |
| 2 | `ResumeLastPlayback` включён **и** `LastPlayedFile` не пуст | попытка восстановления, §3.2 |
| 3 | иначе | текущая ветка `StartupOpenMode` (`home` / `lastFolder` / `lastFile`) - без изменений |

Важно: ветка 2 **срабатывает независимо от `StartupOpenMode`**, включая `home`. Чекбокс включают
осознанно, и он про «продолжить», а не про «открыть папку».

### 3.2 Попытка восстановления

1. Путь проверяется **вне UI-потока** тем же `ProbeArgument`, что и аргумент командной строки
   ([Main_Form.Lifecycle.vb:431-451](../../../src/Main_Form.Lifecycle.vb#L431-L451)). Окно за это время
   уже показано и живо - мёртвая SMB-шара не даёт замороженного окна на минуты.
2. Успех (`probe.Exists`, не каталог) - открывается **папка файла** обычным путём
   (`Current_Folder_Path` = каталог, полный список файлов, `current_File_Index` = индекс этого файла,
   `ReadShowMediaFile(Mode_FolderAndFile)`), чтобы стрелки/слайдшоу/счётчик `N/total` работали сразу.
   Список одного файла (как в ветке `Mode_FolderAndKnownFile` для аргумента) здесь **не годится**:
   пользователь продолжает просмотр, а не открывает вложение.
   - Если файла нет в отфильтрованном списке папки (сменился фильтр расширений `IncludedExtensions`,
     файл больше не подходит) - индекс `0`, файл не навязывается. Это не ошибка и не сообщение.
3. Любой неуспех - `probe.Missing`, `probe.Denied`, сетевая недоступность, исключение, каталог вместо
   файла - **тихо**: `lbl_Status` не трогается, диалогов нет, окно остаётся пустым, в лог уходит одна
   строка `Debug.WriteLine(.. "resume: last file unavailable: " & path)`. Ветка 3 (`StartupOpenMode`)
   при этом **не выполняется**: включённая опция уже сделала свой выбор, и подмена «того самого файла»
   случайной папкой - это ровно та неожиданность, которой §0.3 избегает.
4. `LastPlayedFile` **не стирается** при неудаче. Отключённый NAS завтра включат; забыть путь из-за
   одной неудачной пробы - потерять данные пользователя. Ключ перезаписывается только следующим
   показанным файлом.
5. Ожидания разблокировки (`pending_Unlock_Timer`, «файл качается») здесь **нет** - это поведение
   осознанного открытия файла, а не фонового восстановления.

### 3.3 Видео и аудио

Отдельного кода восстановления позиции не пишется. Открытие файла из §3.2 идёт через обычный
`PlayVideoWithVlcAsync`, который уже вызывает `QueueRememberedVideoPosition(file_Path)`
([Main_Form.VideoPlayer.vb:322](../../../src/Main_Form.VideoPlayer.vb#L322)), а `Vlc_Media_Player_Playing` -
`ApplyPendingVideoPosition()`. Отсюда:

- `RememberVideoPosition` **выключен** → файл открывается с начала. Это честно: пользователь запретил
  помнить позиции, и опция старта не имеет права это обходить.
- Запись позиции устарела (изменились `LastWriteUtcTicks` или `Length`
  - [ModernViewerPreferences.vb:205](../../../src/ModernViewerPreferences.vb#L205)) → с начала.
- Позиция `<= 0` или `>= 1` (досмотрено до конца) → с начала.
- Играть или стоять на кадре решает существующий `VideoAutoplay`: включён - продолжает
  воспроизведение с позиции, выключен - показывает этот кадр на паузе (`pause_New_Video_When_Ready`).
  Новой настройки «стартовать на паузе» не вводится.
- Картинка/GIF просто открывается - позиции у неё нет.

### 3.4 Что именно запоминается

`LastPlayedFile` обновляется на **каждом успешно показанном** медиафайле (не только видео - название
опции говорит «последний файл»), там же, где ведётся список недавних файлов
(`recent_Media_File_List`), с `MarkSettingsDirty()`, то есть без записи в реестр на каждый флип
([Main_Form.Lifecycle.vb:977-1007](../../../src/Main_Form.Lifecycle.vb#L977-L1007)).

**Не запоминаются** (ключ остаётся прежним, а не затирается):

| Что | Почему |
| --- | --- |
| запись внутри архива (`archive-cache\<pid>-<token>\..`) | инвариант архивов: никакой временный путь не переживает сессию; на следующем старте этого файла физически нет. Фильтр - тот же `PersistableFolderPath()`, что уже применён к `ImageFolder` ([Main_Form.Lifecycle.vb:1036-1040](../../../src/Main_Form.Lifecycle.vb#L1036-L1040)) |
| удалённые MRL/URL (`IsRemoteMediaUrl`) | пробу пути к ним не применить, и «продолжить поток с позиции» смысла не имеет |
| файл, только что перемещённый/удалённый самим приложением | по этому пути его уже нет; актуальным станет следующий показанный файл |

### 3.5 Второе окно

При `AllowNewWindows` вторичный процесс профиль не пишет вообще
([ModernViewerPreferences.vb:130-133](../../../src/ModernViewerPreferences.vb#L130-L133),
`PersistSettings` на [Main_Form.Lifecycle.vb:1030](../../../src/Main_Form.Lifecycle.vb#L1030)) - значит
`LastPlayedFile` пишет только первичный процесс, и это правильно: «последний» должен быть один.
**Восстановление же выполняется только в первичном процессе**: иначе три открытых окна после
перезапуска показали бы три копии одного и того же файла. Вторичное окно ведёт себя как сегодня
(ветка 3).

## 4. Хранение

Один новый ключ настройки и один новый ключ состояния, оба в существующем кусте `SZA\FastMediaSorter`:

| Ключ | Тип | Умолчание | Где |
| --- | --- | --- | --- |
| `ResumeLastPlayback` | `"0"` / `"1"` | `"0"` - **выключено** | `ModernViewerPreferences` (`ReadBool`/`WriteBool`, рядом с `StartupOpenMode`) |
| `LastPlayedFile` | строка, полный путь | `""` | пишется/читается в `PersistSettings` / `Form1_Load` рядом с `ImageFolder` и `LastCounter` |

`LastPlayedFile` намеренно **не** в `ModernViewerPreferences`, а рядом с `ImageFolder`/`LastCounter`:
это состояние сессии того же сорта, оно пишется тем же дебаунсом и очищается теми же средствами.

Экспорт настроек ([`ExportJson`](../../../src/ModernViewerPreferences.vb#L174-L185)) переносит только
`ResumeLastPlayback` (это настройка). `LastPlayedFile` - персональные данные того же класса, что
`VideoPositionHistory`, и в экспорт не входит вообще, поскольку живёт вне этого класса.

Кнопка очистки истории («Очистить историю», `AddHistoryRow`) должна очищать и `LastPlayedFile` -
иначе «история очищена», а последний просмотренный файл при следующем старте открывается снова.

## 7. Краевые случаи

| Случай | Поведение |
| --- | --- |
| Опция включена, `LastPlayedFile` пуст (первый запуск после включения) | ветка 3, обычный `StartupOpenMode` |
| Файл есть, но папка огромная и на сети | окно уже показано, проба и листинг идут своим чередом; заморозки нет |
| Файл существует, но не проходит фильтр расширений | папка открывается, курсор на `0` (§3.2.2) |
| Файл лежит в архиве | путь не сохранялся вовсе (§3.4) - ветка 3 |
| Файл был последним в папке и удалён между сессиями | тихо пустой экран (§3.3 п.3) |
| Позиция видео сохранена, но файл перекодирован (изменился размер/дата) | открывается с начала - существующая проверка `LastWriteUtcTicks`/`Length` |
| Опция включена, приложение запущено двойным кликом по файлу | побеждает аргумент (ветка 1) |
| Опция выключается после использования | `LastPlayedFile` продолжает писаться (безвредно) или перестаёт - решает реализация; на поведение это не влияет. Рекомендация: писать всегда, чтобы включение опции работало сразу |
| Вторичное окно | восстановления нет (§3.5) |

## 8. Приёмка

### 8.1 Автотесты (`dotnet test tests/Lite.Tests`, обе ноги зелёные)

1. `ResumeLastPlayback` по умолчанию `False`; `Load` без ключа даёт `False`; `"1"` даёт `True`;
   round-trip `Save`→`Load` сохраняет значение.
2. `ExportJson`/`FromJson` переносят `ResumeLastPlayback`.
3. `LocalizationParityTests` и `LocalizationCoverageTests` зелёные с двумя новыми строками.

### 8.2 Ручные сценарии (mainline)

1. Опция выключена (умолчание) - старт ведёт себя ровно как до задачи, при всех трёх значениях
   `StartupOpenMode`. **Это главный тест: по умолчанию не меняется ничего.**
2. Опция включена, видео досмотрено до середины, закрыть, запустить - открывается тот же файл, с той
   же позиции, папка листается стрелками, счётчик `N/total` верный.
3. То же с `VideoAutoplay = off` - тот же кадр, на паузе.
4. То же с `RememberVideoPosition = off` - тот же файл, с начала.
5. Последним был JPEG - открывается он же.
6. Файл удалён между запусками - **пустое окно, ни одного сообщения**, `StartupOpenMode` не
   отрабатывает.
7. Файл на отключённой сетевой шаре - окно появляется сразу и остаётся пустым; заморозки на минуты
   нет.
8. Запуск двойным кликом по другому файлу - открывается файл из аргумента.
9. Последним был кадр внутри `.cbz` - восстановления нет, отрабатывает `StartupOpenMode`.
10. «Очистить историю» → перезапуск - пустое окно.
11. Сборка `FastMediaSorter_x86.exe` - 0 ошибок, поведение старта прежнее.

### 8.3 Сборка

`.\build.ps1` - обе сборки без ошибок (общий код обязан собираться на обоих рантаймах).

## 9. Возможное продолжение (вне объёма)

- **Ф2: периодическое сохранение позиции** (например, раз в 30 с во время воспроизведения), чтобы
  аварийное завершение не теряло место в фильме. Сейчас позиция пишется только при смене файла и при
  закрытии.
- **Ф3: восстановление сессии целиком** - полноэкранный режим, зум, вкладка/фильтр. Отдельная задача,
  другой класс состояния.

## 10. Как это реализовано (2026-08-18)

Всё по §5; три места, где реализация отличается от буквы спецификации, и почему.

1. **Открытие восстановленного файла - `LoadFiles()` + `ReadShowMediaFile(Mode_SetFile)`**, а не
   `Mode_FolderAndFile` (§3.2.2). `Mode_FolderAndFile` безусловно ставит `current_File_Index = 0`, то
   есть курсор на файле потерялся бы; а `Mode_FolderAndKnownFile` через
   `LoadFilesForExternalInput` **вставляет** отсутствующий файл в начало списка - ровно то
   «навязывание», которое §3.2.2 запрещает. `Mode_SetFile` работает по уже прочитанному списку, так
   что папка читается один раз, индекс ищется по полному пути (без учёта регистра), а не найден -
   остаётся `0`. Комбобокс папок и список недавних папок при этом обновляет сам `ReadShowMediaFile`.
   Код: `TryResumeLastPlayedFile` / `ResumeLastPlayedFileAsync` / `OpenResumedFile` в
   [Main_Form.Lifecycle.vb](../../../src/Main_Form.Lifecycle.vb).
2. **Очистка `LastPlayedFile` при очистке истории** сидит в `Main_Form.ReplaceRecentHistory`
   ([Main_Form.ModernPreferences.vb](../../../src/Main_Form.ModernPreferences.vb)) - в методе, который
   `AddHistoryRow` и вызывает, - а не в самой строке настроек. Так ключ чистится и от кнопки
   «Очистить», и от удаления одной записи, и только если файл действительно исчез из списка (при
   лимите истории `0` он в него и не попадал, и это не должно читаться как удаление).
3. **Тест «round-trip `Save`→`Load`» (§8.1 п.1) намеренно не написан.** `ModernViewerPreferences.Save()`
   пишет весь блок настроек в тот же живой куст `SZA\FastMediaSorter`, который читает установленная
   программа, так что объект со значениями по умолчанию затёр бы настройки того, кто запускает
   `dotnet test` на своей машине. Обе стороны ключа доказаны безопасно: запись одного значения профиля
   вручную с восстановлением прежнего (`Load` видит `"1"`/`"0"`/отсутствие ключа) плюс round-trip
   `ExportJson`→`FromJson` - [tests/Lite.Tests/ResumeLastPlaybackTests.vb](../../../tests/Lite.Tests/ResumeLastPlaybackTests.vb).
   Ради этого `src/ModernViewerPreferences.vb` добавлен в список `<Compile Include>` тестового проекта.
