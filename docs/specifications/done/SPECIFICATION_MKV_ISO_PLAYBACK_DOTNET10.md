## 0. ИТОГ (ревизия 2): что решено и что сделано

Разведка перед решением дала три факта, которые изменили картину:

1. **Монтирование ISO без админа работает** (O-ISO-1 закрыт эмпирически: Win32
   `OpenVirtualDisk` + `AttachVirtualDisk` с `ATTACH_VIRTUAL_DISK_FLAG_READ_ONLY` из
   неэлевированного шелла - успех, `\\.\CDROM0`, `DetachVirtualDisk` rc=0). Главный
   риск §10 снят.
2. **Но Windows 8+ монтирует data-ISO двойным кликом сама**, а примонтированный образ
   - обычная папка, которую приложение уже открывает. То есть значительная часть
   «поддержки data-ISO» у пользователя есть и без нас.
3. **Внутри read-only образа сортировка невозможна** (move/delete упрутся), работает
   только режим «копировать». Для сортировщика ценность узкая.

**Решение владельца (2026-07-16): ISO не делаем вовсе.** Отпадают O-ISO-1, O-ISO-2,
O-ISO-3, O-ISO-6 и фазы Ф-B, Ф-C, Ф-D, Ф-E. Ни DiscUtils, ни вендоринга
`libdvdnav`/`libdvdread`, ни монтирования, ни ассоциации `.iso`. Разделы 5, 6 и
таблица §1 остаются ниже как **зафиксированный результат ресёрча** (в т.ч. граница
по DRM), а не как план работ.

**Что из этой спеки РЕАЛИЗОВАНО (2026-07-16):**
- **Локальный MKV** - работы не потребовалось: `.mkv` уже в `video_File_Extensions`,
  а modern-диспетчер шлёт видео прямо в `PlayVideoWithVlcAsync` (WebBrowser снят
  раньше). Ф-A по локальному MKV был выполнен ещё в базовом эпике.
- **Ф-A (удалённые MRL) + O-ISO-5 = ДА**: гейт `File.Exists` снят для удалённых схем
  (`CanVlcReachMedia`), MRL передаётся строкой через `FromType.FromLocation`
  (`CreateVlcMedia`), добавлено поле **«Открыть URL..»** (правый клик по кнопке
  «Выбрать файл»). См. `src/Main_Form.OpenUrl.vb` + `src/MediaUrl.vb` (33 теста).
  **UNC намеренно НЕ считается удалённым** - Windows его резолвит, он всегда играл,
  и переклассификация только потеряла бы проверку на отсутствующий файл.
- **O-ISO-7 = ДА (в рамках этого этапа)**: выбор аудио/субтитр-дорожек - кнопка
  «Дорожки» (появляется только когда есть из чего выбирать) + клавиши **A** (звук) и
  **V** (субтитры), с запоминанием выбора **по коду языка**. См.
  `src/Main_Form.VideoTracks.vb`.
- **O-ISO-4** был закрыт ранее: никакого обхода DRM (§6 остаётся инвариантом).

**Проверено на живом движке** (headless-стенд + MKV с двумя звуковыми дорожками и
субтитрами, собранный ffmpeg): `AudioTrackDescription` содержит служебную запись
`Disable` (id=-1) - поэтому «есть выбор» считается по **настоящим** дорожкам;
`SetAudioTrack(id)` применяется; и главное - **`player.Media.Tracks` сохраняет чистое
поле `Language` (`rus`/`eng`) даже после `Media.Dispose()`**, что и позволило
запоминать выбор по языку, а не по нестабильному имени вида `Russian - [Russian]`.

**Не проверено:** O-ISO-2 (прямой MRL для DVD/BD-ISO) - нужен настоящий DVD/BD-образ,
которого нет. Неактуально, раз ISO вне рамок.

## 1. Резюме (что можно и в какой зоне)

| Формат / источник | Как играется | Зона | Статус в коде |
|---|---|---|---|
| **MKV, локальный** | LibVLC (единый движок в modern) | STANDARD | Уже работает (через fallback) |
| **MKV, удалённый (UNC `\\server`)** | LibVLC, `file://server/..` | STANDARD | Работает, если `File.Exists` проходит |
| **MKV, удалённый (`smb://`/`http://`/`ftp://`/`sftp://`/`nfs://`)** | LibVLC access-плагины | STANDARD | **Заблокировано** гейтом `File.Exists` - надо снять |
| **DVD-Video ISO, незашифрованный** (домашняя запись, без CSS) | `dvd:///..iso` **напрямую** (VLC читает образ сам, без монтирования) | STANDARD* | Нет + **нужны dvd-плагины** (см. §3) |
| **Blu-ray ISO, незашифрованный** (BDMV без AACS) | `bluray:///..iso` **напрямую** (плагин libbluray уже есть) | STANDARD | Нет, база плагинов готова |
| **Data-ISO** (образ с обычными медиафайлами, без VIDEO_TS/BDMV) | VLC внутрь не заглянет → смонтировать средствами ОС или распарсить DiscUtils | STANDARD | Нет, надо добавить |
| **DVD-Video ISO, коммерческий (CSS)** | требует обхода DRM | **вне рамок** | Не поддерживаем (Store-safe, §6) |
| **Blu-ray ISO, коммерческий (AACS/BD+)** | требует обхода DRM | **вне рамок** | Не поддерживаем (Store-safe, §6) |

`*` DVD-Video без CSS «легален по DRM» (обхода защиты нет), но требует
доукомплектации свободными плагинами `libdvdnav`/`libdvdread`, которых в нашем
NuGet-пакете нет (§3).

**Одной фразой:** MKV (локальный/удалённый) и data-ISO закрываются полностью и
чисто; незашифрованные DVD/BD-ISO - тоже STANDARD, но нужно довезти свободные
dvd-плагины; дешифровка коммерческих защищённых дисков (CSS/AACS/BD+) - **полностью
вне рамок проекта**: мы её не реализуем, не бандлим и не хукаем никак (проект
публикуется в Microsoft Store и не делает ничего, связанного с обходом DRM). §6
объясняет, где именно проходит эта граница и почему.

## 2. Текущее состояние в коде

- **MKV уже распознаётся как видео.** `.mkv` входит в `video_File_Extensions`
  ([Main_Form.vb:72](../../src/Main_Form.vb#L72)). В legacy net48-сборке любой
  видеофайл сперва грузится в IE WebBrowser
  ([Main_Form.MediaLoading.vb:876](../../src/Main_Form.MediaLoading.vb#L876) →
  `LoadVideoInWebBrowser`), IE не умеет Matroska, срабатывает `onerror` →
  `HandleVideoError` → `PlayVideoWithVlcAsync`
  ([Main_Form.VideoPlayer.vb:73-83](../../src/Main_Form.VideoPlayer.vb#L73-L83)).
  То есть MKV уже играет, но платит лишний round-trip через дохлый WebBrowser.
- **В modern-сборке (.NET 10) WebBrowser удаляется** (раздел 6.2 базовой
  спецификации): единый движок LibVLC, `LoadVideoInWebBrowser` схлопывается в
  `PlayVideoWithVlcAsync`. Для MKV это значит - прямое воспроизведение без
  round-trip. **Именно modern-сборка - целевая для этой фичи.**
- **ISO не поддержан нигде.** `.iso` нет ни в `video_File_Extensions`, ни в
  `Image_File_Extensions`, ни в скане папок, ни в ассоциациях.
- **Гейт воспроизведения.** `PlayVideoWithVlcAsync`
  ([Main_Form.VideoPlayer.vb:168-169](../../src/Main_Form.VideoPlayer.vb#L168-L169))
  начинается с `If String.IsNullOrEmpty(file_Path) OrElse Not File.Exists(file_Path)
  Then Return` и строит `New LibVLCSharp.Shared.Media(libVlc, New Uri(file_Path))`.
  Для локального пути и UNC-шары `New Uri` даёт `file://..` - LibVLC это играет.
  Для настоящих удалённых схем (`smb://`, `http://`, `sftp://`) `File.Exists`
  вернёт `False` и файл молча не откроется, хотя access-плагины LibVLC такие схемы
  умеют (§4.2).

## 3. Ключевой факт: что реально есть в нашем LibVLC (проверено по бинарям)

Проверено по завендоренному пакету `VideoLAN.LibVLC.Windows.3.0.21`
(`packages/VideoLAN.LibVLC.Windows.3.0.21/build/{x86,x64}/plugins/`) и по
задеплоенным `bin/Release/libvlc/win-{x86,x64}/plugins/`:

**Есть (access-плагины):** `liblibbluray_plugin.dll` (Blu-ray), `libvcd_plugin.dll`
(Video CD), `libcdda_plugin.dll` (Audio CD), `libsmb_plugin.dll`,
`libsftp_plugin.dll`, `libnfs_plugin.dll`, `libftp_plugin.dll`,
`libhttp_plugin.dll`/`libhttps_plugin.dll`, `libfilesystem_plugin.dll`, RTP/RTSP
(`liblive555_plugin.dll`), MMS, SRT, UDP/TCP. Демукс Matroska
`libmkv_plugin.dll` - **есть**. Кодеки - `libavcodec_plugin.dll` (H.264/H.265/VP8/
VP9/MPEG/AC3/DTS/…), `libdav1d_plugin.dll` + `libaom_plugin.dll` (AV1).

**НЕТ (важно!):** `libdvdnav_plugin.dll` и `libdvdread_plugin.dll` - **DVD-Video
access-модули в пакете отсутствуют** (в обеих архитектурах). Проверено: glob
`**/plugins/**/*dvd*` по всему дереву не находит ничего. Пакет
`VideoLAN.LibVLC.Windows` их не кладёт, хотя libbluray - кладёт.

**Никогда не входит ни в один пакет:** `libdvdcss.dll` (обход CSS),
`libaacs.dll` + `libbdplus.dll` + `keydb.cfg` (обход AACS/BD+). Это зона noLegal
(§6).

**Практические следствия из этого факта:**
1. **Blu-ray (незашифрованный)** - плагин есть, работает «из коробки» после
   монтирования / прямым MRL `bluray://`.
2. **DVD-Video (любой)** - **не заиграет** на нашем текущем наборе плагинов: нет
   dvdnav/dvdread. Чтобы поддержать даже незашифрованный DVD-ISO, нужно
   **завендорить два свободных плагина** `libdvdnav_plugin.dll` +
   `libdvdread_plugin.dll` из официальной полной сборки VLC той же версии в
   `plugins/access/`. Оба - LGPL/GPL, свободно распространяемы, это НЕ обход защиты
   (в отличие от libdvdcss). Это чистая STANDARD-доукомплектация.
3. **Data-ISO** - у VLC нет универсального «залезь внутрь ISO и покажи файлы»
   access-модуля. Data-ISO надо **монтировать** средствами ОС и читать как папку
   (§5.2), либо парсить управляемым кодом (§5.3, вариант DiscUtils).

## 4. MKV

### 4.1 Локальные MKV - фактически готово

В modern-сборке (LibVLC-only) `.mkv` уже в списке видеорасширений и играет напрямую
`PlayVideoWithVlcAsync`. Демукс `libmkv_plugin.dll` + `libavcodec` покрывают
типичное содержимое MKV: видео H.264/H.265/VP9/MPEG(-2/4), AV1 (dav1d/aom), аудио
AAC/AC3/E-AC3/DTS/FLAC/Opus/Vorbis, субтитры SRT/ASS/SSA/VobSub/PGS, главы и
несколько дорожек. Отдельной работы по локальному MKV не требуется - он «падает» в
общий видеопуть после снятия WebBrowser.

**Что доделать (мелочь):** убедиться, что в modern маршрут MKV идёт сразу в VLC
(без artefacts от удалённого WebBrowser-пути), и что выбор аудио/субтитр-дорожки
доступен через существующий контроллер (сейчас UI дорожек нет - это отдельный
опциональный пункт, см. открытые вопросы).

### 4.2 Удалённые MKV - снять гейт `File.Exists`

Access-плагины `smb`, `sftp`, `ftp`, `http(s)`, `nfs`, RTP/RTSP уже в комплекте.
Единственное, что мешает удалённому воспроизведению - `PlayVideoWithVlcAsync`
блокирует всё, что не проходит `File.Exists`.

Предлагаемая правка (в modern-варианте `PlayVideoWithVlcAsync`):
- Разделить путь на **локальный/UNC** (есть буква диска или `\\server`) и
  **удалённый URI** (`smb://`, `http://`, `https://`, `ftp://`, `sftp://`,
  `nfs://`, `rtsp://`).
- Для локального/UNC - как сейчас: `File.Exists` + `New Uri(path)` (`file://`).
- Для удалённого URI - **не** делать `File.Exists`; передавать MRL строкой:
  `New LibVLCSharp.Shared.Media(libVlc, mrl, FromType.FromLocation)`. Аутентификацию
  (`smb://user:pass@host/..`) VLC берёт из самого MRL; учётные данные вводить не
  просим (за рамками этой итерации - см. открытые вопросы).
- Учесть, что для удалённого источника VLC-буферизация ощутимо больше;
  статус-строку («Буферизация..») и обработку таймаута оставить как есть, VLC сам
  отдаёт события `EncounteredError`/`Playing`.

Замечание про «удалённые» в контексте приложения: основной кейс приложения - файлы
на **сетевых шарах** (`\\server\share\video.mkv`). Они уже работают (UNC → `file://`,
Windows-редиректор тянет по SMB прозрачно). Явные `smb://`/`http://` URL - расширение
на будущее; техническая база (плагины) готова, нужен только снятый гейт и, при
желании, поле «Открыть URL..».

### 4.3 Покрытие кодеков/дорожек

Всё типичное содержимое MKV покрыто `libavcodec` + `libmkv`. Что вне охвата (и это
нормально): экзотические lossless-видеокодеки, требующие внешних декодеров; но такие
в MKV встречаются редко. Аппаратное декодирование (`libd3d11va_plugin.dll`) в
комплекте есть - HEVC/H.264 разгружаются на GPU.

## 5. ISO - ядро задачи

### 5.1 Три типа ISO - у каждого свой путь

ISO - это не формат видео, а образ файловой системы (ISO 9660 / UDF). «Играбельность»
зависит от того, что внутри:

1. **Data-ISO** - образ с обычными медиафайлами (`\Movie\film.mkv`, набор `.mp4` и
   т.п.), без DVD/BD-структуры. Это самый частый бытовой случай «скинул папку с
   видео в образ».
2. **DVD-Video ISO** - образ DVD-диска со структурой `VIDEO_TS\` (VOB/IFO/BUP).
   Может быть незашифрованным (домашняя запись) или зашифрованным CSS (коммерческий
   диск).
3. **Blu-ray ISO** - образ BD-диска со структурой `BDMV\` (M2TS/CLPI/MPLS). Может
   быть незашифрованным или защищённым AACS (+ опц. BD+).

### 5.2 Как это делает сам VLC: читает образ напрямую, без монтирования

Ключевой факт (проверено по ресёрчу): **VLC НЕ монтирует ISO.** У него собственные
ридеры файловой системы диска (ISO 9660 / UDF) внутри `libdvdread` (DVD) и
`libbluray` (Blu-ray) - он открывает `.iso` как файл и читает секторы напрямую,
без виртуального привода и без прав администратора. Цитата из первоисточников:
*«VLC parses ISO containers natively without requiring third-party mounting
software.. play DVD ISO files directly.. without needing to mount them as virtual
drives»*.

Поэтому **основной путь для DVD/BD-ISO - прямой MRL по пути к образу, без всякого
монтирования:**

- **DVD-Video ISO (незашифрованный)** → `dvd:///C:/movie.iso`. Требует
  dvdnav/dvdread плагины, которых у нас нет (§3, п.2) - их надо завендорить. Обход
  защиты отсутствует - чистый STANDARD.
- **Blu-ray ISO (незашифрованный)** → `bluray:///C:/movie.iso`. Плагин libbluray
  **уже есть**, работает из коробки. Для показа меню - опция `:bluray-menu`.

Монтирование средствами ОС для DVD/BD **не нужно** и только добавляет сложность
(буква диска, lifecycle, no-UNC). Оно требуется лишь для data-ISO (§5.3), куда VLC
залезть не может.

### 5.3 Data-ISO: монтирование ОС или DiscUtils (единственные, кому нужен «вход внутрь»)

У VLC **нет** универсального access-модуля «открой произвольный .iso и покажи
файлы внутри». Значит, у data-ISO (обычные `.mkv`/`.mp4` без DVD/BD-структуры) есть
ровно два STANDARD-пути достать содержимое:

**Вариант A - управляемый парсер DiscUtils (предпочтительно).** Библиотека
**DiscUtils** (.NET, лицензия MIT) читает ISO 9660/UDF полностью в managed-коде:
перечислить содержимое образа, извлечь нужный медиафайл во временную папку, играть
его как обычный файл. Плюсы: **без монтирования, без админ-прав, работает и с
удалённым образом** (открыть `Stream` по UNC/HTTP и парсить). Минус: лишняя
зависимость + распаковка во временную папку (место/время). Может закрыть data-ISO
целиком и снять зависимость от OS-монтирования вовсе.

**Вариант B - монтирование средствами Windows.** Смонтировать образ (`X:\`) → скан
`X:\` **как обычной папки** существующим файловым сканером
([Main_Form.FileScanning.vb](../../src/Main_Form.FileScanning.vb)) → пользователь
листает/сортирует как всегда. Механика без прав администратора:
- **Не** PowerShell-цмдлет `Mount-DiskImage` (может требовать UAC, тяжёл из VB), а
  Win32 **`AttachVirtualDisk`** (`virtdisk.dll`) с `ATTACH_VIRTUAL_DISK_FLAG_READ_ONLY`.
  Монтирование ISO на чтение на Windows 8+ доступно обычному пользователю (Проводник
  монтирует двойным кликом без UAC) - но **проверить эмпирически** (O-ISO-1).
- Lifecycle: `AttachVirtualDisk` → найти назначенную букву (`GetVirtualDiskPhysicalPath`
  → номер диска → том → буква); при смене файла/выходе - `DetachVirtualDisk`. Держать
  реестр смонтированного нами; **никогда** не размонтировать чужие образы. Минус:
  буква диска + lifecycle-менеджмент; **не работает для удалённых образов** (§5.5).

Рекомендация: для data-ISO взять **DiscUtils** (Вариант A) - он и локальный, и
удалённый случай закрывает без монтирования и админ-прав; OS-монтирование (Вариант B)
держать как опцию/фолбэк, если DiscUtils споткнётся на редком UDF-варианте.

### 5.4 Классификация ISO перед открытием

Тип образа определяем **до** открытия дешёвым DiscUtils-листингом корня: есть
`VIDEO_TS\` → DVD (`dvd://`); есть `BDMV\` → Blu-ray (`bluray://`); иначе → data-ISO
(DiscUtils-извлечение / монтирование + скан). Один и тот же managed-парсер и
классифицирует, и достаёт файлы из data-ISO - лишней инфраструктуры не надо.

### 5.5 Удалённые ISO

- **DVD/BD-ISO с сетевой шары (UNC).** Поскольку VLC читает образ сам, а UNC-путь
  (`\\server\share\movie.iso`) - валидный файловый путь для ОС, MRL
  `dvd:///\\server\share\movie.iso` / `bluray://..` **может читаться напрямую по
  SMB** без монтирования и копирования (VLC-ридер тянет секторы через
  Windows-редиректор). Медленно, но без промежуточных шагов - **проверить**
  (O-ISO-2). Явные `smb://`-схемы для DVD/BD скорее не сработают (libdvdread/libbluray
  ждут файловый путь, а не VLC-access-цепочку), поэтому - именно UNC.
- **Data-ISO удалённо** → **DiscUtils по сетевому `Stream`** (UNC/HTTP), извлечь файл
  во временную папку - рабочий STANDARD-путь без монтирования и админа.
- **OS-монтирование по сети невозможно.** Проверено: Windows `Mount-DiskImage`/
  `AttachVirtualDisk` работают только с локальным путём; UNC и сетевые диски не
  монтируются (ограничение Windows). Значит для удалённого ISO монтирование как
  стратегия отпадает - и хорошо, что и DVD/BD (прямой MRL по UNC), и data-ISO
  (DiscUtils по `Stream`) обходятся без него. Крайний случай (образ читается по сети
  слишком медленно) - предложить пользователю явным действием скопировать в
  `%TEMP%`; автоматически десятки ГБ BD не копируем.

## 6. Граница охвата: коммерческие защищённые DVD/Blu-ray - вне рамок

Проект **не делает ничего, связанного с обходом DRM**, и публикуется в Microsoft
Store - политика Store прямо запрещает средства обхода технических мер защиты.
Поэтому воспроизведение **коммерческих защищённых дисков** - единственный сценарий,
который мы **не поддерживаем вообще**. Причина не в кодеках, а в DRM: содержимое
зашифровано, и его показ требует **обхода защиты**, чего мы не делаем ни в каком виде
(ни бандлом, ни докачкой, ни «self-service-хуком», ни подсказкой в UI).

Что именно требуют такие диски (для понимания, где проходит граница - не как
инструкция):

- **DVD (CSS):** потребовал бы `libdvdcss.dll` (GPL; распространение спорно из-за
  антиобходных норм вроде DMCA; GPL-инфекция несовместима с нашим проприетарным
  Store-приложением).
- **Blu-ray (AACS/BD+):** потребовал бы `libaacs.dll` + внешняя база ключей
  `keydb.cfg` (+ при BD+ `libbdplus.dll`). Ключи проприетарные; даже сам VLC как
  open-source не имеет права их поставлять. Бандл/докачка таких ключей = раздача
  средства обхода защиты.

**Решение (жёсткое):** `libdvdcss`, `libaacs`, `keydb.cfg`, `libbdplus` **никогда не
входят в дистрибутив, не скачиваются и не подключаются** - ни автоматически, ни как
опция «положи сам». Никакого UI, ни справочной строки, поощряющей дешифровку. Если
пользователь открывает защищённый образ - показываем нейтральное «диск защищён,
воспроизведение недоступно» и всё.

Свободные плагины `libdvdnav`/`libdvdread` (§3, §8-Ф-D) - это **НЕ** средства обхода
защиты (они лишь навигация по незашифрованному DVD), их вендорить можно и нужно;
`libdvdcss` и AACS-компоненты - принципиально другая категория, их не трогаем.

## 7. Рекомендация (итог ресёрча)

1. **MKV** - довести до конца в modern-сборке: локальный уже работает; снять гейт
   `File.Exists` для удалённых URI (§4.2). Дёшево, чисто, STANDARD.
2. **Незашифрованные DVD/BD-ISO** - STANDARD, играть **прямым MRL по пути к образу
   без монтирования**: `bluray:///..iso` (плагин уже есть) и `dvd:///..iso` (нужно
   завендорить свободные `libdvdnav`/`libdvdread`, §3). VLC читает образ сам.
3. **Data-ISO** - самый частый бытовой кейс; VLC внутрь не заглянет. Достаём
   содержимое **DiscUtils** (managed, MIT, без монтирования и админа, локально и
   удалённо); OS-монтирование `AttachVirtualDisk` - опция/фолбэк (проверить O-ISO-1).
4. **Коммерческие защищённые DVD/BD** - **вне рамок**: не поддерживаем, не бандлим,
   не хукаем и не подсказываем никакую дешифровку (Store-политика, §6). Защищённый
   образ → нейтральное «диск защищён, воспроизведение недоступно».
5. Всё это - **в modern-сборке (.NET 10)**. Legacy x86-вьювер (раздел 1.1 базовой
   спецификации) намеренно урезан - ISO-поддержку туда не тащим.

Граница охвата проходит ровно по DRM: **нет обхода защиты - поддерживаем; нужен обход
(CSS/AACS/BD+) - вне рамок**. Всё, что не требует ломать шифрование (контейнеры,
кодеки, незашифрованные образы, монтирование, парсинг файловой системы), - легально,
Store-совместимо и реализуемо.

## 8. План работ по фазам

- **Ф-A. MKV в modern.** Убедиться, что после снятия WebBrowser MKV идёт прямо в
  VLC. Снять гейт `File.Exists` для удалённых MRL в `PlayVideoWithVlcAsync`
  (локальный/UNC - как есть; URI-схемы - строкой в `Media(..., FromType.FromLocation)`).
- **Ф-B. Диспетчер ISO + классификация (DiscUtils).** `.iso` в новом списке (не в
  `video_File_Extensions` - отдельная ветка). Подключить `DiscUtils` (MIT); дешёвым
  листингом корня определить тип: `VIDEO_TS\` → DVD, `BDMV\` → Blu-ray, иначе →
  data-ISO. Ветвление задаёт, каким путём открывать (Ф-C/Ф-D).
- **Ф-C. DVD/BD-ISO прямым MRL.** Играть `bluray:///..iso` (плагин есть) и
  `dvd:///..iso` **без монтирования** - VLC читает образ сам. Локальный путь и UNC
  (`\\server\..iso`) - оба строкой в `Media(..., FromType.FromLocation)`.
- **Ф-D. DVD-плагины.** Завендорить `libdvdnav_plugin.dll` + `libdvdread_plugin.dll`
  (LGPL/GPL, из официальной сборки VLC 3.0.21) в `plugins/access/`; учесть в
  `build.ps1`/деплое и в упаковке (Inno/MSIX/portable). Проверить незашифрованный
  DVD-ISO (без этого DVD-ветка не заиграет).
- **Ф-E. Data-ISO через DiscUtils.** Извлечь целевой медиафайл во временную папку
  (или отдать managed `Stream` в LibVLC через `imem`, если без распаковки), играть,
  убирать за собой. Работает локально и удалённо (`Stream` по UNC/HTTP). Опционально:
  OS-монтирование `AttachVirtualDisk` (`virtdisk.dll`, read-only, поиск буквы,
  lifecycle, размонтаж при смене файла/выходе) как фолбэк - **проверить работу без
  админ-прав** на Win10/11/Server 2016+ (O-ISO-1).
- **Ф-F. Защищённые диски - явный отказ (не hook!).** Если открыт зашифрованный
  CSS/AACS-образ, показать нейтральное «диск защищён, воспроизведение недоступно».
  **Никаких** `libdvdcss`/`libaacs`/`keydb.cfg` - ни бандла, ни докачки, ни опции
  «положи сам», ни подсказок (§6, Store-политика). Это не фаза-фича, а инвариант.
- **Ф-G. UI/UX.** Индикация «Открываю образ..», обработка ошибок (битый образ,
  нет dvd-плагина, защищённый диск → понятное нейтральное сообщение), ассоциация
  `.iso` (опционально - открытый вопрос).

## 10. Риски

- **Монтирование без админа** - гвоздь. Если на какой-то целевой ОС
  `AttachVirtualDisk` для ISO всё же требует прав - придётся либо UAC (нарушает
  no-admin принцип), либо ограничиться DiscUtils-парсингом для data-ISO и отказаться
  от DVD/BD-ISO. Проверить рано (Ф-B, O-ISO-1).
- **Lifecycle смонтированных образов** - утечки букв дисков/handle при падении,
  «висящие» приводы. Нужен надёжный размонтаж (в т.ч. в `Application.ThreadException`/
  выходе) и защита «размонтируем только своё».
- **Вес дистрибутива** - dvd-плагины мелкие, но DiscUtils + временная распаковка
  data-ISO едят место; удалённый BD-ISO копировать (~десятки ГБ) - неприемлемо
  автоматически.
- **Дрейф legacy/modern** - ISO/DVD-фича только в modern; следить, чтобы `#If`-швы
  не ломали legacy-компиляцию.
- **Случайно не завезти средство обхода DRM.** `libdvdnav`/`libdvdread` вендорить
  можно (это навигация, не дешифровка); `libdvdcss`, `libaacs`, `keydb.cfg`,
  `libbdplus` - **никогда** (Store-политика, §6). При отборе плагинов из полной
  сборки VLC следить, чтобы CSS/AACS-компоненты не попали в дистрибутив.
