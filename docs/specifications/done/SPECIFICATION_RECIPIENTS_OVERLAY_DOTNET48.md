> dcc066e). Плавающая панель получателей поверх медиа (`Main_Form.RecipientsOverlay.vb`,

## 0. Что послужило триггером

В окне «Настройки» есть галочка **«Держать это окно поверх остальных»** (`SetOnTop`
на вкладке «Файлы и система», группа «Окно»).

Её **изначальный смысл** был другим. Когда-то `Table_Form` было именно *таблицей
каталогов-получателей* (только сетка `DEL + 0..9`), и «поверх остальных» держало
эту таблицу над картинкой - чтобы сортировщик, гоняя папку одной рукой на мыши,
**кликал по получателю прямо поверх изображения** и раскидывал файлы мышью.

Со временем `Table_Form` разрослось в полноценное окно настроек с пятью вкладками
(просмотр, видео, файлы, OCR..). Держать *это* окно поверх картинки смысла больше
нет - тем более что окно настроек почти всегда открывается **модально**
(`ShowDialog`, F2), где `TopMost` вырождается в no-op. Исходная идея «получатели
поверх медиа» оказалась потеряна.

**Задача:** вернуть исходную идею отдельной узкой плавающей панелью получателей, а
галочку - переименовать, отвязать от окна настроек и по умолчанию выключить.

### 1.2 Модель каталогов-получателей

Хранилище: `Public Hardkeys_to_move_mediafile(10) As String`
([Common_Module.vb:4](../../../src/Common_Module.vb#L4)) - массив на 11 элементов
(индексы 0..10).

**Рантайм-конвенция (авторитетная, задаётся клавиатурой)**
([Main_Form.KeyboardInput.vb:115-144](../../../src/Main_Form.KeyboardInput.vb#L115-L144)):

| Клавиша | Вызов | Слот |
|---------|-------|------|
| `1`..`9` | `PoMove(1)`..`PoMove(9)` | 1..9 |
| `0` | `PoMove(10)` | **10** |
| `D`/`Delete` | `ReadShowMediaFile("DeleteFile")` | - (удаление) |

`PoMove(slot)` ([Main_Form.FileOperations.vb:64](../../../src/Main_Form.FileOperations.vb#L64))
читает `Hardkeys_to_move_mediafile(slot)`, пустой путь = «нет каталога для клавиши»,
иначе переносит/копирует текущий файл (учёт `Is_Copying_not_Moving` и
`chkbox_Independent_Thread_For_File_Operation`). Слот `0` в рантайме не используется.

`Image_Panel_Form` адресует так же: `Hardkeys_to_move_mediafile(If(idx=0, 10, idx))`
([Image_Panel_Form.vb:516](../../../src/Image_Panel_Form.vb#L516)) - т.е. `0 -> слот 10`.

### 1.3 Два исторических бага адресации (важно для корректности панели)

**Баг A - двойной клик по сетке настроек уводит на +1 слот.**
`DataGridView1_CellMouseDoubleClick` по колонке-клавише зовёт `Main_Form.DoKey(e.RowIndex)`
([Table_Form.vb:312-314](../../../src/Table_Form.vb#L312-L314)), а
`DoKey` ([KeyboardInput.vb:228-236](../../../src/Main_Form.KeyboardInput.vb#L228-L236)):

```vb
If keyIndex = 0 Then ReadShowMediaFile("DeleteFile") Else PoMove(keyIndex + 1)
```

Строка сетки `z` (1..10) показывает слот `z`, но двойной клик выполняет
`PoMove(z+1)` = **чужой слот**. Строка «0» (row 10) вызывает `PoMove(11)` -
**выход за границы массива** (0..10), необработанное исключение. `DoKey`
вызывается **только** из этой сетки (других вызовов в коде нет), клавиатура его не
использует.

**Баг B - каталог клавиши «0» не сохраняется.**
Загрузка ([Lifecycle.vb:453-456](../../../src/Main_Form.Lifecycle.vb#L453-L456)):

```vb
For z = 0 To 9 : Hardkeys_to_move_mediafile(z) = GetSetting(.., "MoveOn" & z, "") : Next
Hardkeys_to_move_mediafile(10) = GetSetting(.., "MoveOn0", "")   ' слот 10 <- MoveOn0
```

Сохранение ([Lifecycle.vb:575-583](../../../src/Main_Form.Lifecycle.vb#L575-L583)):

```vb
For z = 0 To 9 : SaveSetting(.., "MoveOn" & z, Hardkeys_to_move_mediafile(z)) : Next
```

Сохраняются только `MoveOn0..MoveOn9` из слотов 0..9. Слот **10** (рантайм-клавиша
«0», куда пишет сетка настроек) **не сохраняется никогда**, а при следующем старте
слот 10 читается из `MoveOn0` (= слот 0, который в рантайме не используется). Итог:
настроенный каталог клавиши «0» теряется после перезапуска.

Владелец выбрал: **починить оба бага** в рамках этой работы (раздел 5).

## 2. Целевое поведение (to-be, обзор)

1. Галочка `SetOnTop` **переименована** в «Показывать таблицу получателей поверх
   медиафайла», **отвязана** от `TopMost` окна настроек и **по умолчанию выключена**
   (после установки и переустановки).
2. Когда галочка включена, в **левом верхнем углу поверх медиа** показывается узкая
   плавающая **панель получателей**: по строке на каждый *настроенный*
   каталог-получатель + строка **«Удалить»**. Высота панели = число строк.
3. **Клик по строке = нажатие соответствующей клавиши**: строка клавиши `k` делает
   ровно то же, что нажатие `k` (перенос/копирование текущего файла в её каталог),
   строка «Удалить» = клавиша `Delete`.
4. Оба исторических бага адресации (1.3) починены, чтобы список получателей и
   клавиша «0» были достоверны везде.

Никакой новой функциональности переноса/копирования/удаления не вводится - панель
переиспользует существующие пути (`PoMove`, `ReadShowMediaFile("DeleteFile")`), так
что её поведение идентично соответствующим горячим клавишам.

## 4. Плавающая панель получателей

Строится в новом партиале **`src/Main_Form.RecipientsOverlay.vb`** (`Partial Public
Class Main_Form`), чтобы напрямую видеть `PoMove`, `panel_Media`, флаги и
`Hardkeys_to_move_mediafile` без межклассовой обвязки.

### 4.1 Что показывает

- По строке на каждый **настроенный** (непустой путь) каталог-получатель, в порядке
  клавиш `1..9`, затем `0`:
  - слот для клавиши `k∈1..9` - индекс `k`; слот для клавиши «0» - индекс `10`.
  - «настроенный» = `Hardkeys_to_move_mediafile(slot) <> ""`.
- Последней строкой - **«Удалить»** (всегда присутствует).
- **Пустое состояние** (ни одного настроенного каталога): показывать **только строку
  «Удалить»** (выбор владельца) - удаление остаётся валидным действием сортировки.

### 4.2 Содержимое строки

Выбор владельца - **клавиша + полный путь**:

```
1  D:\Photos\Keepers
2  D:\Photos\ToSort
0  E:\Archive\2026
✖  Удалить
```

- Формат: `«<клавиша>  <полный путь>»`; для строки удаления - глиф `✖` + «Удалить».
- Полные пути бывают длинными: ширина строки капится (см. 4.3), лишнее усекается
  многоточием (`AutoEllipsis`), полный путь дублируется в tooltip строки.

### 4.3 Размер и позиция

- **Узкая, но высокая**: ширина = ширина самой длинной строки, но не более
  `Min(LU(480), panel_Media.ClientSize.Width * 0.5)`; высота = сумма высот строк
  (нет пустого места снизу).
- **Позиция**: левый верхний угол `panel_Media` с отступом `LU(8)` сверху и слева.
- Все размеры/отступы через `LogicalToDeviceUnits`/`LU()` (DPI-безопасность, ср.
  [Table_Form.vb:18](../../../src/Table_Form.vb#L18)).
- В полноэкранном режиме верхний край `panel_Media` занят плавающим `flow_Toolbar`;
  чтобы не перекрывать его кнопки, при активном оверлей-тулбаре добавлять к верхнему
  отступу `flow_Toolbar.Height`. В супер-полноэкранном (тулбара нет) - базовый отступ.

### 4.4 Реализация контрола

- Рекомендуемый путь (кодо-совместимый с `flow_Toolbar`): один `Panel`
  `recipients_Overlay` как дитя `panel_Media`, `Anchor = Top Or Left`,
  `BringToFront()`. Внутри - вертикальный стек **плоских кнопок** (`Button`,
  `FlatStyle=Flat`), по кнопке на строку (≤11 штук).
- Кнопки удобны: нативный клик/hover, `AutoEllipsis`, tooltip. Список короткий -
  оверинжиниринг с owner-draw не нужен.
- Внешний вид: полупрозрачно-тёмный фон панели, светлый текст; строка «Удалить» -
  красноватый акцент и визуальный отступ/разделитель сверху. (Настоящая альфа-
  прозрачность дочернему контролу недоступна; при необходимости истинной
  полупрозрачности - вариант B из 4.7.)
- Порядок: получатели `1..9,0` сверху, «Удалить» - снизу (destructive - подальше от
  точки, куда чаще всего падает курсор). Порядок фиксируем, при желании правится
  одной константой.

### 4.5 Публичный API и триггеры пере-сборки

- `Friend Sub ApplyRecipientsOverlay()` - единая точка: если
  `Is_Show_Recipients_Overlay = False` -> скрыть/уничтожить оверлей; иначе -
  пере-строить строки из текущих `Hardkeys_to_move_mediafile`, разместить (4.3),
  `BringToFront()`.
- Вызывать `ApplyRecipientsOverlay()`:
  - при загрузке формы (3.2);
  - из `SetOnTop_CheckedChanged` (3.3);
  - при закрытии `Table_Form` (каталоги/язык могли измениться) - через
    `Main_Form` после `ShowDialog`/в обработчике закрытия;
  - при смене языка (`LngCh`) - перестроить подпись «Удалить»;
  - при ресайзе/смене режима: из `SyncMediaSurface`/`ISizeChanged`
    ([Main_Form.UILayout.vb](../../../src/Main_Form.UILayout.vb)) - только
    репозиционировать (не пересобирать строки).

### 4.6 Взаимодействие (клик)

- Одиночный левый клик по строке:
  - получатель клавиши `k` -> **тот же путь, что нажатие `k`**: `PoMove(slot)` (slot по
    4.1). Никакого `DoKey` - адресуем слот напрямую, минуя баг A.
  - «Удалить» -> `ReadShowMediaFile("DeleteFile")` (как клавиша `Delete`).
- Копирование vs перенос, независимые потоки, подтверждения, сообщения статус-бара -
  **наследуются** от `PoMove`/`DeleteFile` (учёт `Is_Copying_not_Moving`,
  `chkbox_Independent_Thread_For_File_Operation`, `Is_no_request_before_file_operation`).
  Инвариант: **клик = нажатие клавиши**, поведение бит-в-бит одинаковое.
- После действия **вернуть фокус** активной медиа-поверхности (`Me.Focus()` /
  фокус активного `Picture_Box`), чтобы клавиатурная навигация продолжала работать
  (иначе фокус останется на кнопке оверлея).
- Нет текущего файла: `PoMove`/`DeleteFile` уже выводят «! Нет файла» - оставляем как
  есть (строки не гасим).

### 4.7 Поверх видео (airspace) и порядок Z

- Картинки (`Picture_Box`) - дочерний оверлей заведомо рисуется поверх.
- `Web_Browser` (ActiveX) и `vlc_Video_View` (нативный HWND) - соседние дочерние
  окна `panel_Media`; топовый по Z-порядку сосед клиппует их в зоне перекрытия
  (тот же механизм, что у `flow_Toolbar` в fullscreen). После старта воспроизведения
  проигрыватель зовёт свой `BringToFront()` - поэтому в точках старта плеера
  ([VideoPlayer.vb:155](../../../src/Main_Form.VideoPlayer.vb#L155),
  [:191](../../../src/Main_Form.VideoPlayer.vb#L191)) и при показе нового файла
  ([Main_Form.MediaLoading.vb](../../../src/Main_Form.MediaLoading.vb)) добавить
  повторный `recipients_Overlay.BringToFront()` (если включён).
- **Вариант B (запасной)**, если поверх ActiveX/LibVLC дочерний оверлей окажется
  ненадёжен: отдельное безрамочное top-level окно, `WS_EX_NOACTIVATE` +
  `ShowWithoutActivation` (не крадёт активацию/фокус), `Owner = Main_Form`,
  позиция пересчитывается на `Move`/`Resize`/смене состояния главного окна. Оно
  рисуется поверх любых дочерних HWND и позволяет истинную полупрозрачность (layered
  window), но требует ручного сопровождения позиции. Рекомендация: начать с варианта
  A, вариант B держать как fallback.

## 5. Починка исторических багов адресации (выбор владельца - «починить оба»)

### 5.1 Баг B - персистентность клавиши «0»

Сделать `MoveOn0` постоянным домом клавиши «0» (слот 10); слот 0 в рантайме не
используется.

- Загрузка ([Lifecycle.vb:453-456](../../../src/Main_Form.Lifecycle.vb#L453-L456)):
  ```vb
  For z = 1 To 9
      Hardkeys_to_move_mediafile(z) = GetSetting(App_name, Second_App_Name, "MoveOn" & z.ToString, "")
  Next
  Hardkeys_to_move_mediafile(10) = GetSetting(App_name, Second_App_Name, "MoveOn0", "")
  ```
- Сохранение ([Lifecycle.vb:575-583](../../../src/Main_Form.Lifecycle.vb#L575-L583)):
  ```vb
  For z = 1 To 9
      SaveSetting(App_name, Second_App_Name, "MoveOn" & z.ToString, If(Hardkeys_to_move_mediafile(z), ""))
  Next
  SaveSetting(App_name, Second_App_Name, "MoveOn0", If(Hardkeys_to_move_mediafile(10), ""))
  ```
  (Совместимо со старым реестром: `MoveOn1..9` те же; `MoveOn0` теперь несёт слот 10.)
  Аккуратно с существующим `Finally ... = Nothing` в цикле сохранения.

### 5.2 Баг A - двойной клик по сетке настроек

`DoKey` вызывается только из сетки, где row `z` привязан к слоту `z`. Убрать `+1`
([KeyboardInput.vb:228-236](../../../src/Main_Form.KeyboardInput.vb#L228-L236)):

```vb
Public Sub DoKey(ByVal keyIndex As Integer)
    If keyIndex = 0 Then
        ReadShowMediaFile("DeleteFile")     ' row 0 = DEL
    Else
        PoMove(keyIndex)                     ' row z -> слот z; row 10 -> PoMove(10) = клавиша «0»
    End If
End Sub
```

Теперь двойной клик по сетке совпадает с клавиатурой, строка «0» (row 10) корректно
идёт в `PoMove(10)`, выхода за границы массива нет. (Проверить: других вызовов
`DoKey` в коде нет.)

## 9. Крайние случаи

- **Модальные настройки**: оверлей виден, но некликабелен, пока открыто модальное
  окно; после закрытия пересобирается (4.5). Ок.
- **Нет текущего файла**: клик даёт штатное «! Нет файла» из `PoMove`/`DeleteFile`.
- **Длинный путь**: усечение + tooltip (4.2).
- **Полноэкранный/супер-полноэкранный**: отступ и Z-порядок по 4.3/4.7.
- **Смена языка на лету**: перестроить подпись «Удалить» (`LngCh` -> Apply).
- **DPI 125/150/175%**: все величины через `LU()`.
- **Каталог «0» после фикса 5.1**: попадает в список и переживает перезапуск.
- **Возврат фокуса**: после клика фокус уходит на медиа-поверхность (4.6) - `N/P/1..0`
  продолжают работать без клика по картинке.

## 10. Тест-план (ручной, как принято в проекте)

1. **Дефолт**: чистая установка -> оверлея нет, галочка снята. То же после
   переустановки поверх (новый ключ отсутствует -> выкл).
2. **Включение**: настройки -> галочка -> закрыть; в левом верхнем углу поверх
   картинки узкая панель: настроенные `1..9,0` + «Удалить», высота по числу строк.
3. **Клик = клавиша**: клик по «2» переносит/копирует так же, как нажатие `2`
   (проверить оба режима - COPY и MOVE); клик «Удалить» = `Delete`.
4. **Клавиша «0»**: задать каталог для «0» в сетке, перезапустить - каталог на месте
   (баг B), клик по «0» и нажатие `0` идут в один каталог.
5. **Сетка настроек**: двойной клик по строкам `1..9,0` бьёт по своему слоту, строка
   «0» не роняет приложение (баг A).
6. **Видео**: оверлей поверх H.264 (WebBrowser) и AVI/MKV (LibVLC), клики работают.
7. **Полноэкранный/супер-ФЭ (F7/F11)**: оверлей не перекрывает кнопки тулбара,
   виден, кликабелен.
8. **Пустое состояние**: очистить все каталоги -> видно только «Удалить».
9. **Фокус**: после клика по оверлею `N`/`P` листают без клика по картинке.
10. **DPI 150%**: панель не расползается, текст в границах.
11. **Сборка**: `.\build.ps1` (net48) - без ошибок `WarningsAsErrors`.

## 11. Дорожная карта (.NET 10 mainline - не сейчас)

Владелец: в net48 - **только галочка в настройках**. В будущей .NET 10-версии
дополнительно (добавлено по его просьбе):

- **горячая клавиша** показать/скрыть оверлей на лету во время сортировки;
- **кнопка на тулбаре** главного окна (в ряд к прочим);
- (опц.) истинно полупрозрачный layered-оверлей (вариант B, 4.7), перетаскивание и
  запоминание позиции, интеграция с новой моделью зума/панорамы
  ([SPECIFICATION_ZOOM_PAN_CLASSIC_DOTNET10.md](../SPECIFICATION_ZOOM_PAN_CLASSIC_DOTNET10.md)).

Ключ реестра `ShowRecipientsOverlay`, флаг `Is_Show_Recipients_Overlay` и `PoMove`-
диспетчеризация переносятся в .NET 10 как есть - там лишь добавляются точки
переключения (клавиша/кнопка), поведение то же.

## 12. Решённые вопросы
