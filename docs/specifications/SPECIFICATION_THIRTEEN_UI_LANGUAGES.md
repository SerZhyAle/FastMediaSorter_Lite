## 2. Блок A - слой локализации и 13 языков UI

### 2.1 Форма ключа: ключ - русская строка

Берём модель CyrFlip: **ключ словаря - существующая русская строка**, значение - по переводу на язык.

Почему не `.resx` и не идентификаторы ресурсов:

- 905 мест уже держат русский текст **в точке использования**. Переход на `My.Resources.Btn_Prev_File`
  - это 905 придуманных имён и 905 правок, где каждая опечатка компилируется, но показывает не то.
  Замена `If(Is_Russian_Language, "Каталог:", "Folder:")` → `T("Каталог:")` - механическая и
  проверяемая глазами в диффе.
- Незнакомый ключ возвращает **сам ключ**: новая строка видна на русском, но никогда не падает и
  никогда не показывает `MISSING_KEY_42`.
- Тест парности (§7.1) ловит именно то, что при `.resx` ловил бы компилятор: строку без перевода.

Плата за это - осознанная: **русский текст остаётся в исходниках**, вопреки общему правилу «артефакты
по-английски». Это цена, которую CyrFlip уже заплатил и о которой знает; альтернатива (ключ - английская
строка) означала бы переписать те же 905 мест дважды. Фиксируем как локальное исключение этой
спецификации.

### 2.2 Где физически живёт слой

Три проекта, **два непересекающихся набора исходников**:

- просмотрщик - `src/**` минус `Modern/` и `FastMediaSorterCompanion/` (см. `Exclude` в
  [FastMediaSorter.Modern.vbproj](../../src/Modern/FastMediaSorter.Modern.vbproj));
- компаньон - только `src/FastMediaSorterCompanion/**` (дефолтные globs SDK).

Поэтому раскладка такая:

```
src/Localization/
  Localization.vb              ' ядро: Names, Codes, Translate, IsRightToLeft, FontFamily, Scaled, DefaultLanguage
  Localization.Registry.vb     ' RegisterStrings() просмотрщика: вызывает Add*Strings() ниже
  Localization.Main.vb         ' строки Main_Form.* (панель, тулбар, подсказки, статусы)
  Localization.Settings.vb     ' строки Table_Form.* (включая ModernLayout - самый большой файл)
  Localization.Ocr.vb          ' строки Table_Form.Ocr.vb + Main_Form.Ocr*
  Localization.Media.vb        ' медиаменю, видео, дорожки, масштаб, оверлеи
  Localization.Files.vb        ' файловые операции, ассоциации, диалоги подтверждения
src/FastMediaSorterCompanion/Core/
  Localization.vb              ' <Compile Include="..\..\Localization\Localization.vb" Link="Core\Localization.vb" />
  Localization.Registry.vb     ' RegisterStrings() компаньона
  Localization.Share.vb        ' строки MainWindow, PackageWizard, ShareText, Share_*_Form, TrayContext
```

Ядро - **один файл, слинкованный в оба проекта** (`<Compile Include=".." Link=".." />` в
`FastMediaSorterCompanion.vbproj`). У проектов разные `RootNamespace` (`fmsl` и
`FastMediaSorterCompanion`), поэтому один и тот же исходник даёт два независимых типа - это
допустимо и желательно: наборы строк у них разные, а движок один.

Класс: `Partial Public NotInheritable Class Localization` с `Shared`-членами и закрытым конструктором
(VB не поддерживает `Partial Module`, поэтому именно класс). `Shared Sub New()` в ядре вызывает
`RegisterStrings()`, который **обязан** предоставить каждый проект в своём партиале. Забыли -
`BC30451: 'RegisterStrings' is not declared`, то есть та же «хорошая» поломка, которой репозиторий уже
пользуется для списка `<Compile>` в net48-проекте.

### 2.3 Публичный API ядра

```vb
Public Shared ReadOnly Codes As String()   ' {"ru","en","uk","de","it","es","fr","pt","ar","hi","bn","ur","zh"}
Public Shared ReadOnly Names As String()   ' эндонимы, тот же порядок

Public Shared Property CurrentCode As String        ' "ru".."zh"; сеттер валидирует и падает на "en"
Public Shared Function T(ru As String) As String    ' перевод; неизвестный ключ -> ru; пустой перевод -> English
Public Shared Function IsRightToLeft() As Boolean   ' ar, ur
Public Shared Function FontFamily() As String       ' Nothing = шрифт по умолчанию
Public Shared Function Scaled(width As Integer) As Integer  ' ширины колонок под длину языка
Public Shared Function DefaultCode() As String      ' язык ОС при первом запуске
Friend Shared Sub Add(ru As String, en As String, uk As String, de As String, it As String,
                      es As String, fr As String, pt As String, ar As String, hi As String,
                      bn As String, ur As String, zh As String)
Friend Shared ReadOnly Property All As IEnumerable(Of KeyValuePair(Of String, String()))  ' для теста
```

`T` - короткое имя намеренно: оно встанет в 905 мест, и `Localization.Translate(..)` там нечитаемо.

**Правило подстановки.** Ни одна строка не собирается конкатенацией переведённых кусков. Сейчас есть
именно такое: `"Файл занят, ждём разблокировки (качается?): " & Path.GetFileName(..)`
([Main_Form.Lifecycle.vb:447](../../src/Main_Form.Lifecycle.vb#L447)). Такие места переезжают на
`String.Format(T("Файл занят, ждём разблокировки (качается?): {0}"), name)` - иначе порядок слов
ломается в языках с другим синтаксисом, а в RTL ещё и направление.

### 2.4 Хранение и миграция

Новое значение в **той же** ветке (`GetSetting/SaveSetting(App_name, Second_App_Name, ..)`):

| Значение | Тип | Содержимое |
| --- | --- | --- |
| `UiLanguage` | строка | **ISO-код**: `ru`, `en`, `uk`, `de`, .., `zh` |
| `Is_Russian_Language` | строка `0`/`1` | **остаётся**, но становится производным зеркалом: `1` ⇔ `UiLanguage = "ru"` |

Хранится **ISO-код, а не эндоним** - отличие от CyrFlip, и сознательное: этот же код служит именем папки
сайта, суффиксом README, значением `hreflang` и колонкой CSV. Один код на язык на всех поверхностях -
требование канона; эндоним пришлось бы отображать в код в четырёх местах.

**Порядок разрешения языка при старте** (первое сработавшее выигрывает):

1. `UiLanguage` из реестра, если это один из 13 кодов;
2. `Is_Russian_Language` из реестра (старая установка): `1` → `ru`, `0` → `en`;
3. `DefaultCode()` - `CultureInfo.CurrentUICulture.TwoLetterISOLanguageName`, затем
   `InstalledUICulture`, оба сводятся к языку без региона (`de-AT` → `de`, `pt-BR` → `pt`,
   `zh-Hans-CN` → `zh`); нет совпадения → `en`.

Пункт 3 заменяет нынешний `SystemDefaultIsRussian()`, который умеет ровно один вопрос («это русский?»).
Функция сохраняется как тонкая обёртка `DefaultCode() = "ru"` - её зовут из мест, которые ещё не
переписаны.

`Is_Russian_Language` **продолжает писаться** при каждом сохранении. Это дешёвая страховка на два случая:
откат на предыдущую версию exe и рассинхрон, если компаньон когда-нибудь отстанет от просмотрщика.

**`Is_Russian_Language` в памяти становится производным.** Объявление в
[Common_Module.vb:5](../../src/Common_Module.vb#L5) и
[CompanionGlobals.vb:19](../../src/FastMediaSorterCompanion/Core/CompanionGlobals.vb#L19) меняется с поля
на `ReadOnly Property` = `Localization.CurrentCode = "ru"`. Смысл - в том, что **326 непереписанных мест
продолжают компилироваться и вести себя разумно** (немец видит английский, а не русский), пока идёт
перенос строк. Это и делает блок A выполнимым по частям, а не одним диффом на 905 строк.

Свойство **остаётся навсегда**, даже когда все 326 мест переписаны (решение владельца 8). Удалять его,
чтобы «поймать компилятором», смысла нет: оно ничего не стоит, ловит любой пропущенный или заново
написанный вызов, и его продолжает читать `CompanionGlobals`. Вместо удаления - проверка в тесте §7.1,
что в исходниках не осталось ни одного чтения; тогда компилятор молчит, а тест говорит.

### 2.6 Скрипты, шрифты, направление письма - что здесь **сложнее**, чем в CyrFlip

Три отличия от образца, каждое стоит отдельной работы.

**(а) Базовый шрифт не покрывает арабицу.** CyrFlip живёт на Segoe UI, который умеет арабский. Здесь
`ApplyApplicationDefaults` в [Application_Events.vb](../../src/Application_Events.vb) намеренно
закрепляет **`Microsoft Sans Serif` 8.25** - это эталонное поведение net48-сборки, снимать его нельзя.
Microsoft Sans Serif арабского не покрывает. Значит, шрифт переопределяется **для пяти** языков, а не для
трёх: `ar`/`ur` → `Segoe UI`, `hi`/`bn` → `Nirmala UI`, `zh` → `Microsoft YaHei UI`.

**(б) Смена шрифта двигает пиксельно выверенную вёрстку.** Форма DPI-unaware, `Main_Form.Designer.vb`
расставлен по координатам. Поэтому шрифт **не** ставится на форму целиком: `Localization.FontFamily()`
применяется точечно - к контролам, которые показывают переведённый текст, с сохранением кегля 8.25.
Список таких контролов формируется по факту в A5 и заносится в код одним хелпером
`ApplyScriptFont(control)`, чтобы не разъезжаться между окнами.

**(в) Длинные языки главное окно переживёт само.** Немецкий и португальский дают самые длинные подписи, и
именно здесь у FMS есть то, чего не было у CyrFlip: [Main_Form.ToolbarOverflow.vb](../../src/Main_Form.ToolbarOverflow.vb)
уже сворачивает всё, что не влезло, в выпадающее «»» по каждому ряду - и мерит **реальную** ширину
текста. То есть тулбар подстраивается бесплатно; проверить надо, что `LocalizeToolbarOverflow()`
вызывается **после** смены языка (сейчас вызывается - [Main_Form.Localization.vb:76](../../src/Main_Form.Localization.vb#L76)),
и что кнопка языка не уезжает в overflow сама (иначе язык не вернуть).

**(г) RTL: главное окно и диалоги разводятся.**

- **Диалоги и окно настроек** - `RightToLeft = Yes` **и** `RightToLeftLayout = True`. Настройки на
  .NET 10 (`Table_Form.ModernLayout.vb`) построены смешанно, и это главный объём шага A4: **24**
  обращения к `FlowLayoutPanel` (они **не** зеркалятся сами - им нужен `FlowDirection.RightToLeft`
  явно; та же ловушка, что описал CyrFlip), **12** явных `.Location = New Point(..)` и **19** присвоений
  `.Left`/`.Top`, против всего **10** `.Dock`. То есть «панелями и докингом» это окно построено только
  наполовину - каждую из 31 явной координаты надо либо пересчитать от правого края, либо перевести на
  докинг.
- **Главное окно** - `RightToLeft = Yes` (направление текста в подписях, меню, подсказках), но
  **`RightToLeftLayout` остаётся `False`** (решение владельца 5). Причина конкретная:
  `RightToLeftLayout` зеркалит клиентскую область целиком, а из прямоугольника `PictureBox` выводят
  свою геометрию `Draw_Perspective` (перспективный фон), оверлей OCR и `PaintInfoOverlay`.
  Зеркалирование потребовало бы пересчёта всех трёх, и цена этого несоразмерна выигрышу: в просмотрщике
  смысловой центр - картинка, а не порядок кнопок. Порядок кнопок тулбара тоже **не** разворачивается -
  это было бы отдельной веткой в `LayoutToolbar()`, которая ломается при каждой правке тулбара.

### 2.7 Выбор языка в интерфейсе

**Просмотрщик.** Кнопка `btn_Language` перестаёт быть тумблером. Новое поведение: показывает **код
текущего языка** в верхнем регистре (`RU`, `EN`, `DE`, `عر` - нет, для арабского и урду тоже латинский
код `AR`/`UR`, иначе он нечитаем в узкой кнопке), клик открывает `ContextMenuStrip` из 13 пунктов
«флаг + эндоним», текущий помечен галочкой. Флаги берутся из уже существующего механизма
`FlagImages` ([OcrLanguageCatalog.vb](../../src/OcrLanguageCatalog.vb)), файлы - `assets/flags/<code>.png`.

**Добавить два PNG:** `assets/flags/bn.png` и `assets/flags/ur.png` - их нет. Оба проекта забирают
папку глобом (`<Content Include="..\assets\flags\*.png">` и `<EmbeddedResource ..>`), так что правок в
`.vbproj` для этого не нужно.

**Окно настроек.** Тумблер языка на вкладке «Файлы и система» становится `ComboBox` с 13 эндонимами и
флагами (owner-drawn, как уже сделано для языков OCR). Смена немедленно перерисовывает окно - как
сейчас делает `Table_Form.LngCh()`.

**Share Manager - своего выбора языка не получает.** Он и сегодня только читает значение, которое пишет
просмотрщик ([CompanionGlobals.vb:23](../../src/FastMediaSorterCompanion/Core/CompanionGlobals.vb#L23)),
и эта асимметрия правильная: два поля выбора на одно значение - это способ рассинхронизировать UI. В
окне компаньона язык показывается как факт (в статусной строке), со ссылкой «сменить в настройках
просмотрщика».

### 2.8 `OcrLanguageCatalog` - как не получить 429 строк

Сейчас `LanguageEntry` хранит `NameEn` + `NameRu` на каждый из 33 языков распознавания. Наивное
расширение - 33 × 13 = **429** переводов, которые никто не вычитает.

**Решение: переходим на эндонимы.** `LanguageEntry` получает одно поле `Name` - самоназвание языка
(`English`, `Русский`, `Deutsch`, `日本語`, ..). Ровно 33 строки вместо 429, они не требуют перевода по
определению, и это ровно то, что делают системные списки языков Windows и браузеров. Исключение -
единственная псевдо-запись `auto` («Автоопределение»), которая уходит в общий слой как обычная строка на
13 языков.

Побочный эффект в плюс: рядом с эндонимом уже стоит флаг, так что список читается и тем, кто не знает
языка интерфейса.

### 2.9 Сборка x86/net48 - что там будет

Слой компилируется в **обе** сборки (он лежит в общем дереве), но список языков урезан сеймом:

```vb
#If NETFRAMEWORK Then
    ' Win 7/8.1 и 32-битная Windows: интерфейс остаётся RU/EN.
    Public Shared ReadOnly Codes As String() = {"ru", "en"}
#Else
    Public Shared ReadOnly Codes As String() = {"ru", "en", "uk", "de", ..}
#End If
```

Две причины, и вторая - техническая, а не только политика сопровождения:

1. Политика из [CLAUDE.md](../../CLAUDE.md): в net48-фолбэк не добавляют возможности, только чинят
   найденные баги; расхождение уводится за `#If NETFRAMEWORK`.
2. **`Nirmala UI` появился в Windows 8.** На Windows 7 - целевой машине x86-сборки - хинди и бенгальский
   отрисуются квадратами. Обещать язык, который на этой ОС не читается, хуже, чем честно его не
   предлагать.

Строковые таблицы при этом общие: `Add(ru, en, uk, de, ..)` компилируется целиком, просто в x86-сборке
`Translate` никогда не спросит индекс больше 1. Дублировать таблицы под две сборки нельзя - это
гарантированный дрейф.

> **Ловушка сборки, читать до первого коммита.** Старый проект
> [src/FastMediaSorter.vbproj](../../src/FastMediaSorter.vbproj) держит **явный список из 71
> `<Compile Include>`** - новый `.vb` в него надо добавить **руками**, в том же коммите. Современный
> проект берёт `..\**\*.vb` глобом и файл увидит; x86-сборка упадёт на первом же обращении
> (`BC30451: 'Localization' is not declared`) - и это хороший случай. Плохой - если файл ни на что не
> ссылается: он молча не попадёт в x86-exe.

## 3. Блок B - сайт: 13 первых страниц

### 3.1 Схема

Сайт отдаётся из **корня** (`.sza-canon.json` → `site.root: "."`). Значит:

```
index.html            ' остаётся: английский вход + in-page переключатель en/ru/uk + ссылки на 10 остальных
ru/index.html         ' новые: своя страница на язык
uk/index.html
de/index.html  it/index.html  es/index.html  fr/index.html  pt/index.html
ar/index.html  hi/index.html  bn/index.html  ur/index.html  zh/index.html
```

Существующие `how-to-viewer.html`, `how-to-sftp.html`, `publish-folders-android.html` **остаются на
EN/RU/UK** - полный гид на 13 языков никто не вычитает, а полуготовый гид хуже честного английского
(канон `LOCALIZATION.md` §1). Со страниц остальных языков - ссылка на английский гид с явной подписью,
что он на английском.

### 3.2 Что на странице

Первая страница - минимальный, но самодостаточный набор:

1. Заголовок + одна фраза, что это.
2. 4-6 карточек возможностей (сортировка одной клавишей, слайдшоу, воспроизведение видео, фон Ambilight,
   OCR-перевод, раздача папки на Android).
3. Блок «Важно знать»: бесплатно, открытый код, две сборки (современная x64 и запасная x86 для Windows 7).
4. Кнопки загрузки: GitHub Release, winget, Microsoft Store.
5. Ссылка на английский гид + ссылка на политику приватности.
6. Переключатель на 13 языков (один и тот же компонент на всех страницах).

### 3.3 Обязательная разметка

- `<html lang="<code>">`, и `dir="rtl"` для `ar`/`ur`;
- полный набор `<link rel="alternate" hreflang="<code>" href="..">` на все 13 + `x-default` → корень;
- `<link rel="canonical">` на **свой** URL, не на корень;
- `og:locale` и `og:url` под язык; `og:image` общий;
- переключатель отдаёт **абсолютные** пути от корня сайта (`/FastMediaSorter_Lite/de/`), иначе он
  ломается на вложенном уровне GitHub Pages.

### 3.4 Ловушка RTL в тёмной вёрстке

Проверить на `ar`/`ur`, что при `dir="rtl"` не разъезжаются: сетка карточек, паддинги с `padding-left`,
иконки-эмодзи перед текстом, `text-align` в кнопках загрузки и стрелки «→» (в RTL их меняют на «←» или
убирают). Логические свойства CSS (`padding-inline-start` вместо `padding-left`) решают это разом - если
текущая таблица стилей их не использует, перевести затронутые правила.

### 3.5 `docs/` - решить и записать

`docs/index.html` - неопубликованная копия редизайна; `.sza-canon.json` прямо предупреждает, что она
**не** обязана совпадать с корневой. Эта спецификация её не трогает: 13 языков делаются в корне, то есть
на живом сайте. Если редизайн когда-нибудь въедет в корень, папки `<lang>/` переезжают вместе с ним -
менять придётся только пути в переключателе. Зафиксировано, чтобы не получить 26 страниц вместо 13.

### 5.2 winget - **остаётся на `en-US`, изменений нет**

Решение владельца 4. Сейчас одна локаль - `SerZhyAle.FastMediaSorter.locale.en-US.yaml`; так и остаётся.
Схема winget позволяет добавить `*.locale.<tag>.yaml`, но мы этого **не делаем**:

- каждый локальный манифест - ещё один файл, который надо обновлять при **каждом** релизе
  (`PackageVersion` дублируется в каждом), а `wingetcreate update` трогает только версию и инсталлятор.
  13 локалей - это 13 способов забыть один файл и получить отказ валидации;
- CLI winget в консоли Windows плохо отрисовывает арабский и индийские шрифты и ломает выравнивание
  вывода;
- аудитория winget - разработчики, у которых английский по умолчанию.

Единственное, что меняется на этом канале: `ShortDescription`/`Description` в `en-US` упоминают, что
интерфейс программы доступен на 13 языках. Это факт о продукте, и он должен быть в описании.

**Заморожено (не трогать никогда):** `PackageIdentifier`, `PackageName` («FastMediaSorter LITE» -
коррелирует с ARP DisplayName), `Moniker`.

### 5.3 Инсталлятор Inno - **мастер остаётся английским**

Решение владельца 4: *если при установке перевода нет - английский, но интерфейс внутри переведён.*
Секция `[Languages]` на 13 языков **не добавляется**.

Обоснование, а не только «проще»:

- Inno Setup 6 покрывает **официальными** `.isl` только часть нашего набора (немецкий, итальянский,
  испанский, французский, португальский, русский, украинский). Для **арабского, хинди, бенгальского,
  урду и китайского** официальных переводов нет - там либо неофициальный `.isl` неизвестного качества,
  либо всё равно английский мастер;
- «7 языков из 13» - это не локализованный мастер, а **лотерея**: половина пользователей всё равно
  видит английский, но теперь ещё и непредсказуемо;
- переводятся всё равно только **экраны Inno**. Наши собственные строки (названия компонентов -
  «codecs», «ocr», «share» - и их описания с размерами) живут в `[CustomMessages]`, то есть переводить и
  сопровождать их пришлось бы нам, на 13 языков, при каждом изменении состава компонентов.

Мастер - это 4-5 экранов, которые видят один раз. Интерфейс - это то, в чём работают. Ресурс идёт во
второе.

**Что всё-таки делаем на этой поверхности** (одна строка, не 13 файлов): на экране «Готово» и в описании
компонента core упомянуть по-английски, что интерфейс доступен на 13 языках и меняется в настройках -
иначе пользователь, увидевший английский мастер, решит, что и программа английская.

**Заморожено:** `AppId`, `DefaultDirName`, `OutputBaseFilename`, `UninstallDisplayName`
(«FastMediaSorter LITE» - якорь корреляции ARP).

### 6.2 Что делаем

**(а) Текст баннеров - вынести из скрипта в данные.** Новый файл
`publishing/store/screenshot-copy.json`: 13 записей по ISO-коду, в каждой `title`, `line1`, `line2`.
Скрипт становится рендерером - тем самым выполняется инвариант 16 (сам PNG - render target, править надо

**(б) `capture-app.ps1` получает `-Language <code>`.** Логика: прочитать текущее `UiLanguage` из реестра

Восстановление обязательно и именно в `finally`: без него прерванный по Ctrl+C прогон оставит машину
разработчика на бенгальском.

**(в) Новый оркестратор `publishing/store/make-store-screenshots.ps1`** - прогоняет 13 языков × нужные
размеры, складывает в `assets/store/screenshot-<CODE>-<W>x<H>.png`. Печатает итоговую таблицу
«язык → файлы» и **явно перечисляет пропущенное**, если какой-то язык не снялся (канон: «no silent
caps»).

### 6.3 Ловушки рисования - все три реальны

1. **Шрифт баннера.** `System.Drawing` не подставляет шрифт автоматически так, как это делает WinForms:
   отсутствующий глиф даёт квадраты **молча**. Шрифт выбирается по коду языка (та же таблица, что в
   §1.1) и **проверяется** до отрисовки: если `FontFamily` не установлен - падать с внятным сообщением,
   а не рисовать квадраты.
2. **RTL.** Арабский и урду рисуются с `StringFormatFlags.DirectionRightToLeft`, иначе строка
   выравнивается слева и знаки препинания уезжают в конец. Форму шрифта (соединение букв) GDI+ делает
   сам, но только если выбран шрифт с арабской таблицей.
3. **Длина строк.** Немецкий и португальский длиннее английского на 15-30 %. Баннер фиксированной
   ширины (1366/720/1080) обрежет строку. Скрипт должен **измерять** (`MeasureString`) и уменьшать кегль
   до влезания, а не обрезать.

Microsoft Store требует скриншоты **только для локали по умолчанию**; остальные - опциональны, но
показываются пользователю с его языком. Практика: снять все 13 и загрузить в те листинги, которые

## 7. Блок F - как это проверяется

### 7.1 Тест паритета строк (автоматический, обязательный)

В `tests/Lite.Tests` и `tests/Companion.Tests` - по одному классу `LocalizationParityTests`:

1. **У каждой зарегистрированной строки есть непустой перевод на каждый из 13 языков.** Падение
   печатает ключ и список недостающих кодов.
2. **Нет дублирующихся ключей** (`Add` дважды с одним русским текстом - тихая перезапись).
3. **Совпадает арность плейсхолдеров**: если в ключе есть `{0}`, он есть и во всех 13 переводах.
   Это ловит самую дорогую ошибку машинного перевода - потерянный или переставленный плейсхолдер,
   который даёт `FormatException` в рантайме у пользователя, а не у нас.
4. **Нет «выжившей» кириллицы**: построить строку на каждом нерусском языке и убедиться, что в ней нет
   кириллических символов (исключения - явный белый список вроде «ЙЦУКЕН», здесь такого нет).
5. **Обратная проверка**, которую легко забыть: каждая строка, которую код передаёт в `T(..)`, должна
   быть **зарегистрирована**. Реализуется прогоном по исходникам (`T("..")` регуляркой) в тесте-сканере;
   иначе новая строка тихо показывается по-русски всем 13 языкам.

6. **`Is_Russian_Language` больше нигде не читается** (решение владельца 8): сканер по исходникам,
   исключая само объявление в `Common_Module.vb`/`CompanionGlobals.vb` и запись значения в реестр.
   Свойство живёт как страховка, но новый код через него ходить не должен.

Тест, который ничего не обошёл, зеленеет так же тихо, как чистый: добавить **контрольный факт**, что
проверка умеет падать (заведомо неполный ключ во временной таблице).

**Тест, который бежит на двух легах, не имеет права знать только один из них.** `Lite.Tests`
собирается и под `net10.0-windows`, и под `net48`, а шов `#If NETFRAMEWORK` режет `Codes` до RU+EN -
значит ожидание надо **выводить из `Codes`**, а не зашивать 13 языков. Так вышло с
[LocalizationStartupTests](../../tests/Lite.Tests/LocalizationStartupTests.vb): в первой ревизии он
требовал `MatchCulture("de-DE") = "de"` и валил net48-лег семью падениями «по дизайну». Красный
пре-флайт, который все привыкли объяснять словами, - это уже не пре-флайт (инвариант 5), поэтому тест
переписан: язык, который сборка несёт, обязан распознаться, а который не несёт - обязан дать `Nothing`,
чтобы `DefaultCode` увёл на английский, а не на квадраты. Теперь шов **сам стал предметом проверки**.

Компаньон - отдельная программа со своим набором исходников, поэтому блок делался вторым заходом,
но **движок переиспользован целиком**: `Localization.vb` и `Localization.Persistence.vb` **слинкованы**
в `FastMediaSorterCompanion.vbproj` (`<Compile Include="..\Localization\...">`), а не скопированы -
правка в `T`/`TF`/`TC` не должна делаться дважды. Отличаются только таблицы: компаньон подставляет
свой `RegisterStrings()` в `src/FastMediaSorterCompanion/Localization/Localization.Registry.vb`.
Проект, который слинкует движок и забудет таблицы, падает на `BC30451` - это правильный отказ.

| | |
| --- | --- |
| Переведено | **221 ключ × 12 языков ≈ 2 650 значений** в 5 таблицах (`.Share`, `.Manager`, `.Wizard`, `.Internet`, `.Params`); дубликатов ключей нет |
| Переписано точек вызова | **262**: 238 тернарников `If(rus, "рус", "eng")` скриптом + 12 конкатенаций руками → `TF` с плейсхолдерами, остальное - разбор массивов и подписей |
| Чтений старого флага | **0**. `CompanionGlobals.Is_Russian_Language` **удалён** совсем (в LITE он остаётся производным щитом под убывающим бюджетом) - тест держит ноль |
| `ShareText` | 23 функции лишились параметра `rus As Boolean`: текст теперь следует активному языку, а не аргументу вызывающего |
| Выбор языка | подменю «Язык интерфейса» в меню трея **и** ссылка-эндоним в нижней панели главного окна. Без флагов: компаньон не встраивает картинки флагов, а эндоним и так узнаётся |
| Смена языка | окна компаньона строятся одним проходом и не переподписываются - `UiLanguage.Changed` заставляет `TrayContext` **пересобрать** меню трея и окно (если оно было открыто) |
| Шрифты | те же три семейства, но здесь **на форму целиком**: вёрстка масштабируется по `AutoScaleMode.Dpi` (см. `DpiLayout`), поэтому шрифт не является базой масштабирования и смена семейства ничего не двигает |
| Хранение | то же `UiLanguage` в той же ветке `SZA\FastMediaSorter` - переключение в любой из двух программ видно во второй при следующем старте (инвариант 9). Тест это фиксирует |
| Офлайн-гид | `Localization.GuideCode()`: `ru`/`uk` → сами себя, всё остальное → `en`. Гид - длинный рукописный документ на трёх языках (решение §3.1), и хинди-пользователю честнее английская страница, чем несуществующая |
| Тесты | `tests/Companion.Tests/LocalizationParityTests.vb` - 9 проверок (те же, что в LITE, плюс «13 языков без сокращения», «язык лежит там, где его читает LITE», «гид падает в английский») |

**Найдено по ходу:**

- **Немецкие типографские кавычки `„…“` ломают компиляцию VB.** `“` (U+201C) компилятор
  принимает как ограничитель строкового литерала, поэтому `„Videothek“` внутри `"..."` рвал
  строку и давал каскад `BC30035` на 40 строк ниже. Заменены на `«…»`, которые ограничителями
  не являются. Это касается любого будущего немецкого текста в коде.
- **`RightToLeftLayout = True` даёт зеркало, а не RTL.** Флаг ставит `WS_EX_LAYOUTRTL`, то есть
  зеркалит весь контекст устройства окна: на скриншоте арабская сборка вышла зеркальным
  отражением - и арабские глифы, и латинский заголовок окна. Оставлен только `RightToLeft = Yes`:
  текст справа, порядок колонок и потока в layout-панелях перевёрнут, глифы целы. Тот же вывод,
  что и в LITE (§2.6 г), но по другой причине.
- **Тест поймал 7 недописанных мест.** Скрипт переписал тернарники, но префиксные конкатенации
  (`T("Роутер: ") & model`) остались - и это ровно то, ради чего тест сверяет каждую точку
  вызова с таблицей. Все семь переведены в `TF("Роутер: {0}", model)`.
- **Один ключ означал два разных предмета** - «Не включать пароль в файл/QR» имел два разных
  английских текста в `ShareText` и в мастере. Сведены к одному; контекстный квалификатор здесь
  не понадобился.

### 8.2. Второй проход по LITE - то, что первый пропустил (2026-07-28, вечер)

Скриншот окна настроек на хинди показал в выпадающем списке **«Вверху слева»** по-русски. Проверка
сканером - **187 строк интерфейса LITE вообще не проходили через слой**. Хуже того, 27 из них не были
даже двуязычными: `Choice("topLeft", "Вверху слева")` не имел английского варианта, и этот файл
присутствует в теге `v26.7.23.1127` - то есть **выпущенная сборка показывала русский текст всем
пользователям** в восьми выпадающих списках современного окна настроек.

**Почему тест этого не поймал - метрика была не та.** `LocalizationParityTests` считал **чтения**
`Is_Russian_Language` и держал их под потолком 40. Но одна строка `Dim rus As Boolean = Is_Russian_Language`
в начале `Select Case` покрывает десятки строк: в `LocalizeOcrTab` - **44**. Счётчик показывал 38 из 40 -
зелено, - пока 187 строк оставались непереведёнными. Считать надо **строки**, а не чтения.

| | |
| --- | --- |
| Добавлено | **136 ключей × 12 языков ≈ 1 630 значений** в 3 таблицах (`.Menus`, `.OcrTab`, `.Choices`) |
| Закрыто | контекстные меню на медиа (23), вкладка OCR/перевод целиком (44), меню «»» (18), подсказки статуса (13), выпадающие списки расширенных настроек (27), загрузка рантаймов (6), подтверждения с подстановкой (7) |
| `OcrLanguageCatalog` | §2.8 выполнен: `NameEn`/`NameRu` → один `Name`-**эндоним** (`Deutsch`, `Ελληνικά`, `中文（简体）`). 33 языка × 13 интерфейсов = 429 строк, которых теперь не нужно; грек узнаёт «Ελληνικά» в любом интерфейсе |
| Helper-параметры | `JumpBy`/`JumpTo` (два аргумента Ru/En → один ключ), `Choice(value, text)` (переводит сам), `OptionalRuntimeManager` (цепочка `isRussian` из 8 сигнатур убрана) |
| Кнопка языка | подпись `Язык / Language` была двуязычной, пока языков было два; теперь просто «Язык интерфейса» - тот же ключ, что в компаньоне |

**Новый тест - `LocalizationCoverageTests`, в обоих наборах.** Каждый кириллический литерал в исходниках
должен либо стоять внутри вызова `T`/`TF`/`TC`, либо сам быть зарегистрированным ключом (массивы ключей и
аргументы helper'ов доходят до слоя на шаг позже). Остаток - явный список исключений с обоснованием:
`OcrLanguageCatalog` (эндонимы) и `OllamaTranslator` (русские слова, по которым **определяется**
непереведённый ответ модели - их сравнивают с текстом, а не показывают). Тест балансирует скобки, иначе
многострочный вызов считался бы нарушением.

**Ещё одна ловушка VB**, теперь китайская: `“` и `”` (U+201C/U+201D) компилятор принимает как ограничители
строки - ровно как немецкие `„…“`. Заменены на 「…」. Правило простое: **в литерале не должно быть ни одной
«умной» двойной кавычки**, на каком бы языке текст ни был.

## 9. Оценка объёма - честно

| Работа | Порядок величины |
| --- | --- |
| Ядро слоя + миграция + выбор языка (A1-A2) | небольшой, полностью проверяемый |
| Перенос 905 строк в слой (A3, форма записи) | механический, но самый долгий; половина - два файла (`Table_Form.ModernLayout.vb` 170 и `Companion/Forms/MainWindow.vb` 88) |
| Перевод 905 строк × 12 языков ≈ **10 900** значений | делается моделью пакетами по файлам; вычитка только RU/UK/EN |
| RTL в окне настроек (24 `FlowLayoutPanel` + 31 явная координата) | самый рискованный кусок вёрстки |
| 13 страниц сайта | одна страница-образец + 12 переводов её текста |
| Store CSV | ручной шаг в Partner Center (создать 11 листингов) обязателен и не автоматизируется |
| Скриншоты | скрипты - небольшой объём; просмотр 39 PNG глазами - обязателен |

Самое дорогое здесь - **не** количество языков, а то, что 905 строк надо сначала вынуть из 278 тернарников
и 4 блоков. Тринадцатый язык после этого стоит одной колонки.
