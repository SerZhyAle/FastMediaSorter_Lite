# Спецификация: классический зум/панорамирование при просмотре изображений (.NET 10)

Статус: план (не начато)
Дата: 2026-07-15, ревизия 1
Родитель: дополнение к эпику [SPECIFICATION_DOTNET10_MODERN_BUILD.md](done/SPECIFICATION_DOTNET10_MODERN_BUILD.md)

> Это дополнение к эпику современной сборки на .NET 10. Оно касается только
> подсистемы взаимодействия при просмотре **изображений и анимаций** (зум,
> панорама, реакция мыши и клавиатуры) - не декодеров и не видео. Реализуется в
> modern-сборке; в legacy x86-вьювере (см. раздел 1.1 эпика) можно оставить
> текущую механику как есть - legacy заморожен.

## 0. Что послужило триггером

Текущая механика зума/листания сложилась исторически и расходится с тем, как
ведут себя привычные просмотрщики (Windows «Фотографии», IrfanView, XnView,
FastStone). Владелец хочет в новой .NET 10-версии пересмотреть её в пользу
**классической модели**, при этом:

- **клики мыши по-прежнему листают** следующий/предыдущий файл (это ключевая
  привычка сортировщика - одной рукой на мыши прогонять папку);
- **ничего из оригинального функционала не должно сломаться** - все текущие
  жесты и хоткеи либо сохраняются, либо получают равноценную замену, а «старое»
  поведение колеса остаётся доступным как опция.

## 1. Текущая механика (as-is, для фиксации базовой линии)

Основной код: [src/Main_Form.MouseInput.vb](../../src/Main_Form.MouseInput.vb),
[src/Main_Form.KeyboardInput.vb](../../src/Main_Form.KeyboardInput.vb),
[src/Main_Form.UILayout.vb](../../src/Main_Form.UILayout.vb) (`SkipZoom`/`SyncMediaSurface`),
[src/HqPictureBox.vb](../../src/HqPictureBox.vb).

### 1.1 Модель состояния зума

Одно поле `zoom_Scale As Single` с тремя семантиками:

| Значение | Смысл | Как достигается |
|----------|-------|-----------------|
| `1.0F` | вписать в окно (fit), по умолчанию | `SkipZoom()` при загрузке/ресайзе |
| `0.0F` | нативные пиксели 1:1 | Shift+колесо |
| `>1` (и теоретически `<1`) | произвольный зум | Ctrl+колесо, множитель 1.1 / 0.9 |

`0.0F` - это **магический флаг** 1:1, а не «нулевой масштаб»; на него завязаны
проверки панорамы (`zoom_Scale = 0 OrElse zoom_Scale > 1`) и делегирования клика.
Множитель `0.9` при Ctrl+колесе может увести `zoom_Scale` ниже единицы без явного
нижнего порога.

### 1.2 Зум = физический ресайз контрола

Зум не трансформирует отрисовку - он **меняет геометрию самих PictureBox**
(`Picture_Box_1/2.Width/Height/Left/Top`), а `SizeMode` растягивает картинку
внутри. Оба бокса (это пара для бесфликерного свопа кадров) двигаются синхронно.
Курсор-центрированность считается вручную через относительную позицию мыши в
`panel_Media` ([Main_Form.MouseInput.vb:214-249](../../src/Main_Form.MouseInput.vb#L214-L249)).
Есть ручные защиты «не увести картинку за экран» (оставить 100 px видимыми).

### 1.3 Карта мыши (as-is)

| Жест | Действие |
|------|----------|
| Колесо вниз / вверх | **следующий / предыдущий файл** |
| Ctrl + колесо | зум in/out (курсор-центр), 1.1 / 0.9 |
| Shift + колесо | 1:1 нативный размер, по центру |
| Alt + колесо (и `MouseUse` с Alt) | сброс зума в fit (`SkipZoom`) |
| Левый клик (fit) | отложенный таймером → следующий файл; двойной → полноэкранный режим |
| Правый клик | предыдущий файл |
| Средний клик | переименовать файл |
| XButton1 / XButton2 | следующий / предыдущий |
| Shift + Лев/Прав клик | +10 / -10 файлов |
| Ctrl + Лев/Прав клик | +100 / -100 файлов |
| Alt + Лев/Прав клик | +1000 / -1000 файлов |
| Левый drag (когда `zoom_Scale = 0` или `>1`) | панорама (двигает боксы, троттлинг 16 мс, порог 5 px) |
| Клик по `lbl_Zoom` | сброс зума |

Двойной клик определяется вручную по `SystemInformation.DoubleClickTime`; чтобы
одиночный левый клик не «моргал» перед распознаванием двойного, он **откладывается
таймером** `pending_Single_Click_Timer` - отсюда лёгкая задержка листания левым
кликом в режиме fit ([Main_Form.MouseInput.vb:137-149](../../src/Main_Form.MouseInput.vb#L137-L149)).

### 1.4 Карта клавиатуры (as-is)

Навигация: `→ N Space PageDown Next BrowserForward` = следующий; `← P B Back
PageUp BrowserBack` = предыдущий; `↑`/`↓` = -10/+10; `Shift+PageUp/PageDown` =
-100/+100; `Home/H` первый, `End/E/L` последний. Плюс операции сортировки
(`Del`, `0..9`), поворот (`R`/`Shift+R`), OCR (`T`/`Shift+T`), полноэкран
(`F7`/`F11`), и т.д.

**Клавиатурного зума нет ни одного** - ни `+`/`-`, ни `Ctrl+0`, ни `Ctrl+1`.

## 2. Проблемы текущей модели

1. **Колесо листает, а не зумит.** Обратно привычке из всех массовых
   просмотрщиков; чтобы приблизить картинку, нужен неочевидный Ctrl+колесо.
2. **Зум через ресайз контрола** хрупок: завязан на `SyncMediaSurface`, пару
   боксов-свопа, перспективный фон и overlay'и; каждая правка рискует
   рассинхронизировать геометрию. Ручные «защиты от заезда за экран» - симптом.
3. **Магический `zoom_Scale = 0`** для 1:1 плодит спец-ветки и путает инварианты.
4. **Нет клавиатурного зума** (`+`/`-`/`Ctrl+0`/`Ctrl+1`) - обязательного для
   классической модели.
5. **Нет явных границ зума** и якорей масштаба (fit / 100% / fill); `0.9^n` уводит
   ниже fit без дна.
6. **Отложенный левый клик** добавляет задержку листанию в режиме fit.
7. **Панорама, drag-порог и делегирование клика** переплетены в одном
   `Pic_MouseMove`/`HandlePictureBoxMouseDown`, что усложняет правки.

## 3. Цель и принципы

- **Классическая модель зума**: колесо приближает/отдаляет картинку под курсором;
  явные якоря **Fit** (вписать) и **100%** (пиксель-в-пиксель); клавиатурный зум.
- **Клики остаются навигацией**: левый = следующий, правый = предыдущий - без
  изменений (это прямое требование владельца).
- **Не ломать оригинал**: каждый текущий жест либо сохраняется, либо получает
  равноценную замену; **старое поведение колеса (листание) остаётся доступным
  как опция** в настройках - это гарантия «оригинальный функционал не пострадал».
- Реализация - в modern (.NET 10). Legacy x86-вьювер не трогаем.

## 4. Предлагаемая модель взаимодействия

### 4.1 Единая модель масштаба

Ввести явную модель вместо тройной семантики `zoom_Scale`:

- `zoomMode ∈ { Fit, Free }`. **Fit** - вписать целиком в `panel_Media` (по
  умолчанию при каждой загрузке/ресайзе). **Free** - фиксированный масштаб,
  заданный пользователем.
- `zoomFactor As Double` - **абсолютный масштаб относительно нативных пикселей**
  (1.0 = 100% = 1:1). В режиме Fit фактический масштаб вычисляется из размеров;
  ярлык `lbl_Zoom` показывает процент (например «Fit 38 %», «100 %», «250 %»).
- **Шаг зума (дефолт, O-Z-7):** геометрический множитель **`1.25`** за нотку
  колеса / нажатие `NumPad +/-`; `Ctrl+колесо` в зум-режиме - множитель **`1.5`**
  (быстрее). Числа - параметры-константы, легко подкрутить.
- **Snap к якорям (дефолт, O-Z-6): включён.** При прокрутке через Fit или 100 %
  зум «прилипает» к якорю (порог ±3 %), чтобы легко попасть ровно в 100 % и в
  «вписать». Отключаемо константой, если помешает.
- **Границы зума (дефолт, O-Z-7):** `zoomMin = min(Fit, 5 %)` (не мельче 5 % и не
  мельче «вписать»), `zoomMax = 4000 %`. `0.0F`-флаг **упраздняется**.

### 4.2 Карта мыши (to-be)

**Решение владельца (2026-07-15):** по умолчанию колесо **листает файлы, как
сейчас** (14-летняя привычка сохраняется). «Классический» режим (колесо зумит)
доступен **опцией** (см. 4.4). В таблице ниже основная колонка - поведение по
умолчанию; в скобках - что даёт включённый опциональный зум-режим.

| Жест | По умолчанию (как привык владелец) | Опция «колесо зумит» |
|------|------------------------------------|----------------------|
| Колесо над изображением | **листание next/prev (как сейчас)** | зум in/out под курсором |
| Ctrl + колесо | зум in/out под курсором (как сейчас) | зум (быстрее, шаг ×2) |
| Shift + колесо | 100 % (1:1) под курсором (как сейчас) | 100 % (1:1) под курсором |
| Alt + колесо | сброс в Fit (как сейчас) | сброс в Fit |
| Колесо над **видео** | листание next/prev (VLC/WebBrowser не зумим) | листание |
| Левый клик (fit / не над зумленной областью) | следующий файл | следующий |
| Правый клик | предыдущий файл | предыдущий |
| Двойной левый клик | полноэкранный режим (без изменений) | полноэкран |
| Средний клик | переименовать (без изменений) | переименовать |
| XButton1 / XButton2 | next / prev (без изменений) | next / prev |
| Shift/Ctrl/Alt + Лев/Прав клик | ±10 / ±100 / ±1000 (без изменений) | то же |
| Левый drag когда `zoomFactor > fit` | панорама | панорама |
| Левый клик когда зумлено (без drag) | **не листает** (осмотр), как сейчас | не листает |

Ключевое: **по умолчанию мышь работает ровно как последние 14 лет** - ни один
жест не меняется. Зум-на-колесе - строго опт-ин.

### 4.3 Карта клавиатуры (to-be) - добавляемое

Навигация и сортировка - **без изменений**. **Решение владельца
(2026-07-15):** зум с клавиатуры вешаем **только на клавиши серого цифрового
блока (NumPad)** - они свободны и не трогают привычные хоткеи. Комбинации с
`Ctrl` (`Ctrl+0`/`Ctrl+1` и т.п.) **не используем** - они у владельца заняты.

| Клавиша | Действие |
|---------|----------|
| `NumPad +` (Add) | **приблизить от текущей позиции курсора мыши** |
| `NumPad -` (Subtract) | **отдалить от текущей позиции курсора мыши** |
| `NumPad /` (Divide) | **Fit (вписать)** |
| `NumPad *` (Multiply) | **100 % (1:1)** |

- «От текущей позиции курсора»: у клавиатурного события нет координат, поэтому
  якорь зума берётся из `Cursor.Position` → `panel_Media.PointToClient(...)`; если
  курсор вне медиа-области - зумим от центра панели.
- Конфликтов нет: `NumPad 0..9` заняты сортировкой (`PoMove`/`Del`), а
  `Add/Subtract/Divide/Multiply` - отдельные клавиши, сейчас ничем не заняты.
- **Стрелки не трогаем** - `←/→` листают, `↑/↓` = ±10 (как сейчас). Панорама с
  клавиатуры не вводится: достаточно drag мышью. См. O-Z-3.

### 4.4 Настройка «Действие колеса мыши»

Переключатель в окне настроек (`Table_Form`, вкладка «Просмотр» или «Видео и
качество»):

- **Листание (как раньше)** - **по умолчанию**: колесо листает файлы; зум
  остаётся на `Ctrl+колесо`, 1:1 на `Shift+колесо`, сброс на `Alt+колесо` - всё
  ровно как сейчас.
- **Зум** - опция: колесо приближает/отдаляет под курсором.

Хранить как флаг в реестре (`SZA\FastMediaSorter`, рядом с прочими viewer-опциями,
загрузка/сохранение в [Main_Form.Lifecycle.vb](../../src/Main_Form.Lifecycle.vb)).
Значение читается в единой точке обработки колеса. Дефолт = «Листание», поэтому
свежая установка/апгрейд ведёт себя идентично привычному поведению.

## 5. Модель рендеринга (внутренняя реализация)

**Дефолт (O-Z-1): переходим на viewport-трансформацию сразу (Фаза Ф-Z3).**
Отказываемся от зума через ресайз контролов в пользу **viewport-трансформации
при отрисовке**:

- Хранить `viewport`: `srcRect` (прямоугольник в координатах нативного
  изображения) и рисовать его в `destRect = panel_Media.ClientRectangle`
  (или в клиентскую область бокса) в `HqPictureBox.OnPaint` через
  `Graphics.DrawImage(img, destRect, srcRect, GraphicsUnit.Pixel)` с текущей
  интерполяцией (HQ bicubic уже ставится в `OnPaint`, см.
  [src/HqPictureBox.vb](../../src/HqPictureBox.vb)).
- Зум = сжать/растянуть `srcRect` вокруг точки под курсором; панорама = сдвиг
  `srcRect`; Fit/100 % = пересчёт `srcRect` из размеров изображения и панели.
- Боксы `Picture_Box_1/2` **остаются размером с панель всегда** (`SyncMediaSurface`
  больше не конкурирует с зумом); пропадают ручные «защиты от заезда за экран»,
  магический `zoom_Scale = 0`, рассинхрон геометрии.

Выгоды: единый источник правды (`viewport`), корректная совместная работа с
перспективным фоном и OCR-overlay (они уже рисуются в `Paint`; overlay-боксы OCR
пересчитываются той же трансформацией `image → screen`), отсутствие свопа
геометрии между `Picture_Box_1` и `Picture_Box_2`.

**Запасной путь (если viewport на Ф-Z3 окажется дорогим):** ограничиться
перепривязкой колеса и клавиатурным зумом поверх текущего ресайза контрола, а
viewport отложить. Основной план - всё же сразу viewport: modern-сборка и так
переписывает декодер/видео-швы (эпик, раздел 6), это лучший момент убрать
легаси-геометрию.

## 6. Поведение по типам контента

- **Статичное изображение**: полный зум/панорама/якоря по разделам 4-5.
- **Анимации (GIF, анимированный WEBP/APNG в modern-стеке)**: зум и панорама
  **обязаны работать так же**, как для статики. При viewport-модели каждый кадр
  анимации рисуется через ту же `srcRect→destRect` трансформацию. Учесть
  взаимодействие с текущим `gif_Restart_Timer`/покадровой отрисовкой
  ([Main_Form.GifPlayback.vb](../../src/Main_Form.GifPlayback.vb)) и с новым
  путём декодирования анимаций из .NET 10-стека (эпик, раздел 6.1). Требование:
  смена масштаба не перезапускает и не рвёт анимацию.
- **Видео (VLC / IE WebBrowser)**: **зум вне рамок** - поверхности видео не
  трансформируются нашим `Graphics`. Над видео колесо **листает** независимо от
  настройки 4.4; масштаб видео - функция плеера, не наша. (В modern видеодвижок
  единый - LibVLC, эпик 6.2; при желании zoom/crop VLC - отдельная будущая тема.)

## 7. Инварианты (что гарантированно не ломаем)

1. Левый клик = следующий, правый = предыдущий (в режиме fit).
2. Двойной левый клик = переключение полноэкранного режима.
3. Средний клик = переименование; XButton1/2 = next/prev.
4. Shift/Ctrl/Alt + клик = джампы ±10 / ±100 / ±1000.
5. Вся клавиатурная навигация и сортировка (`Del`, `0..9`, `Home/End`, стрелки,
   `PageUp/Down`, `R/Shift+R`, `T/Shift+T`, `F5/F7/F11`, …) - без изменений.
6. Панорама drag'ом левой кнопкой в зумленном состоянии сохраняется.
7. «Колесо листает» - **поведение по умолчанию** (раздел 4.4); зум на колесе -
   опция. Умолчание = привычная мышь без изменений.
8. Fit пересчитывается при загрузке файла и при ресайзе окна/смене
   полноэкранного режима (как сейчас в `ISizeChanged`/`SkipZoom`).
9. Перспективный фон и OCR-overlay продолжают корректно совмещаться с картинкой
   при любом масштабе/сдвиге.

## 9. План работ по фазам

- **Ф-Z0. Базовая линия и тесты.** Зафиксировать текущее поведение (этот раздел
  1), собрать ручной чек-лист жестов.
- **Ф-Z1. Единая точка колеса + настройка.** Ввести флаг «действие колеса»,
  развести зум/листание; поведение зума пока на текущем ресайзе контрола.
- **Ф-Z2. Клавиатурный зум.** `+`/`-`/`Ctrl+0`/`Ctrl+1`; ярлык в процентах;
  границы и snap к Fit/100 %.
- **Ф-Z3. Viewport-рендер.** Перевести зум/панораму на `srcRect→destRect`,
  убрать `zoom_Scale = 0`, свопы геометрии и off-screen-защиты; свести OCR-overlay
  и перспективу к одной трансформации.

## 10. Открытые вопросы - все решены (дефолты, 2026-07-15)

Решения владельца:

- **O-Z-2. РЕШЕНО.** Дефолт действия колеса = **листание (как сейчас)**; зум на
  колесе - опция. Мышь по умолчанию не меняется вообще.
- **O-Z-3. РЕШЕНО.** Панорама с клавиатуры не вводится - только drag мышью;

- **O-Z-4. РЕШЕНО.** Клавиатурный зум - только NumPad: `+`/`-` = зум от курсора,

- **O-Z-5. РЕШЕНО.** Двойной клик = **полноэкранный режим** (оставляем как есть;
  toggle 100 %/Fit не берём).

Дефолты по внутренним вопросам (не влияют на привычное управление; можно
пересмотреть в ходе реализации):

## 11. Риски

- **Смена привычки колеса.** Часть пользователей привыкла листать колесом;
  снимается настройкой 4.4 (старое поведение остаётся) и дефолтом, который можно
  выбрать (O-Z-2).
- **Совмещение с перспективным фоном и OCR-overlay.** При viewport-модели все
  трое должны брать единую трансформацию `image→screen`; иначе overlay «уедет».
  Нивелируется тем, что это единый источник правды (плюс к текущему разнобою).
- **Анимации в новом декодере.** Покадровая отрисовка через `srcRect→destRect`
  должна не ронять FPS и не перезапускать цикл при зуме (Ф-Z4).
- **Дрейф с legacy.** В legacy-вьювере механика остаётся старой; общий код
  прячется за `#If NET` там, где расходится (как в эпике, раздел 3).
