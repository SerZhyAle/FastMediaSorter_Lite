## 0. Цель

Открытие папки не должно вешать окно, а список - врать о содержимом. Сегодня
`GetFiles` (энумерация + метаданные + сортировка) выполняется синхронно на
UI-потоке при каждом открытии папки, смене сортировки и старте слайдшоу с первого
файла; при восстановлении последней папки каталог обходится **дважды**; файлы,
добавленные снаружи, невидимы до ручного перечитывания.

| Ид | Ценность | Что |
|---|---|---|
| У-03 | ★★ | Скан в фоне с отменой + убрать двойную энумерацию при старте |
| У-04 | ★★ | `FileSystemWatcher`: живой список |
| У-12 | ★ | Явное состояние вместо эвристики «index = 0 → перечитать» |
| У-05 | ★ | Сортировать и папки >100k (порог - наследие слабого железа) |

## 1. У-03: скан в фоне

### 1.1 Убрать предварительный обход ([Lifecycle.vb:508-519](../../src/Main_Form.Lifecycle.vb))

При восстановлении последней папки UI-поток сначала перечисляет её целиком
(нефильтрованный `Count` - **только** ради проверки сохранённого индекса, причём
сравнивает медиа-индекс с числом всех файлов), а затем `GetFiles` обходит её второй
раз с фильтром и сортировкой. Для сетевой шары это два полных обхода до первого кадра.

Проверка не нужна: клампы в `Mode_Files`/`UpdateCurrentFileAndDisplay` и так приводят
индекс в границы, а `LoadFiles` сам вернёт False на пустой/недоступной папке. Оставить:

```vb
Current_Folder_Path = GetSetting(App_name, Second_App_Name, "ImageFolder", "")
If Current_Folder_Path <> "" Then
    Integer.TryParse(GetSetting(App_name, Second_App_Name, "LastCounter"), current_File_Index)
    ReadShowMediaFile(Mode_Files)   ' сам перечитает, отфильтрует, отсортирует и зажмёт индекс
End If
```
(Правка безопасна и для net48 - это чистое удаление лишнего обхода; шов не нужен.)

### 1.2 `GetFiles` - в `Task.Run` с отменой

```vb
#If Not NETFRAMEWORK Then
''' <summary>Скан каталога вне UI-потока. Токен привязан к папке: пользователь
''' сменил папку - предыдущий скан отменяется и его результат отбрасывается
''' (раньше 100k файлов на SMB держали окно в "Не отвечает" секундами, а надпись
''' "чтение каталога.. ждите!" даже не успевала перерисоваться).</summary>
Private Async Function GetFilesAsync(folder As String, token As CancellationToken) As Task(Of Object)
    Return Await Task.Run(Function() ScanFolderCore(folder, token), token)
End Function
#End If
```

- `ScanFolderCore` - нынешнее тело `GetFiles`, но: папка приходит **параметром**
  (не из глобала), внутри цикла - `token.ThrowIfCancellationRequested()`, статусы
  через `IProgress(Of String)`.
- Метаданные (`Length`/`LastWriteTime`) запрашивать **только** для активных режимов
  сортировки: для `abc`/`xyz`/`<0123`/`>3210` они не нужны, а это лишний stat на
  каждый файл (на SMB - основная цена скана).
- `LoadFiles`/`LoadFilesForExternalInput`/`LoadFilesForRandomOrSlideshow` в
  modern-ветке становятся `Async Function` и `Await`-ят скан; `ReadShowMediaFile`
  соответственно - тоже (сигнатура за швом; net48 остаётся синхронным).
- На время скана блокируются только операции над списком, а не весь UI: статус
  «чтение каталога..», окно живое, Esc отменяет.

## 2. У-12: явное состояние загрузки

[MediaLoading.vb:289](../../src/Main_Form.MediaLoading.vb): `LoadFilesForRandomOrSlideshow`
использует `current_File_Index = 0` как признак «список ещё не загружен» - поэтому R
или старт слайдшоу на первом файле папки запускают полный рескан **уже загруженного**
списка (на сетевой папке - многосекундное «чтение каталога.. ждите!»).

```vb
''' <summary>Список файлов актуален для Current_Folder_Path. Раньше эту роль играл
''' current_File_Index = 0 - магия, из-за которой R на первом файле перечитывал
''' весь каталог (У-12).</summary>
Private is_Folder_List_Loaded As Boolean
Private loaded_Folder_Path As String
```
Перечитывать, только если `Not is_Folder_List_Loaded` или
`loaded_Folder_Path <> Current_Folder_Path` (плюс инвалидация из У-04 при
изменениях снаружи). Сбрасывать при смене папки и в `Mode_FolderAndFile`.

## 3. У-04: `FileSystemWatcher`

Список - разовый снимок: удалённые снаружи файлы отсеиваются реактивно по одному
(`File.Exists` при показе), а **добавленные** не появляются вообще, пока пользователь
не нажмёт «Перечитать». Типовой сценарий сортировщика - смотреть папку загрузок,
куда файлы докачиваются прямо сейчас.

```vb
#If Not NETFRAMEWORK Then
Private WithEvents folder_Watcher As FileSystemWatcher
Private WithEvents watcher_Debounce_Timer As New Timer() With {.Interval = 500}
#End If
```

- Ставится на `Current_Folder_Path` (без подпапок), `NotifyFilter = FileName`,
  события `Created`/`Deleted`/`Renamed`; фильтрация по `all_Supported_Extensions`.
- События приходят **не с UI-потока** → складывать в потокобезопасную очередь,
  `BeginInvoke` дебаунс-таймера, применять пачкой на UI.
- Применение инкрементальное, с сохранением текущей сортировки: вставка через
  `BinarySearch` с активным компаратором (для `rnd` - в конец), удаление - через
  `RemoveCurrentFileFromList`-подобный хелпер по значению; `current_File_Index`
  корректируется при вставке/удалении **до** текущей позиции - показанный файл не
  должен «уезжать» под пользователем.
- Файл, который ещё пишется (докачка), нельзя показывать: `Created` только добавляет
  запись в список; попытка показа сама разберётся (ветка «занят» уже есть).
- Watcher останавливать при смене папки и в `FormClosing`; на сетевых путях он
  ненадёжен - при `Error`-событии (переполнение буфера, обрыв) молча деградировать
  к нынешнему поведению (разовый снимок) и один раз написать в лог.

## 4. У-05: сортировка больших папок

[FileScanning.vb:301, 332-336](../../src/Main_Form.FileScanning.vb): при
`>= max_Number_Of_Files_For_List` (100 000) список отдаётся массивом **в порядке
файловой системы** - выбранная сортировка молча игнорируется, комбобокс врёт.

Порог - наследие слабого железа: на .NET 10 `OrderBy` по 100k строк - десятки
миллисекунд, метаданные уже прочитаны на этапе энумерации, а сам скан после У-03
не блокирует UI.

- В modern: убрать порог (или поднять до защитного максимума ~2 000 000) и
  сортировать всегда; ветка `is_Files_Array_Active` остаётся как есть - меняется
  только то, что массив тоже сортируется.
- Если ветка «без сортировки» где-то сохраняется - показывать это явно (например,
  `cmbox_Sort` с пометкой «(без сортировки)»), а не молча.
- net48 (x86, 32-битный процесс, ограниченная память) порог **сохраняет**.

## 5. Приёмка

1. **Открытие большой папки**: 100k файлов на SMB → выбрать папку → окно остаётся
   отзывчивым (можно двигать, статус «чтение каталога..»), первый файл появляется
   по готовности; Esc во время скана - отмена без зависания.
2. **Смена папки на ходу**: начать открытие огромной папки, тут же выбрать другую →
   показана вторая; результат первого скана не «всплывает» поверх.
3. **Старт**: восстановление последней сетевой папки - **один** обход каталога
   (проверить по логу: одно `w1095: GetFiles..`), время до первого кадра ~вдвое меньше.
4. **R на первом файле**: встать на первый файл сетевой папки, нажать R несколько
   раз → нет «чтение каталога.. ждите!» (рескана нет), случайные файлы показываются
   мгновенно.
5. **Живой список**: смотреть папку, скопировать в неё снаружи 3 новых jpg → в
   течение ~1 с счётчик «N из M» вырос на 3, файлы встали на свои места по текущей
   сортировке, показанный файл не сменился; удалить снаружи файл, который **не**
   показан → счётчик уменьшился, позиция сохранилась.
6. **Докачка**: начать копировать в папку большой файл → он появляется в списке;
   листнуть на него до конца копирования → «Файл занят, ждём разблокировки», по
   завершении показывается.
7. **Сортировка 100k+**: папка из 120k файлов, сортировка «abc» → порядок
   действительно алфавитный (в x86 - прежнее поведение с порядком ФС).
8. **net48**: скан по-прежнему синхронный, поведение не изменилось.

## 6. Риски

- **Заразность `async`**: `LoadFiles*` → `ReadShowMediaFile` → ~30 вызывающих.
  Держать шов узким: асинхронной делать только загрузку **списка**, а не весь
  `ReadShowMediaFile`; при необходимости - `Async Sub`-обёртка с `media_Generation`
  (С4) для проверки актуальности после `Await`.
- Watcher на сетевой папке шумит и переполняется - обязательна деградация по
  `Error`-событию (см. 3) и дебаунс.
- Инкрементальная вставка обязана уважать активный компаратор, включая
  `NaturalFilenameComparer` и `UseNls`-порядок (`abc`/`xyz`) - иначе список
  «расползётся» относительно пересканирования. Приёмка 5 проверяет.
- Снятие порога 100k в modern увеличивает пик памяти на большом каталоге - замерить
  на 500k файлов перед снятием.
