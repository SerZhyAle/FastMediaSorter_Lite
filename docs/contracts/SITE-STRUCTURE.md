The product site is a landing, an install-trust page, an edition page (`server.html`), nine task guides, a
subject index (`topics.html`), a glossary and a privacy page, in 13 landing and trust locales and English,
Russian and Ukrainian in-page for the guides, the reference pages, the edition page and the privacy page. This pointer says only what the repository must do to stay conformant.

## What this repository must do

1. **Keep the tier and the page set honest.** The adoption row declares tier guide; a page type the tier
   requires and the site lacks is a dated exception, not a silent absence. Portal-only rules (4-7, 12-14) are
   not bound at this tier. The not-found page (rules 2 and 15) is `404.html`, generated by
   `tools/Build-SitePages.ps1` and held by its `-Check`; the declared release-notes page is the GitHub Releases
   address (decision and forwarder policy: [docs/guides/SITE_ADDRESSES.md](../guides/SITE_ADDRESSES.md)).
2. **Keep every public page reachable from the landing in three steps** (rule 3). `tools/Build-SitePages.ps1`
   writes the sitemap; a new root `*.html` joins it automatically.
3. **Keep a published address meaning what it meant** (rule 8) and, when a page moves, leave a forwarder. The
   list of addresses held outside the site (the programs, the listings, the READMEs) is
   `tools/site-addresses.jsonl`, resolved against the page set by `tools/Test-SiteAddresses.ps1` in every
   test run (ticket 150; the list, its fields and the locale-sibling form per page group are in
   [docs/guides/SITE_ADDRESSES.md](../guides/SITE_ADDRESSES.md)).
4. **Offer a language control only the languages a page exists in** (rule 9), and publish each page group in
   its declared locale set (rule 10); the core three (en, ru, uk) are the floor and the gaps against it are
   recorded exceptions.
5. **Never let a missing translation become a dead end** (rule 11): a program that builds a locale address
   (`src/Support/SitePages.vb`, `TrustPageUrl`) falls back to the primary language and says so.
6. **Hold section 8 (0.2).** The variants of a page are linked siblings (A, rules 9 and 10); the visitor's language is
   kept by every internal link (B, rule 6); a program's fallback is the English page (C, rule 11); from the release
   that first carries a page its address and anchors do not change (D, rule 8); every setup, start or repair screen of
   a function that has a page links it (E); and nothing is marked "not available yet" (F). Not read here: A and C
   against the program's resolver, and D against a record of released addresses.
7. **Carry the Support page and the release history (the 2026-10-17 amendment, 0.3).** `support.html` is the Support
   page; the release history is rendered from the versioned records of shipped releases (`CHANGELOG.md`, never
   `[Unreleased]`) by `tools/Build-SitePages.ps1`. A footer link to the Support page from every page, and a declared
   locale set for the pages that name none, are still owed.
