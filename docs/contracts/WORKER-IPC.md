## What this repository must do to stay conformant

- The pipe name and the one-request-per-connection shape are frozen. Never change either without the
  worker changing in the same breath, and never spawn a second worker: the pipe is a machine-wide
  singleton on purpose.
- Bound every call. An unbounded blocking read against a worker that accepts the pipe and then says
  nothing leaks a handle per poll tick.
- On a request, **absent means unchanged**: an unset knob is omitted from the JSON, never sent as `0` or
  `false`.
- Any additive request field needs a **capability field in the status**, the way `port` has
  `portSupported`. Without one, a field an older worker dropped cannot be told from one it applied.
- An additive response field that is absent means *no data yet* - never an error, and never a zero shown
  to the user as a measurement. The 0.10 status additions `capabilities` and `mode` are bound for disk discovery; absent capability means unavailable.
- **Read `ok`.** A transport that succeeded says nothing about whether the request did. Every flow acts
  on the verdict: a refused `SetNetworkPolicy` while LAN only is on is a persistent warning, a refused
  folder list is not followed by a start, a refused counter reset leaves the counters alone and says so.
- **A version refusal is shown, never swallowed.** It is its own exception type
  (`WorkerVersionRefusedException`), turned into a typed result by the one exchange point
  (`WorkerProcess.Exchange`) and never read as "nobody answered".
- **Never spawn after an answer.** A worker that answered - with a refusal, with `ok=false`, with
  anything - is running and owns the pipe.
- The request bytes this host sends are generated by the product's own serializer into
  `tests/Companion.Tests/TestData/worker-ipc/requests/` and pinned byte for byte - the host half of the
  contract's section 7 artifact. Regenerate them, never edit them.

## 0.10 and the disk-control extension

Section 9 (0.10, 2026-10-02) carries `DISK-SHARE`'s schema-2 disk control requests in the same flat
`type`/`ok` envelope; schema 1 stays supported for the existing request types, and a worker echoes the
request's schema. This host now adopts the six disk request types through `DiskSharing`: the product serializer chooses
schema 2 for those requests and schema 1 for every legacy request. Disk responses are bounded and checked
against schema 2; the legacy reader still refuses a schema-2 answer. Root ownership is retained, and only
FMS-owned folders may reach `SetSharedFolders`. Removing the last FMS folder sends that scoped update
without a separate global stop; the worker applies its selection lifecycle and retains disk roots.

Ticket 114, 2026-10-04: request fixtures, including both autostart and share directions, are generated by
the product serializer. The host tests cover schema isolation, capability discovery, credential cleanup,
response limits, owner isolation and a real local Windows drive alias. Native mount, reboot and installed
upgrade evidence remain open; a compatible FileDO bundle and an administrator-capable host are prerequisites.

Ticket 035 (2026-09-24) closed the four host-side findings of 2026-09-23 - the refusal swallowed by every
caller, `ok` read nowhere, `port:0` sent for an unset knob, `portSupported` unused - and filed what the
host depends on beyond the pipe as proposals in the catalog: the exchange vectors, the `reachability` and
`stats` sub-fields, the excluded-range marker and the worker's launch surface. All four **still await the
owner**; the last is also what `SHARE-SESSION`'s 1.1 clarification references.

The response `schemaVersion` is compared since ticket 025 section 9: `WorkerIpc.EnsureUnderstood` refuses
a response whose version is above the client's own, with a message that names both halves and tells the
user to update the app. Refused upwards only, deliberately: an absent version on a RESPONSE would be a
worker older than the field, and refusing that would break the upgrade path the field exists to protect.

What keeps the contract below 1.0 is not ours: a recorded exchange per request type - the conformance
artifact section 7 asks for - can only be produced where the server half lives, the worker's repository,
whose exception for it runs until 2026-12-31.
