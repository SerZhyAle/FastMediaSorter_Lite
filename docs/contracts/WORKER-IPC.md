## What this repository must do to stay conformant

- The pipe name and the one-request-per-connection shape are frozen. Never change either without the
  worker changing in the same breath, and never spawn a second worker: the pipe is a machine-wide
  singleton on purpose.
- Bound every call. An unbounded blocking read against a worker that accepts the pipe and then says
  nothing leaks a handle per poll tick.
- On a request, **absent means unchanged**: an unset knob is omitted from the JSON, never sent as `0` or
  `false`.
- Any additive request field needs a **capability field in the status**, the way `port` has
  `portSupported`. Without one, a field an older worker dropped cannot be told from one it applied.
- An additive response field that is absent means *no data yet* - never an error, and never a zero shown
  to the user as a measurement.
- **Read `ok`.** A transport that succeeded says nothing about whether the request did. Every flow acts
  on the verdict: a refused `SetNetworkPolicy` while LAN only is on is a persistent warning, a refused
  folder list is not followed by a start, a refused counter reset leaves the counters alone and says so.
- **A version refusal is shown, never swallowed.** It is its own exception type
  (`WorkerVersionRefusedException`), turned into a typed result by the one exchange point
  (`WorkerProcess.Exchange`) and never read as "nobody answered".
- **Never spawn after an answer.** A worker that answered - with a refusal, with `ok=false`, with
  anything - is running and owns the pipe.
- The request bytes this host sends are generated by the product's own serializer into
  `tests/Companion.Tests/TestData/worker-ipc/requests/` and pinned byte for byte - the host half of the
  contract's section 7 artifact. Regenerate them, never edit them.

Ticket 035 (2026-09-24) closed the four host-side findings of 2026-09-23 - the refusal swallowed by every
caller, `ok` read nowhere, `port:0` sent for an unset knob, `portSupported` unused - and filed what the
host depends on beyond the pipe as proposals in the catalog: the exchange vectors, the `reachability` and
`stats` sub-fields, the excluded-range marker and the worker's launch surface.

The one deviation this repository carried - the response's `schemaVersion` deserialized and never
compared - was **closed on 2026-09-22** by ticket 025 section 9. `WorkerIpc.EnsureUnderstood` refuses a
response whose version is above the client's own, with a message that names both halves and tells the user
to update the app; those words belong to the end that faces the user, which is this one. Refused upwards
only, deliberately: an absent version on a RESPONSE would be a worker older than the field, and refusing
that would break the upgrade path the field exists to protect. The contract stays at 0.9 for a reason that
is not ours - it has no conformance artifact, and that belongs to the worker's repository.
