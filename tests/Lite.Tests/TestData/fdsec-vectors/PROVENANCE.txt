FDSEC conformance vectors - vendored artifacts, not a vendored contract
=======================================================================

What this folder is
-------------------
The committed conformance vectors of the FDSEC-FORMAT contract, section 16, copied here
so that FdSecConformanceTests can run for anyone who clones this repository. A test that
depends on a drive letter cannot run for anybody else, which is why these three files
travel with the tests.

What this folder is NOT
-----------------------
A copy of a contract. The two documents - FDSEC-FORMAT and FDSEC-BEHAVIOUR - stay in the
shared catalog and are CITED, never duplicated (see docs/contracts/FDSEC.md, and
CLAUDE.md's first line for where the catalog lives). Copying an artifact so a test can
run is a different act from copying a document so a repository can disagree with it.

Digests
-------
The test asserts these before it trusts a byte, so a vector file that changed under us
fails loudly instead of quietly redefining what "conformant" means. Re-running the
catalog's generator is a deliberate act and updates this file with it.

1.1 added two cases to vectors.json and changed neither container: root_empty_credential
(the empty credential's root under the empty container's salt) and containers.multi, a
three-chunk original published as layout fields rather than as a file - the test
assembles it from those fields and checks the result against blake2b256_of_file.

One value the vectors do not carry
----------------------------------
vectors.json publishes root_fast_branch but not the credential it was derived from - the
generator holds that string. It is recovered and pinned in FdSecConformanceTests
(FastBranchCredential), verified against the published root under the empty container's
salt, so the fast branch is proven rather than assumed.
