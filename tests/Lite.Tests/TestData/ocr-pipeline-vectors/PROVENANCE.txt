OCR-PIPELINE 1.7 A and 1.8 A/B shared cases - vendored artifacts, not a vendored contract
=========================================================================================

What this folder is
-------------------
The two shared fixtures the reference implementation of OCR-PIPELINE reads in BOTH of its editions
(Go desktop, JavaScript extension) to hold the two rules this product ported on 2026-10-13
(ticket 183): the line split's tall-word cut (amendment 1.7 A) and the CJK word and line join
(amendment 1.8 A and B). They are copied here so that OcrPipelineVectorTests can run for anyone who
clones this repository - a test that depends on a sibling checkout or a drive letter runs for nobody
else.

What this folder is NOT
-----------------------
A copy of a contract. OCR-PIPELINE stays in the shared catalog and is CITED, never duplicated (see
docs/contracts/OCR-PIPELINE.md and the first line of CLAUDE.md for where the catalog lives). The
catalog itself ships no vector for 1.7 or 1.8: the contract names these two files as its pins
("Pinned by the shared fixture tests/testdata/ocr_cjk_join_cases.json", and the split cases of
ocr_balloon_stitch_cases.json for 1.7 A), and they live in the reference implementation's
repository. This product does not own either rule: a case that disagrees with them is a question for
the contract's owner (doc-html-translate), never a local edit of these files.

Digest
------
The test asserts these before it trusts a byte, so a case file that changed under us fails loudly
instead of quietly redefining what "conformant" means. Re-taking an artifact is a deliberate act and
updates this file with it. The bytes are the reference's own (LF), which is why .gitattributes marks
this folder -text.
