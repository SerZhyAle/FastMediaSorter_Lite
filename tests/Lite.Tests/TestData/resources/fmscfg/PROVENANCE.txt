The snapshot moved from FMSCFG 2.1 (read 2026-10-02, when these fixtures were first vendored) to 2.4. The
amendments 2.2 (parser pinned by role, empty password = not carried), 2.3 (accessNote language) and 2.4 (the
`rendezvousTunnel` access-path kind and its producer duty) leave `schemaVersion` and both canonical vectors
unchanged; this consumer does less than 2.4 allows (it skips the kind, it never dials it) and nothing wrong.
SHARE-SESSION 1.1 only restates what ends a share's identity; the client rules 6-10 the reconnect policy follows
are unchanged.

Verification on 2026-10-07: the two json code fences of CONFIG_FORMAT.md 2.4 were extracted by script (UTF-8, no
BOM, no trailing newline) and compared with canonical-v1.fmscfg / canonical-v2.fmscfg as bytes - identical
(447 and 760 bytes, digests below). To repeat: match the fence body with the pattern (?s)```json\r?\n(.*?)\r?\n```
against the catalog document, hash each group, and compare with the two canonical lines in the SHA-256 list.

Android response provenance (kept apart from the catalog): docs/specifications/101_RESPONSE_FMS_ANDROID_CONTRACT_ALIGNMENT.md,
dated 2026-10-01, a static read of the Android working tree; nothing was run on a device. SHA-256 of that file as
used by this snapshot: 67a56269a96846688e7cde1ec860f42758c71d41d695172e0cabc00d8c8d38d5. The catalog registry's own FMSCFG row for the Android app (2.4, 2026-10-07) is a
separate statement by its owner and is not copied here. Android's answers inform implementation choices; they
authorise no relaxed host-key check, no SMB wire field and no change to the canonical vectors.

Files (every file in this folder is listed in MANIFEST.txt, which says where it came from, whether it is meant to
be valid and what the reader must answer; FmsFixtureCorpusTests holds both directions)
-------------------------------------------------------------------------------------

canonical-v1.fmscfg, canonical-v2.fmscfg
  The two canonical vectors of the FMSCFG contract (catalog: config-interchange/CONFIG_FORMAT.md). Extracted
  VERBATIM from the contract's own code fences by script, byte for byte, no trailing newline. They are the shared
  bytes the parser is pinned to; they must never be regenerated from this repository's serializer.

android-export-synthetic.fmscfg, companion-export-synthetic.fmscfg
  SYNTHETIC. Written by hand to the SHAPE the Android response 101 section 11 describes (one root, one lan path,
  schemaVersion 2, readOnly omitted, slideshowInterval written, password and fingerprint empty) and the Share
  Manager's own producer (readOnly written on every root, a destination with readOnly:true and isDestination:true,
  an ipv6 path, an accessNote). Dummy credentials and documentation addresses (RFC 5737 / 3849) only. They are not
  captures from a named build; a live Android export remains a manual acceptance item (101 section 5 item 7).

canonical-v2.qr.txt, android-export-synthetic.qr.txt
  The compressed QR transport (FMSCFG1: + base64(gzip(json))) of the two files named in their stems, made on
  2026-10-07 with .NET GZipStream (optimal level). The bytes are fixed here; the tests do not regenerate them.

tunnel-path-synthetic.fmscfg
  SYNTHETIC, from the 2.4 amendment's table: lan, portforward and a last `rendezvousTunnel` path with a valid
  host/port and a shareId of 22 base64url characters. The reader skips the kind without dialling it.

pin-locked-mixed-synthetic.fmscfg
  SYNTHETIC. One open root and one root with a non-empty accessPin: the file reads, the locked root is refused,
  and the mixed file cannot commit whole (Q100-1 interim: whole-file refusal, nothing imports unlocked).

invalid-*.fmscfg, invalid-not-gzip.qr.txt
  SYNTHETIC negatives, one defect each: a future schemaVersion, a protocol other than sftp, a malformed non-empty
  fingerprint, a repeated security property, a traversal virtualPath, a port above 65535, an empty roots array,
  a QR body that is not gzip. The expected typed result of each is in MANIFEST.txt.

No file here holds a live password or PIN or the endpoint of a reachable user: the test
A_fixture_carries_only_dummy_secrets_and_addresses_nobody_owns checks it.
