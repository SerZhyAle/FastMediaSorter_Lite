WORKER-IPC exchange vectors - the host half of section 10 item A
================================================================

Layout     : vectors/<case>/{request.json, response.json, expect.json}, as the catalog's.
             This file lists the SHA-256 of every file present and the command that made each half.

request.json  - generated, never hand-edited: the exact byte sequence the Share Manager's own
                serializer (WorkerIpc.SerializeRequest) writes to the pipe for that request, as the
                product builds it. No trailing newline: the pipe carries none.
                Non-ASCII is escaped as \uXXXX with upper-case hex; an unset knob is absent.
expect.json   - generated by the same test, only where the contract text alone fixes the conclusion
                (higher-schema, unknown-type, status-older-worker, and whether the server is up in
                status-running / status-down). {"refused":bool,"ok":bool,"running":bool|null,
                "fields":{..}}; in "fields" null means the host must read the member as absent.
                For every other case it carries values of the recorded response and is owed with it.
response.json - NOT PRESENT. Owed by the worker's harness (the only implementation that produces a
                response nobody hand-wrote); status-older-worker and higher-schema need a switch in
                that harness that answers as an older or a newer build. The command is the worker
                owner's to name and goes on a line here when the files arrive.
