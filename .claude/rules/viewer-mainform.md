# Viewer core: Main_Form partials, single instance, zoom, perspective, file I/O

> Area rules for the paths above (auto-loaded). Index and the always-on rules: CLAUDE.md.

**Main_Form** is one logical class spread over `Main_Form.*.vb` partials, one per concern: edit the file matching the concern, not just the main one, and never quote a partial count (`ls src/Main_Form*.vb | grep -v Designer`).
- **[Main_Form.vb](../../src/Main_Form.vb)** - the decomposed shell (`SPECIFICATION_MAIN_FORM_DECOMPOSITION.md`, local specification). **First-run UI language follows the Windows display language** (`Localization.DefaultCode()`: that language when this build is translated into it, otherwise English - never Russian, which is only the table's source language); once the user picks one, the saved `UiLanguage` ISO code wins. Hosts the `COPYDATASTRUCT` declaration and the `ProcessArgument()` entry point used for cross-instance forwarding (see Application_Events).
- **[Main_Form.VideoPlayer.vb](../../src/Main_Form.VideoPlayer.vb)** - **Modern = LibVLC only**: the IE WebBrowser is never instantiated (the Designer's `AllowWebBrowserDrop` line was removed because on .NET that setter *alone* creates the ActiveX in the constructor, and every `Web_Browser.DocumentText` touch is behind `#If NETFRAMEWORK`); [Main_Form.MediaLoading.vb](../../src/Main_Form.MediaLoading.vb) sends video straight to `PlayVideoWithVlcAsync`. **net48** keeps `LoadVideoInWebBrowser` (H.264) + the LibVLC fallback. Modern calls `StopVlcPlayback()` before move/delete file ops - VLC locks the playing file, where net48 released it by blanking the WebBrowser.
- **[Main_Form.PerspectiveHalo.vb](../../src/Main_Form.PerspectiveHalo.vb)** - whole-file `#If Not NETFRAMEWORK`: "dynamic perspective", a sub-option chain under `Is_Pespective`. `Is_Dynamic_Perspective` (registry `DynamicPerspective`, off by default) fades the finished bars from `Draw_Perspective` towards `Me.BackColor` with distance from the photo - a **permanent** property of the frame, not an intro. `Is_Animated_Perspective` (`AnimatedPerspective`, on by default; its parent is off until switched on by hand) decides whether a new photo *grows* that halo out from the photo edge. `Halo_Animation_Speed` (`AnimatedPerspectiveSpeed` = `slow`/`medium`/`fast`, default `medium`) is snapshotted into `halo_Running_Duration_Ms` when a growth starts, so a change lands on the next photo instead of jolting a running animation. Invariants:
  - One code path does both: at progress `p` the ramp spans `p * barWidth` out from the photo, so `p = 1` **is** the resting halo (drawing instantly = entering at `p = 1`) and the growing front never steps against the background.
  - `halo_Underlay` (the frame on screen when the growth started, taken over from the picture box, not disposed) is drawn at alpha `1 - eased`. **It fades with TIME, never with distance**: at `eased = 1` it draws nothing, which keeps the resting frame pixel-identical to the pre-underlay one (verify by comparison, not by eye); fading by distance leaves the old frame in the bar and paints constant-alpha bands.
  - Frames cannot be accumulated (a grown ramp gives a pixel *less* background than the frame before): each is recomposed from the kept bars bitmap.
  - `Draw_Perspective(animate)` only reports "a new photo asked" ([.MediaLoading.vb](../../src/Main_Form.MediaLoading.vb), and the first image via `Main_Form_Shown`; resize/zoom never). Whether that grows is the halo layer's call; `perspective_Animate_Pending` carries the intent across the throttle's trailing timer.
- **[Main_Form.OcrOverlay.vb](../../src/Main_Form.OcrOverlay.vb)** also hosts `PaintInfoOverlay()` - the optional top-left HUD (file name + `N/total`) drawn in the PictureBox `Paint` handler when `Is_Show_Info_Overlay` is on, never baked into the bitmap.
- **[Main_Form.FileAssociation.vb](../../src/Main_Form.FileAssociation.vb)** - associations are written per-user to `HKCU\Software\Classes` (no admin rights), then `SHChangeNotify`.
- **[Main_Form.DragDrop.vb](../../src/Main_Form.DragDrop.vb)** - a media file can be dropped on every **media surface** (picture boxes, `panel_Media`, help label, video WebBrowser, LibVLC view), not just the form. The OLE drop registration does NOT bubble to the parent, so a child without its own shows the "no-drop" cursor: `WireSurfaceDragDrop()` (from `Form1_Load`) wires every surface explicitly with the shared `Form1_DragEnter`/`Form1_DragDrop`, and `WireVlcSurfaceDragDrop()` the LibVLC view when it is lazily created. The WebBrowser ActiveX host never raises managed drag events, so on net48 only (`#If NETFRAMEWORK`) `AllowWebBrowserDrop = True` lets IE accept the file and its `Navigating` to the dropped `file://` URL is cancelled and routed through `ProcessArgument()`. **UIPI**: `ChangeWindowMessageFilterEx` admits `WM_DROPFILES`/`WM_COPYDATA`/`WM_COPYGLOBALDATA` **per window** (the form and each drop surface, re-applied on handle re-creation) and **only when the process is elevated** (`SingleInstanceProtocol.IsProcessElevated`), so a drop or forwarded file from a normal-IL Explorer reaches an elevated viewer. Never relax it at medium integrity: the only lower senders there are Low-IL sandboxes. Every path ends in `ProcessArgument()`.
- `Main_Form.RecipientsOverlay.vb` - the floating destination-folder list over `panel_Media` (`Is_Show_Recipients_Overlay`, off by default; `SPECIFICATION_RECIPIENTS_OVERLAY_DOTNET48.md`): a click maps to the same `PoMove(slot)`/`ReadShowMediaFile("DeleteFile")` as the matching DEL/0..9 hotkey. `Main_Form.ShareLauncher.vb` is the viewer's *only* Android Folder Share surface: it just finds and wakes the separate Companion app; the viewer never runs the worker.
- **[Main_Form.AudioView.vb](../../src/Main_Form.AudioView.vb)** + **[AudioMetadata.vb](../../src/AudioMetadata.vb)** + **[MediaKind.vb](../../src/MediaKind.vb)** - modern-only (whole-file `#If Not NETFRAMEWORK`). `MediaKindClassifier.KindOf(ext)` is the single classifier (`003_SPECIFICATION_SORTABLE_CONTENT_KINDS_DOTNET10.md`) and what separates audio from "video without a picture": `.mp3/.wav/.m4a/.wma/.ogg` stay in `video_File_Extensions` (LibVLC plays them either way) but paint through `PaintAudioSurface`, not the `VideoView`. Tags are parsed **off** the UI thread via LibVLC `media.Parse` and dropped on arrival if `media_Generation` moved on. With no cover, the backdrop is the `WAVE-PARTICLES` contract (`AudioVisualiser` preference, on by default; surface class "audio player backdrop": `ambient`, `full`, no tuning): section 3's constants live once in [WaveParticlesConstants.vb](../../src/Backdrop/WaveParticlesConstants.vb), the rolls and section 4 arithmetic in the pure [WaveParticlesSession.vb](../../src/Backdrop/WaveParticlesSession.vb) (`WaveParticlesSessionTests` asserts both; a source scan keeps a contract number out of `Main_Form.AudioView.vb`), and `AudioView` only draws what the session hands back. The **timer tick owns the clock** (`Stopwatch`, capped per tick) and `PaintAudioVisualiser` only presents the buffer, so a repaint for another reason never moves the animation. The timer **only runs while an uncovered audio file is on screen**; while minimised, cloaked ([BackdropHostSignals.vb](../../src/Backdrop/BackdropHostSignals.vb)), motion-reduced (`ReduceMotionActive()`: the in-app switch OR Windows "Animation effects") or on energy saver + battery it only polls for the way back. Never make it react to the audio signal (rule 17). The plate and its ink are a **declared content overlay** (`APP-STYLE` rule 5): `AudioOverlayColours` is their one table, `Main_Form.AudioView.vb` carries no colour literal, and `AudioOverlayContrastTests` holds 4.5 : 1 for text and 3 : 1 for strokes over a white and a black cover - change an alpha or an ink only through that table. The site hero is the catalog's reference script served byte-identical as `assets/wave-particles.js` - re-copy it, never edit it. `IncludeAudioInNavigation`/`IncludeVideoInNavigation` (`009`) filter a kind out of the folder listing entirely, so `N/total` matches what paging visits.
- **[Main_Form.ToVideo.vb](../../src/Main_Form.ToVideo.vb)** + **[src/Video/](../../src/Video)** - modern-only: animated WEBP/APNG/GIF to a real MP4. `VideoConvertPlan` is the pure, unit-tested half; `AnimationToVideo` drives FFmpeg, which is **not bundled** (fetched on first use like the OCR runtimes). The original is deleted **past the Recycle Bin**, and only once the MP4 exists at its final name. `IsCurrentAnimation()` is true while an animation plays **or** while the first frame of an over-budget animation is on screen (`TooLongAnimationInfo()`): then the frame count, length and transparency come from that `StagedInfo`, not from the GDI+ playback state.
- **[Main_Form.AnimationUpgrade.vb](../../src/Main_Form.AnimationUpgrade.vb)** - modern-only (whole-file `#If Not NETFRAMEWORK`), spec `241`: a long animated picture is put on screen as its **first frame** and the rest is prepared in the background. `StartGifLoopPlayback` is the one place every picture passes, so it calls `BeginAnimationUpgradeIfPreview` (a marked picture -> `AnimationUpgradeState.ShowPreview`, the status line `Анимация готовится..`, one `AnimationUpgradeJob` to the single-slot `AnimationUpgradeRunner`: ONE dedicated worker, one job in the process, the newest waiting request wins, a stale one is dropped by `media_Generation`, a running one is never interrupted and finishes into the decode cache); `StopGifLoopPlayback` calls `LeaveAnimationUpgrade`. The finished animation is swapped **in place** into the box that still shows that very preview object (`ApplyPreparedAnimation`: generation + reference identity + `TryLand`), the preview is disposed and `ApplyTranslateButtonsVisibility()` recomputed; `R` on the first frame calls `HoldAnimationPreview` so the swap never undoes the user's turn. While a preview is shown `IsCurrentStillImage()` is False (`IsAnimationPreviewShown`) and `OnMediaDisplayed` starts no auto-OCR: the editor decodes its own copy and a save would flatten the animation. A preview is never offered to the media cache (`SetActiveBoxOrigin` is skipped for a marked picture). The pure halves (`AnimationUpgradeState`, `AnimationUpgradeRunner`, `AnimationStaging`) are in `src/Imaging/` and unit-tested without a form.
- **[Main_Form.AnimationVideo.vb](../../src/Main_Form.AnimationVideo.vb)** + **[Main_Form.AnimationVideoAhead.vb](../../src/Main_Form.AnimationVideoAhead.vb)** - modern-only (both whole-file `#If Not NETFRAMEWORK`, both listed in the x86 vbproj), spec `242`; the pure halves and the rules are in `imaging-icons-archives.md`. `BeginAnimationUpgradeIfPreview` asks `TryStartAnimationVideo` **before** it starts 241's job (a marked first frame, including an over-budget one) and, for a picture that is not a stand-in, `TryStartHugeGifVideo` (a GIF over the size threshold, facts read off the GDI+-loaded picture - the decision comes after GDI+ decoded it, not before). A video takes over the SAME picture box under the guards 241 uses (`media_Generation` + the preview's identity), plays through the ordinary `PlayVideoWithVlcAsync` (the `CreateVlcMedia` hook hands it a `StreamMediaInput` over the decrypting stream; silent, `:input-repeat`, no zoom/pan/perspective/OCR/editor while it plays - `IsAnimationPreviewShown` and `TooLongAnimationInfo()` answer for it), and any failure calls `FallbackToSpec241` (for a GIF there is no 241 job: it just leaves the video state). **The ahead:** `OnAnimationVideoPlaying` calls `StartAnimationVideoAhead` once per `vlc_Play_Serial` (`animation_Video_Serial` resets on release, so it cannot tell two videos apart); a landing goes through `animation_Video_Ahead.Promote` in `TryStartAnimationVideo`. Release is `ReleaseAnimationVideoCurrent` (ends with `ReconcileAnimationVideoAhead`), purge on setting off is `PurgeAnimationVideoStore`, on exit `DisposeAnimationVideoStore` (also the ahead route); `EnsureAnimationVideoStore` is the one place the store is created and is lock-guarded because the ahead's worker calls it. Do not read form or UI state from the ahead's worker: it gets its inputs (`ffmpegExe`, background colour, `insideSecure`) captured on the UI thread by `StartAnimationVideoAhead`.
- **[Main_Form.SlotHealth.vb](../../src/Main_Form.SlotHealth.vb)** + **[SlotHealth.vb](../../src/SlotHealth.vb)** - modern-only, ticket 011: a recipient folder is probed once in the background with a 2 s ceiling and the verdict is cached; pressing the **same key twice in a row re-probes** ("the NAS is awake now"). Nothing is queued and nothing leaves the list on a failed probe. **The refusal names the real reason** (2026-10-17): the probe reads a `SlotCause` from the error CODE (`SlotCauses.OfException`, the `IOException` HRESULT - never the message; rule 6) and a server folder carries `ReasonText` from `ResourceMessages.ForFailure`; `ShowSlotRefusal` / `SlotRefusalText` build the sentence from app-owned strings, log it to `current.log`, and a late answer of a timed-out probe restates it (`ApplyLateSlotAnswer`). `Detail` stays log-only.
- **[Main_Form.FolderScanAsync.vb](../../src/Main_Form.FolderScanAsync.vb)** - modern-only (whole-file `#If Not NETFRAMEWORK`), `014_SPECIFICATION_VIEWER_CORE_S11_MODERN_ASYNC.md`: the folder walk off the UI thread. `ReadShowMediaFile` stays a synchronous pipeline - `EnsureFolderList` (from `UpdateFileIndexAndList`) starts the scan with a 100 ms grace, so a local disk or warm share finishes inside it and nothing differs; only a slower scan returns the call, and the SAME read mode runs again with `is_Continuation:=True` when the listing lands. Rules: the pool half only LISTS (`local_Provider.ListEntries`) - the extension filter, sort and metadata read UI-owned state and stay in `GetFiles`, which takes the listing through `TakeScannedListing`; while a scan runs, every read mode except `NavigationRules.IsListReplacingMode` is refused by the gate at the top of `ReadShowMediaFile`; a continuation is not counted, not throttled and **must never repeat `open_Coordinator.NoteNavigation()`** (it would cancel a file opened meanwhile); archives, resources and `-NoBack` keep the synchronous walk.
- **[MediaCache.vb](../../src/MediaCache.vb) + [Main_Form.MediaCache.vb](../../src/Main_Form.MediaCache.vb)** - modern-only (same 014 specification): pictures just paged past, kept so a flip back is not a decode. **One owner at a time** - a decoded `Image` belongs to a picture box OR the cache and is MOVED between them, never shared: `RetireBoxPicture` offers a box's picture instead of disposing it, `TakeCachedPicture` hands it back and the entry leaves the cache. Code that replaces a box's image during navigation goes through `RetireBoxPicture`; code that releases a file about to be moved or deleted keeps disposing (`ReleasePictureBoxMedia` clears the box's origin). A box remembers a `PictureOrigin`; an animated, rotated-in-place or origin-less picture is never offered. The prefetch follows `is_Nav_Backwards` (`NavigationRules.PrefetchIndex`).

**Display resilience** (a transient failure never drops the image):
- `UpdateControlVisibility()`'s dynamic-background colour analysis and `Draw_Perspective()` run their GDI+ pixel work inside `Try/Catch`: GDI+ can transiently throw (`OverflowException`, `"Parameter is not valid"`, e.g. while the background worker decodes on a slow share), and the image is already on the PictureBox, so the failure is swallowed and the frame keeps the previous tint/bars.
- `Draw_Perspective()` debounces with a trailing-edge timer: a redraw skipped by the `how_long_wait_before_draw_perspective` throttle is retried once scrolling stops.
- The background worker reads image dimensions via `Utils.GetImageDimensions()` (header parse, no GDI+), never `Image.FromFile`, so it never decodes the current image concurrently with the UI thread's `GetPixel`.
- **First media gets its bars too**: the first image at startup loads inside `Form1_Load` while `is_form_shown` is `False`, so every `Draw_Perspective()` there is gated off; `Main_Form_Shown` redraws once. `Draw_Perspective` self-gates if no picture box is visible or perspective is off.
- **Seam fix**: `GetDisplayedVerticalEdgeColors`/`GetDisplayedHorizontalEdgeColors` sample one pixel **in** from the very edge (`edgeInset`): the outermost downscaled row/column folds in the darkest border/vignette pixels and leaves a faint dark seam between photo and bar.

**[Application_Events.vb](../../src/Application_Events.vb)** - `My.MyApplication` startup hooks for single-instance behaviour (plus the modern-only `ApplyApplicationDefaults` DPI/font pin - see "Two builds, one source tree").
- On `Startup`: a path-independent named mutex (`FastMediaSorterSingleInstanceMutex`) detects a running instance (VB's built-in `IsSingleInstance` only matches the same exe path). If found, the new process forwards its command-line file path to the running window via `WM_COPYDATA` and cancels (`e.Cancel = True`). **The running instance may be either exe**, so the search runs over **both** names in `Viewer_Process_Names`. An instance whose window is hidden or minimized can have `Process.MainWindowHandle` zero - the sender falls back to `EnumWindows` over the process's top-level windows. The hand-off rules live in [SingleInstanceProtocol.vb](../../src/SingleInstanceProtocol.vb): the forward carries a `dwData` tag, `Main_Form.WndProc` acts only on a tagged message, answers it with 1 and opens the file after returning, and the sender counts a delivery **only on that answer** - a WinForms process's helper windows (GDI+, broadcast) answer 0 and must never pass for a delivery. The sender retries for up to 6 s while a viewer process exists. A mutex owned by an elevated viewer throws `UnauthorizedAccessException` for an ordinary launch - that means "another instance exists", forward to it; an elevated process runs with `IsSingleInstance = False`, because the framework's `CurrentUserOnly` pipe cannot connect across integrity levels.
- On `StartupNextInstance`: the running instance receives the new args, calls `Main_Form.ProcessArgument()`, and deliberately avoids stealing focus (restores the previously-foreground window).
- **Bare relaunch** (no file argument) restores the window instead of doing nothing: `StartupNextInstance` calls `Main_Form.RestoreMainWindow()` directly; the mutex path forwards `Main_Form.Show_Window_Command` (`::fms-show-window::`), which `External_message` intercepts. Unlike a file open it DOES take focus. `RestoreMainWindow()` (`Main_Form.Lifecycle.vb`) is just unminimize + activate + `BringToFront`: **the viewer has no tray-resident/close-to-tray mode** (that moved to the Share Manager), so closing it closes it.
- `WM_COPYDATA` payload is **UTF-8** on both send and receive (the receiver in `Main_Form.vb` decodes as UTF-8, not `PtrToStringAnsi`), so non-ASCII filenames survive.
- `ProcessArgument()` does not trust a single `File.Exists` for a `\\server` path: it probes with `File.GetAttributes` to tell a genuinely-missing file (fail fast) from a network hiccup (retry for the SMB session to recover) from an access-denied **lock** (still being written/downloaded). A locked file is watched on a timer and **opens automatically once it unlocks**, instead of being silently dropped.

**Single-exe support infrastructure** - initialized from `MyApplication.Shared Sub New()` in `Application_Events.vb`, before any `Startup`/single-instance logic runs:
- **[RuntimeBootstrap.vb](../../src/RuntimeBootstrap.vb)** - the `AssemblyResolve` half is **x86/net48 only** (`#If NETFRAMEWORK`): it resolves every managed dependency of that exe (ILMerge never runs) from `FmsPayloadmanaged/*.dll` embedded resources; the modern publish lays those down natively and embeds no managed payload. `OpenBundledAsset()` works in **both** builds and serves the other bundled assets (`FmsPayloadflags/`, `FmsPayloadhelp/port-forward.html`, `FmsPayloadicons/`) under the same frozen lookup keys.
- **[OptionalRuntimeManager.vb](../../src/OptionalRuntimeManager.vb)** - downloads the *native* OCR/VLC runtimes (`tesseract50.dll`, `libvlc.dll`) from NuGet on first use when not bundled (mainly the x86 viewer and dev builds; the offline packages bundle them via `Prepare-OcrOfflinePayload.ps1`). `CurrentArchFolder()`/`CurrentVlcArchFolder()` pick `x64\`/`x86\` and `libvlc\win-x64`/`win-x86` **by process bitness**, so both exes share one tree. Under single-file publish Tesseract needs `InteropDotNet.LibraryLoader.Instance.CustomSearchPath` set here (`Assembly.Location` is empty).
- **[AppFileLogger.vb](../../src/AppFileLogger.vb)** - writes `current.log` next to the exe (falls back to `%LOCALAPPDATA%` if not writable) and hooks `Application.ThreadException` / `AppDomain.UnhandledException` / `TaskScheduler.UnobservedTaskException`. The file is opened **append-only** (`OpenAppendOnly`: `FILE_APPEND_DATA` without `FILE_WRITE_DATA`, through `AppendOnlyFileStream`), because several processes append and `FileMode.Append` let them overwrite each other. A UI-thread exception is also reported on screen through `UiFaultReporter` (the status line): with a `ThreadException` handler attached WinForms shows nothing itself. Release strips `Debug.WriteLine`, so an error path that matters logs through `AppFileLogger`.

**[FileManager.vb](../../src/FileManager.vb)** - File I/O module
- `LoadImageWithStream()` keeps its `MemoryStream` open (prevents file-lock issues; disposed explicitly with the image); formats GDI+ can't open go through the `IImageDecoder` seam.
- **EXIF auto-orientation**: when `Is_Exif_AutoRotate` is on, `LoadImage` runs `ApplyExifOrientation()` on non-GIF images - reads the `Orientation` tag (0x0112), `RotateFlip`s the pixels upright, strips the tag. No-op when the tag is absent; failures are swallowed (a bad tag must never stop the load).
- **WEBP** is handled by the `IImageDecoder` seam (net48: WIC then ImageSharp 2; modern: ImageSharp 3, animated variants animate). Don't re-add a decoder call here.

**[Common_Module.vb](../../src/Common_Module.vb)** - global state & P/Invoke. `Is_Copying_not_Moving` is **net48 only now** - see "Move vs copy"; never read it on modern. The viewer options (`Is_Exif_AutoRotate`, `Is_HighQuality_Scaling`, `Is_Show_Info_Overlay`, `Slideshow_Base_Interval_Ms`, ..) load/save in `Main_Form.Lifecycle.vb`.

**[HqPictureBox.vb](../../src/HqPictureBox.vb)** - `PictureBox` subclass for the two media surfaces (`Picture_Box_1`/`Picture_Box_2`). When `Is_HighQuality_Scaling` is on it sets `HighQualityBicubic` on the `Graphics` **inside `OnPaint` before anything is drawn** - the base draws the zoomed image there, so the control `Paint` event (which fires after) is too late. It also owns the **viewport draw** (spec 012 section 5): when `SourceRect` and `DestRect` are both set, `OnPaint` draws just that strip (`DrawImage` with `TileFlipXY` so the zoomed edge does not darken) instead of letting the base paint per `SizeMode`; empty rects mean the base path. The overlays (OCR, info, PDF, audio surface) hang on its `MediaPaint` custom event, raised at the end of `OnPaint` on every path - not `Control.Paint`, which the viewport path cannot raise because its `OnPaint` skips the base drawing.

**[Main_Form.Zoom.vb](../../src/Main_Form.Zoom.vb) + [ZoomMath.vb](../../src/ZoomMath.vb)** - the classic zoom model, **modern build only** (both whole-file `#If Not NETFRAMEWORK`; the x86 viewer keeps the historical mechanics). `ZoomMath` is pure, unit-tested geometry; the partial is the WinForms glue. Zoom and pan are a **viewport**: `current_ImageBounds` is the rectangle the whole image occupies on `panel_Media`, `ComputeViewport` turns it into the `SourceRect`->`DestRect` pair the boxes paint, and the boxes stay panel-sized always - no control resizing, no `zoom_Scale = 0` flag (modern keeps `zoom_Scale` at 1 and x86 still writes it; shared "is this fitted?" questions go through `MediaIsAtFit()`, which reads `zoom_Mode_Free` on modern). The perspective bars and the OCR overlay re-derive their geometry from `DisplayedImageRectangleOnPanel`, so they stay aligned at any zoom. The wheel keeps flipping files by default; zoom-on-wheel is opt-in (`Zoom_Wheel_Zooms`, registry `WheelZooms`).

**Perspective background effect** (the pillarbox/letterbox bar fill; algorithm in `SPECIFICATION_BACKGROUND_EFFECT.md`):
- The numbers and the arithmetic live once, in [src/LetterboxFillMath.vb](../../src/LetterboxFillMath.vb) (contracts `LETTERBOX-BARS` / `LETTERBOX-HALO`, **owned here**; pointer [docs/contracts/LETTERBOX-FILL.md](../../docs/contracts/LETTERBOX-FILL.md)): pure, shared by both exes, each constant and function citing its rule, held to the catalog's vectors by `LetterboxFillConformanceTests`. `Main_Form.PerspectiveBackground.vb`, `Main_Form.PerspectiveHalo.vb` and `Imaging/EdgeSampler.vb` only paint and call it - do not put a number back in them (a source scan fails). A change a user can see is an amendment in the catalog first.
