# Imaging seam, icon seam and archive browsing

> Area rules for the paths above (auto-loaded). Index and the always-on rules: CLAUDE.md.

**[src/Imaging/](../../src/Imaging)** - the image-decoder seam (both builds call it; never bypass it):
- **[ImageDecoder.vb](../../src/Imaging/ImageDecoder.vb)** - `IImageDecoder` (`DecodeToImage`, `TryGetPixelSize`) + `ImageDecoderProvider`, which picks the platform decoder once. `FileManager.LoadImageWithStream` and `Utils.GetImageDimensions` only ever see this interface.
- **No licence-keyed imaging library, anywhere** (spec `270`): ImageSharp is gone from both builds and every package; `tools/Test-ImageBackendArtifacts.ps1` proves it on the built artifacts (build.ps1, Release.ps1, build-msix.ps1). Do not re-add it or any other library that needs a licence key.
- `LegacyWicImageDecoder.vb` is whole-file `#If NETFRAMEWORK`: WIC first, then **[LegacyLibWebp.vb](../../src/Imaging/LegacyLibWebp.vb)** - libwebp 1.6.0's `libwebpdecoder.dll` from `x86\` (or `x64\` on the net48 test leg) beside the exe, loaded by full path, built and import-checked against Windows 7 by `tools/Build-LibWebpDecoder.ps1` (pinned in `payload/libwebp/`, `PROVENANCE.txt`). It decodes a still WEBP only; an animated WEBP stays the known gap on Windows 7/8.1. **[ModernMagickDecoder.vb](../../src/Imaging/ModernMagickDecoder.vb)** is whole-file `#If Not NETFRAMEWORK`: **Magick.NET-Q8-x64** (no OS codec, so WEBP works on Server editions without the Store extension). Every Magick read goes through **[MagickReadGate.vb](../../src/Imaging/MagickReadGate.vb)**: the container is sniffed from the bytes by **[ImageSignature.vb](../../src/Imaging/ImageSignature.vb)** (an explicit table; anything else is `Unknown` and refused, so SVG/MVG/MSL/PDF/PS never reach ImageMagick) and the read pins that coder. `MagickResourceLimits` sets the area ceiling to `DecodeBudget.Max_Frame_Pixels` and **Disk = 0** (no temp spill). The budget is asked from headers first: **[AnimationHeader.vb](../../src/Imaging/AnimationHeader.vb)** walks WEBP/PNG chunks (hostile-safe, restores the stream position), `GifBlockWalker` GIF, a Magick ping the rest; the first-frame preview cuts the first WEBP frame out of the file instead of decoding the animation. Static frames re-encode to PNG; **animated** webp/APNG become an **in-memory GIF** with the frame delays copied, so the existing GDI+ GIF playback animates them. **AVIF/HEIC/HEIF** are sniffed by their ISO-BMFF `ftyp` header (no OS codec, no paid "HEVC Video Extensions"); that path applies `AutoOrient` itself when `Is_Exif_AutoRotate` is on, because the PNG re-encode drops the EXIF Orientation tag before `FileManager.ApplyExifOrientation` could see it. **JPEG XL** is sniffed by `ImageDecoderProvider.LooksJxl` (bare codestream `FF 0A` or the 12-byte `JXL ` signature box; the container's `ftyp` comes after it, so it never collides with the ISO-BMFF test) and decoded by `PayloadViaMagickJxl`: the frame count comes from a header-only `MagickImageInfo.ReadCollection`, the `DecodeBudget` runs before any pixel is allocated, one frame ends in the same `MagickStillToPng` as AVIF/HEIC and several become an in-memory GIF (`MagickAnimationToGif`). JXL frames of zero duration are layers of one picture, so libjxl reports a single frame for them - that file is a still, not an animation. The extensions routed through the seam instead of GDI+ are `ImageDecoderProvider.Decoder_Backed_Extensions` (`.webp` on both builds; `.avif`/`.heic`/`.heif`/`.jxl` modern only - x86 keeps them in `web_specific_image_extensions` and says "Unsupported format"). The editor does not WRITE JXL (Save As is PNG/JPEG/WEBP); `ReadDonorMetadata` still reads a JXL source through Magick so the EXIF carries over.
- **`DecodeCache*.vb` + `ImageDecodePayload.vb`** (modern-only) - on-disk decode cache in front of that seam. Only formats the app decodes **itself** are cached (animated WEBP, AVIF, HEIC, JXL); JPEG/PNG/BMP never are (GDI+ opens them in milliseconds). `DecodeCacheKey` and `DecodeCachePolicy` are pure and unit-tested, so the store is the only part that touches disk. The key is path + write time + size + `Is_Exif_AutoRotate` + format version - not a content hash, since hashing a 200 MB file is the cost being removed; eviction is oldest-write-first (`DiskCacheTrim`), not LRU. `0` in Settings switches the cache off.
- **Long animated WEBP/APNG open in two stages** (modern-only, spec `241`; the viewer half is `Main_Form.AnimationUpgrade.vb`, see `viewer-mainform.md`). `ImageLoadStage` (`Whole` / `Staged` / `FirstFrame`, in `ImageDecoder.vb`) is passed by `FileManager.LoadImageStaged` into `DecodeCache.LoadImage(path, failure, stage)`: the **display path and the prefetch ask `Staged`**, the **thumbnails (`Image_Panel_Form.CreateThumbnail`, `ShellThumbnails.DecodeFit`) `FirstFrame`**, the upgrade worker `Whole`; `LoadImageWithStream` is `Whole` and the only call net48 makes. `IImageDecoderPayload.DecodeFirstFramePayload` is a header read + `MagickReadGate.ReadFirstFrame` (the first WEBP frame cut out of the file, frame index 0 otherwise) -> one PNG with `IsPreview`, never stored, never logged as "prepared". An animation is staged when `AnimationStaging.ShouldStage` (width x height x frames over `Still_First_Min_Total_Pixels` = 10 Mpx, overflow-free); a smaller one keeps today's single step at `Staged` and a `FirstFrame` ignores even a cache hit that is an animation. The preview rides on the **Image object** through the `Tuple(Of Image, MemoryStream)` plumbing as a `ConditionalWeakTable` entry (`AnimationStaging.Mark` / `InfoOf` / `Unmark` -> `StagedInfo`: canvas, frames, `DurationMs`, `HasAlpha`, `IsTooLong`); a copy of the picture knows nothing. `DecodeBudget.Classify` separates `AnimationTooLong` (first frame only, kept in the list, "Replace with video" offered) from `FrameTooLarge` (refused, `Content`). The GIF transcode dithers up to 100 Mpx in total and uses Octree without dither above (`GifTranscodePolicy`); the cache format is v3 (`Cache_Format_Version`, bumped by spec 270 so no entry an earlier decoder wrote is served), one entry may be up to 128 MB (`min(128 MB, a quarter of the budget)`), and `Animation prepared:` is the one log line per transcode. Do not make the preview a second kind of cache entry and do not widen the tuple.
- **Animated graphics through video** (modern-only, spec `242`; the viewer half is `Main_Form.AnimationVideo.vb` + `Main_Form.AnimationVideoAhead.vb`, see `viewer-mainform.md`; setting `AnimatedViaVideo`, on by default). A long animated WEBP (the 241 first frame), an animation over the decode budget and a **huge GIF** play as a silent, looping **video** instead of a GDI+/GIF animation: FFmpeg encodes a fragmented MP4 into **memory** (`pipe:1`, 256 MB ceiling, never a plaintext file), the bytes are sealed into an ephemeral FDSEC container and LibVLC plays it through `StreamMediaInput`. The pure halves, all in `src/Imaging/` and `src/Video/` and unit-tested without a form: `AnimationVideoPolicy` (who is eligible; the huge-GIF thresholds are two tentative constants, `GifBlockWalker` reads a GIF's frames without decoding it), `AnimationVideoPlan` (the argument builder - it has **no output path**, a test reads it - and the run outcome), `AnimationVideoEncoder` (the process runner), `AnimationVideoStore` (per-run in-memory credential, hex names under `%TEMP%\FastMediaSorter-av\<pid>-<token>\`, a `DeleteOnClose` handle kept for the container's life, startup sweep of dead-pid folders), `AnimationVideoRoute` (one job at a time, `CancelCurrent()` returns a task that completes when the encoder is gone), `AnimationVideoClock` (**counts** the position: LibVLC `Time` and `EndReached` do not work for `StreamMediaInput`) and `AnimationVideoPrefetchPlan` + `AnimationVideoAheadSlot` (the one-ahead slot). Rules to hold without opening the spec: **one FFmpeg process at a time** (rule 14); the original is never changed, deleted or held past FFmpeg's read (rule 26); at most the file on screen **plus one ahead** exists (`AnimationVideoStore.MaxLeases` = 2, `Seal` throws beyond it); the ahead is started only **after the current one plays**, at below-normal priority, is cancelled when the landing differs, **promoted** when it matches (a Ready container is handed over at once, a Preparing one is waited for and delivered once) and a cancelled job is never finished; any failure falls back to the 241 route and never blocks navigation (rule 23); FFmpeg's download consent is asked once per installation and a No is remembered (rule 22). Release order and what is not covered (the source animation stays where it is, `.fd-sec` contents stay on 241) are spec 242 rules 19 and 29.

**The writing half of the same seam** - modern-only (whole-file `#If Not NETFRAMEWORK`), spec `SPECIFICATION_IMAGE_EDITOR_DOTNET10.md`. Image files are written only through this seam (nothing else re-encodes a picture); `R` rotates the display, not the file:
- **[ImageEncoder.vb](../../src/Imaging/ImageEncoder.vb)** - `IImageEncoder`/`ImageEncoderProvider` mirror the decoder's shape. The writable set is deliberately **narrower** than the readable one - `.png .jpg .jpeg .bmp .tiff .webp`; `.gif`/`.ico`/`.wmf`/`.emf`/`.exif` are refused on purpose, each for its own reason.
- **[ModernMagickEncoder.vb](../../src/Imaging/ModernMagickEncoder.vb)** - GDI+ to Magick.NET through a lossless PNG in memory (JPEG quality 92, WEBP lossless). Carries the original's EXIF across, **removes the embedded thumbnail** (it pictures the file *before* the edit and Explorer prefers it), rewrites `PixelXDimension`/`PixelYDimension`, and removes or keeps `Orientation` so it always describes the pixels actually written (`ExifOrientationPolicy`).
- **[ImageFileWriter.vb](../../src/Imaging/ImageFileWriter.vb)** - `CanReplaceOriginal` is a real open-for-write probe, run **once** per editor session (a round trip to the share); `tmp` + swap leaves no half a photo on failure. The temp name is `photo.fms-tmp.jpg`, marker **before** the extension: the encoder picks the format from the extension it is handed.
- **Editor** ([Image_Editor_Form.vb](../../src/Image_Editor_Form.vb), [Main_Form.ImageEditor.vb](../../src/Main_Form.ImageEditor.vb), `EditorGeometry.vb`, tools in `Image_Editor_Form.Tools.vb`) - `btn_Edit` and the middle-click menu's first item are shown by `IsCurrentStillImage()` through `SetToolbarItemHidden`. The editor **reads the original's bytes itself** and decodes its own copy - never `Picture_Box.Image`, which is a WEBP rebuilt through PNG, an animation flattened to GIF, or pixels already rotated with the tag stripped.

**[src/Icons/](../../src/Icons)** - the iconography seam, modern-only (whole-file `#If Not NETFRAMEWORK`), linked into the Share Manager by `<Compile Include>` like the localization engine - spec `027`, contracts `ICON-SET`/`ICON-RENDER`/`ICON-EXTERNAL` (pointer [docs/contracts/ICON.md](../../docs/contracts/ICON.md)). `IconMap` is the ONE table from control name to vocabulary id + canonical-name key; a meaning the vocabulary lacks carries an empty id and the catalog proposal's file name instead, and a test holds both. `GlyphRenderer` fills the vendored `assets/glyphs/*.svg` (embedded as `FmsPayloadglyphs/`) in the control's one colour - never a Unicode or MDL2 stand-in. It reads the catalog's SVG subset in full (group `transform`, `fill="none"` + `stroke`, `fill-rule`, opacity): a reader that skips any fails silently, which is why `IconographyContractTests` checks pixels, not just parsing. Never hand-edit a vendored glyph - `tools/Sync-IconGlyphs.ps1` re-imports (glyphs and test vocabulary), and `-Check` compares them against the **catalog** (exit 1 drift, 2 catalog unreachable; root from `-CatalogRoot` or `FMS_CONTRACTS_ROOT`); the provenance test only proves the files match their own record. A site control that must take `currentColor` carries an inline copy marked `data-glyph="<id>"`, held verbatim to the vendored file by a test. The x86 fallback keeps its Unicode toolbar glyphs under a registry exception and embeds no glyph files, so every call into this seam from shared code sits behind `#If Not NETFRAMEWORK`.

**[src/Archives/](../../src/Archives)** - archive browsing, modern-only (whole-file `#If Not NETFRAMEWORK`), spec `010_SPECIFICATION_ARCHIVE_BROWSING_DOTNET10.md`. A ZIP/CBZ is shown as a **folder**, and there is **no virtual file system**: every entry gets a real path under `%LOCALAPPDATA%\SZA\FastMediaSorter\archive-cache\<pid>-<token>\` when the archive opens, the file list is filled with those paths, and the file appears there only when something is about to show it - so the decoder, prefetch, zoom, perspective background, OCR and LibVLC keep working on plain paths.
- **[ArchivePaths.vb](../../src/Archives/ArchivePaths.vb)** - pure: the cache root and the **destination name**, built by us from the entry's last segment only (`00042_page12.jpg`). That is what makes zip-slip structurally impossible rather than filtered; the index prefix also defuses reserved device names and keeps two `cover.jpg` apart. Parse the name by hand, never with `Path.GetExtension` - it reads a colon as a volume separator and eats `a:b.jpg`.
- **[ArchiveTempStore.vb](../../src/Archives/ArchiveTempStore.vb)** - cleanup on leaving the archive, on closing the app, and a sweep of orphans on the next archive open. The sweep reads the owning pid out of the directory name and asks whether that process is still one of ours (`Common_Module.Viewer_Process_Names`, shared with the single-instance forwarding); anything older than 24 h goes regardless, because Windows reuses pids.
- **[ArchiveSession.vb](../../src/Archives/ArchiveSession.vb)** - one open archive via **SharpCompress** (modern project only). `TryEnsureExtracted` writes to `<name>.part` and renames, is serialized by a lock (the display path and the prefetch worker read one archive stream), and refuses by name: too large, bomb (ratio checked from the header, before any write), encrypted, broken. A **solid** 7z/RAR (`Kind = Sequential`) is read in ONE pass (`RunSequentialPass`, off the UI thread, own file handle, reader from `IArchive.ExtractAllEntries()` - `ReaderFactory` does not know 7z) driven by `BeginSequentialOpen` in `Main_Form.Archive.vb` with progress and Esc-cancel; entries are matched by (key, occurrence), the prefetch passes `allowSlow:=False`, and format is decided by content, never by the file name. `ArchiveEntryFilter` decides which entries become files (media only; no `__MACOSX/`, zero-byte or nested archive) and which containers open (`.zip .cbz .7z .rar .cbr`).
- **[Main_Form.Archive.vb](../../src/Main_Form.Archive.vb)** - `EnsureArchiveEntryOnDisk` is reached through `EnsureEntryLocal`, called BEFORE the display path's existence check, which would otherwise drop every entry from the list. The refusal of DEL and the recipient slots inside an archive is the archive branch of `ResourceBlocksFileOperations(verb)` in [Main_Form.Resource.vb](../../src/Main_Form.Resource.vb) - the one refusal point (see `resources-secure.md`). The registry gets `PersistableFolderPath()`, never the archive path.
