# Localization: 13 languages, one layer, two programs

> Area rules for the paths above (auto-loaded). Index and the always-on rules: CLAUDE.md.

Spec: `013_SPECIFICATION_THIRTEEN_UI_LANGUAGES.md`.

- **The key IS the Russian source string.** `Localization.T("Удалить")` - no resource ids, no `.resx`. A key with no entry returns the Russian source: visible, never a crash.
- **Engine in [src/Localization/](../../src/Localization)**, string tables beside it. The **Share Manager links the same two engine files** (`Localization.vb`, `.Persistence.vb`) via `<Compile Include>` and supplies its **own** `RegisterStrings()` + tables under [src/FastMediaSorterCompanion/Localization/](../../src/FastMediaSorterCompanion/Localization). Linked, not copied - a fix to `T`/`TF`/`TC` must not need doing twice. A project that links the engine and forgets its tables fails with `BC30451`, which is the right failure.
- **Anything carrying a value uses `TF` with a placeholder**, never concatenation: word order and direction differ per language, so `"Файл занят: " & name` cannot be translated and `TF("Файл занят: {0}", name)` can. `TranslatedValueConcatenationTests` holds it for both programs: a `&` chain with a `T`/`TC` call and a value fails the run (paragraph joins, an appended complete sentence and code only the x86 fallback compiles are not findings). `TC(context, key)` disambiguates the few Russian words that are genuinely two different things.
- **Storage**: `UiLanguage` (ISO code) under `SZA\FastMediaSorter`, with the pre-13 `Is_Russian_Language` still written as a mirror so an older exe lands on a sane language. Both programs read and write it, so a switch in either shows in the other on its next start. `Is_Russian_Language` is a derived compatibility shim in `Common_Module` (viewer only); new code must not read it.
- **Two tests, and the second one is the one that matters.** `LocalizationParityTests` holds all 12 translations per key, placeholder arity, no leaked Cyrillic and every `T`/`TF`/`TC` call site registered. `LocalizationCoverageTests` counts **strings, not flag reads** (one `Dim rus As Boolean = Is_Russian_Language` at the top of a `Select Case` once hid 44 untranslated strings behind a single read). Every Cyrillic literal must reach the layer or be a registered key; the exemptions are listed with reasons in the test.
- **Never put a smart double quote in a literal, in any language.** VB treats `“`/`”` (U+201C/U+201D) as string delimiters, so German `„…“` and Chinese `“…”` silently break the file and cascade `BC30035` dozens of lines below. Use `«…»` and `「…」`.
- **RTL is `RightToLeft = Yes` only, never `RightToLeftLayout`.** The second flag mirrors the whole window device context (Arabic came out as a mirror image) and in the viewer moves the media PictureBox that `Draw_Perspective` and the OCR overlay derive their geometry from.
- **Script fonts** (`Localization.FontFamily()`): Nirmala UI for hi/bn, Microsoft YaHei UI for zh, Segoe UI for ar/ur (the app is pinned to Microsoft Sans Serif, which has no Arabic). In the **viewer** the font goes on individual controls, never the form (DPI-unaware, pixel-tuned layout). In the **Companion** it goes on the form: those windows scale by `AutoScaleMode.Dpi`, so the font is not the scaling baseline.
- **The x86/net48 fallback ships RU+EN only** (`#If NETFRAMEWORK` cuts `Codes`): Nirmala UI arrived in Windows 8, and a language that renders as boxes is worse than none. A `UiLanguage` it does not ship falls back to English rather than throwing.
- **Site**: per-language pages live under **one** root folder, `lang/<code>/index.html`, generated by [tools/Build-SitePages.ps1](../../tools/Build-SitePages.ps1) from [tools/site-copy.json](../../tools/site-copy.json). They are render targets - edit the JSON and re-run, never the HTML (canon invariant 16); `-Check` proves the committed pages match **and** fails if a legacy per-language folder is left in the repo root. **`robots.txt` and `sitemap.xml` are render targets of the same script**: the sitemap is derived at run time (every `*.html` in the repo root plus one directory per translated language), so adding a page needs no edit. The **shared social assets are named once** at the top of the script (`$OgImage`, `$Favicon`). The prefix is the script's single `$LangDir` - URL, hreflang and output path follow it - but the hand-authored root `index.html` carries its own switcher and hreflang block that must be edited by hand to match. Pages is branch-based (`main:/`), so `/lang/ru/` needs a real directory; the old `/ru/` URLs are gone and are **not** redirected.
