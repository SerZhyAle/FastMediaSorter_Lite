# What's New / Changelog

Versions use the `YY.M.D.HHmm` format (see [BUILD_AND_RELEASE.md](docs/guides/BUILD_AND_RELEASE.md)).
The `[Unreleased]` section accumulates during regular **builds**; at **release** time it moves
into a new versioned section with a date and becomes the "What's New" text for the GitHub Release / site.

Categories: `Added`, `Changed`, `Fixed`, `Removed`.

## [Unreleased]

- **The access note in a share's code now reads in two languages (Share Manager).** The sentence that tells a phone why a connection failed (for example, that the router port is closed) used to be written in the language of the PC; the file now carries it in the PC's language followed, after one line break, by the same note in English, so a phone set to another language can still show something it understands. A PC that already speaks English writes the note once, and the share's code stays byte-identical to what older readers got.

- **The disk list no longer guesses.** When the Share Manager cannot read the state, holder or record of a shared disk, the list says "Unknown" instead of "Error" or "No", and the Open button stays off until the state is known - an unreadable answer is never taken as permission to mount or to drop a holder.

- **Two toolbar pictures come from the shared icon set.** The brush tool of the image editor and the "turn into video" button are drawn from the same vocabulary as every other icon (the brush is now a brush, not a pencil, in the editor's toolbar and on the guide page that shows it). On the website the copy buttons now say "Copied" in the page's own language instead of a check mark, and choosing Russian, English or Ukrainian from a language list is remembered for the other pages.

- **Less work behind every page flip.** The dynamic background colour (the "by side / top / bottom" and automatic schemes) and the perspective bars used to read the picture one pixel at a time through GDI+, thousands of calls per photo on a 4K image, and could fail when the decoder touched the same picture at that moment. Each frame is now copied out once and sampled from memory (both programs); the tint and the bars are identical to the level, including the rounding of the side averages. In the 64-bit program a static WEBP, AVIF or HEIC no longer keeps a second copy of the file's bytes alive beside its pixels while it is on screen - only an animation keeps its stream, because GDI+ reads the later frames from it.

- **Live sound from a phone or a watch (64-bit program).** The viewer can now listen, as it happens, to the microphone broadcast of the FastMediaSorter Android app on a phone or a watch. Right-click the file button and choose "Open live broadcast..", then paste the broadcast code (`FMSBCAST1:`), the link the phone shares or the stream address, pick the `.fmsbcast` file the phone saves, or simply drop that file on the window or open it from Explorer; the PC and the device must be on the same network. The window says LIVE and has no seek bar, no pause and no remembered position. A broken connection is retried a few times within 12 seconds and then reported ("the broadcast ended or the device is unreachable" if sound had played, "could not connect" if it never did), a watch that already has its four listeners says so at once instead of being asked again, and a session that slowly falls behind because the two devices' clocks never agree exactly jumps back to the live edge by itself. A broadcast from a newer app version asks you to update, a video broadcast says it is not supported yet, and an address only the device itself could reach (127.0.0.1) is refused by name. A live broadcast uses exactly one connection per listener - no probe request, and the system's habit of quietly retrying a request on a second connection is switched off for it, because on a watch every extra connection uses up one of its four places. Settings > Files and system gets a button that adds `.fmsbcast` files to "Open with" (and takes it away again); the installer registers nothing. The 32-bit program is unchanged.

- **Links from the programs open the page in the language the program is speaking.** The Settings window of the viewer and the tray menu, the Share Manager's windows and its offline port-forwarding guide now send a Russian-language program to the Russian page of the site and a Ukrainian one to the Ukrainian page; the other eleven languages land on their own copy of the program page and the install-trust page. The Android guide, the Server edition page and the privacy policy take the language from the address (?lang=ru / ?lang=uk, which the Server edition page and the privacy policy now read too). The Android app's site and the document-translation site follow the language as well (the Ukrainian Android page was never reachable from the viewer before), and FileDO links open its German and French copies. A page that has no copy in the language stays English.

- **Website fixes from a real browser run.** The privacy page now has the same look, theme switch and full width as every other page. The Arabic page no longer scrolls sideways on a phone (list markers hung 2 px past the edge). The generated language and trust pages load their styles from their own copy of the site instead of the published one, so a local or staged view shows what will ship. Buttons, the language and theme controls and the footer links are at least 44 px tall and wide for every pointer, not only on a touch screen.

- **The website now says which outside addresses its pages contact.** Opening a page of the site (not running the program) loads the lettering from `fonts.googleapis.com` and `fonts.gstatic.com` (Google Fonts) and, on the home page and its twelve language pages, asks `api.github.com` for the latest release so the download link points at it. Each receives your IP address and your browser's user agent and nothing else, and no analytics, tag-manager or advertising address is contacted. The privacy page has a new "This website" section in English, Russian and Ukrainian, and every language of the install-trust page carries the same paragraph. A new check, `tools/Test-SiteOrigins.ps1`, lists the outside hosts of every published page and fails when one is not declared and disclosed, or when a declared one is no longer used.

- **Ukrainian on every guide, the glossary, the subject index and the Server edition page; the privacy policy in Russian and Ukrainian.** The task guides, the glossary, 	opics.html and server.html used to switch between English and Russian only; each now has a Ukrainian block for every paragraph, and the language control offers RU / EN / UA (UA joins the two guides that already had it). The privacy policy is no longer English-only: the same address, docs/privacy.html, now switches English / Russian / Ukrainian in-page, and it is listed in the sitemap and the search index. The site check fails a page whose three languages are not the same size or whose language control offers a language the page lacks.

- **A real "page not found" for the website.** An address that does not exist on the site now shows a page in the product's own look, in English, Russian and Ukrainian, with the program page, the subject index and every guide, instead of the host's default error. The release notes stay on the GitHub Releases page, which the site links as "All releases".

- **One program, three doors, and a focused package per role.** The site now opens with what the product is - view and sort your media, and when you need it the same program is also a folder-share server and a host for FileDO virtual disks, each optional and off until you enable it - and gives each audience its own door: **a viewer** (the full package, or the Compact type for a viewer with no server), **share to Android** (the full package with the folder share server ticked, or the always-on Server edition, now widened with a "which download" first screen) and a reserved, text-only door for the planned **Media Exchange Server** (nothing to download, nothing promised). The default Server payload, every installed identity and every frozen name are unchanged.
- **Fewer native crashes while paging through audio (64-bit program).** The viewer could disappear without a message inside LibVLC - the owner's reports point at MP3 files. Everything that talks to LibVLC from a background thread is now counted and ordered: the tag read behind the audio plate and the file-details window runs one at a time and releases its media off LibVLC's own callback thread, a stop started on a background thread is waited for before the next file plays (live-broadcast restarts included), and closing the window waits, within a bound, for that work before freeing the player. A new hand-run stress script drives the real viewer through rapid next/previous and closes in the middle of a tag read; 50 sessions ended without a crash dump. The 32-bit program is unchanged.

Limits and clearing for the same cache now live together (the collapsed "cache management" group is retired), and the hints say what clearing keeps: source files stay, thumbnails rebuild, OCR language data survives while results re-recognize. ### Added

- **Diagnostics after an interrupted session.** The viewer and Share Manager now record when a previous logged session did not finish and point to Windows crash records. Diagnostic reports list crash dump names and sizes; dump contents stay on the machine.
- **The .fdd disks window opens FileDO's Disk Manager.** An **Open FileDO Disk Manager** button starts `filedo_win.exe --disks` from the FileDO bundle next to the program, or from the folder FileDO's own installer registered; when neither exists the window says so instead of guessing a path. A disk that FileDO still holds mounted is now explained in plain words (which drive, and that it must be unmounted in FileDO first) with the same button right under the message. The "FileDO disks guide" link now opens FileDO's own virtual-disks guide. All strings are in the 13 Share Manager languages.
- **Share Manager can manage file-backed FileDO disks.** The new **.fdd disks..** window selects a container or an already mounted drive, shows disk state and holder, and provides open, clean close, explicit force close, remove and separate autostart controls. A container can be shared without a letter or exposed through a local drive alias for the current Windows session. External FileDO roots stay separate from ordinary folder edits. Container mounting requires a compatible FileDO component and an administrator-capable worker; the existing LocalService host is not silently elevated.
- **The floating panels sit at the window's edge, can be pinned one by one, and come in four sizes (64-bit program).** The two toolbar rows and the status line now start flush against the left edge of the window (the right edge in a right-to-left language), stacked from the top like the docked toolbar they replaced, instead of floating in the middle. Each panel has a small pin button in its corner: a pinned panel (blue, upright pin) never hides, the others still appear when the pointer comes near; the choice is remembered per panel, and the existing "Keep floating panels visible" switch still pins all three at once. Settings > Viewing gets **Panel size** - Small, Medium (the size the panels always had), Large, or Adaptive, which also follows the window's width - applied on top of the monitor scale, and the panel **opacity** is now a slider with a live value instead of a number box.
- **A destination folder (`0..9`) can be a folder on a server (64-bit program).** In Settings, double-click a slot's folder: with servers or shares saved, the menu offers "A folder on this PC.." and each saved resource; a resource picked there makes the slot its folder, and a subfolder can be typed after the address. The recipients panel and the media menus show the slot by the resource's name. The first press of the key connects in the background - asking for the password once if none is remembered, and storing it only after the server accepted it - and then `0..9`, `Shift`+digit, the panel's copy zone, the thumbnail panel's batch and `U` work exactly as they do for a local folder: the file is sent, read back and compared before the original is deleted, a name that is already taken on the server is asked about (or renamed "(2)") just as on disk, and a missing last folder is created when the parent answers. A slot never asks the "trust this server?" question in the middle of sorting: a server whose key has not been verified yet, one that is not in the resource list, or one saved as read-only is refused with a sentence that says which. A share that needs a login and is saved as a resource works as a destination too. Taking a move back with `U` brings the file home and, because the program cannot be sure no one changed it on the server meanwhile, keeps the server's copy as well - and says so.
- **Servers and network shares that need a login open like ordinary folders (64-bit program).** Right-click the folder box (or open the folder menu of the toolbar) and choose "Resources": it lists the servers you have set up, opens the last few in one click and leads to the manager, where you add a server by hand (address, port, user, password, folder), import the `.fmscfg` file or the clipboard text that the Share Manager on this or another PC produces, test whether a server answers, edit or remove it. Typing `sftp://user@host:port/folder` in the folder box does the same, and so does dropping a `.fmscfg` file on the window - one resource opens at once, several are left in the list. A server opens exactly like a local folder: pictures, video, audio and documents are shown as if they were here (the program fetches the file it is about to show and the next one into a private cache that is deleted when you leave), `RE` asks the server again, and DEL, `0..9`, `Shift`+digit, F6 and `U` work on the server's files through the verified transfer described below - or say in one sentence why they cannot, for a folder that was shared read-only. A server's SSH key is pinned. A `.fmscfg` brings it along, so even the very first connection is checked; for a server added by hand the program shows the fingerprint and asks once (the default answer is No); a key that later changes stops the connection and shows both fingerprints, and forgetting the old one is a deliberate button in the resource's own dialog, never a dismissible prompt. When a server has several addresses (home network, IPv6, the router's forwarded port) they are tried in the order the Share Manager listed them. The password is kept only encrypted for your Windows account, or - if you untick "Remember" - in memory until the program closes; it never reaches a log or the logs package. A network share that needs a login (SMB) is opened with its own connection that the program drops when you leave it, and it never takes over a connection Windows already holds for another user. **Not yet:** a folder that the Share Manager protected with a PIN makes the whole file refuse to import (the program cannot open it as unlocked); and the display settings a file may carry for a folder - file-type filter, hidden files, comment, slideshow interval, colour - are checked but not applied, so the folder opens with the usual settings. The 32-bit program (Windows 7 and 8.1) has none of this. That verified transfer is also the one path every file operation on a server takes: a move is proven by content (SHA-256 both ways) before its source is touched, and the source is deleted only if it is still the version that was copied - otherwise both copies are kept and the program says a copy was made and the move was not. A replacement keeps the old file under a name of its own until the undo window closes, a step lost in flight is settled by asking the server - never by doing it twice - and `U` on such a transfer checks what it is about to undo (the object unchanged, the original slot free) before moving anything back. Folder sharing from this PC (the Share Manager) is unchanged.

- **A password-protected `.fd-sec` file now opens like any other picture or video (64-bit program).** These are secure containers made by FileDO: one ordinary-looking file holding another file's bytes, its real name, its size and its dates behind a password - and carrying nothing at all that says so, which is the point of them. Until now the program simply had no idea what they were. Now they appear in the folder like everything else and are counted in `N/total`; the first one you stop on asks for the password once, and from then on every other container in that sorting run opens by itself. What comes out is treated as what it actually is - a photograph zooms, gets its perspective background and its on-image translation, a video gets the seek bar, the tracks and the volume - because the real name is read out of the container and classified exactly as a file on disk would be. **Nothing is ever written to disk on the way**: there is no temporary copy, no unpacked file in a cache folder, nothing left behind if the program is killed - the picture is decoded straight out of memory and the video is played from a stream that is decrypted a block at a time as the player reads it. That is also why the picture editor, "replace with video" and "translate in the browser" are not offered for a container: each of them would have to write the decrypted file out. A container you have not unlocked shows a padlock with its name and one line saying what it needs - it is not an error, and a slideshow skips past it instead of stopping on a dialog nobody is there to answer. Holding an arrow key across a folder of them asks nothing until you settle on one, and a container you cancel is not asked about again while you stay in that folder. When something does go wrong the program says which of three things it was, and never the wrong one: the password may be wrong (**or the file was never a container, or somebody changed it** - these genuinely cannot be told apart, and claiming otherwise would be a lie half the time), or the file is damaged, which the password is never blamed for (that includes a container whose hidden name could pass for a folder path or a device such as `CON`, or whose recorded size is impossible - such a file is refused, never opened under an altered name), or it was made by a newer version of the format, which is refused by name rather than called damage. Settings -> "Files and system" -> **"Protected files"** holds the four choices: whether to list them at all, how long the password is remembered (it is held in memory only and is written nowhere - not the registry, not a file), whether the hidden file's real name is shown on screen at all, and an **"Open with"** entry for Explorer that adds this program to the menu without taking `.fd-sec` away from whatever owns it now. The middle-click menu also offers **"Forget the password"** whenever one is being held, and **"Check the whole container"** for the occasions when you want every block read and the signature verified rather than just the parts you looked at. The 32-bit program for Windows 7/8.1 does not list these files at all.

Now the write permission the phone sees always matches what the SFTP server actually allows.
