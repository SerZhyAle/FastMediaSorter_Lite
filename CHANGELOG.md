# What's New / Changelog

Versions use the `YY.M.D.HHmm` format (see [BUILD_AND_RELEASE.md](docs/guides/BUILD_AND_RELEASE.md)).
The `[Unreleased]` section accumulates during regular **builds**; at **release** time it moves
into a new versioned section with a date and becomes the "What's New" text for the GitHub Release / site.

Categories: `Added`, `Changed`, `Fixed`, `Removed`.

## [Unreleased]

### Added
- **The 64-bit viewer and Share Manager now use one shared icon vocabulary.** Toolbar and action pictures are rendered from the same catalog SVG paths instead of depending on whichever Unicode or Windows font happens to be installed, so refresh, grid, fullscreen, slideshow, file navigation, sharing, copy, add and settings have one defined meaning and a screen reader gets that meaning in the current interface language. The old 32-bit compatibility viewer keeps its established glyphs.
- **A password-protected `.fd-sec` file now opens like any other picture or video (64-bit program).** These are secure containers made by FileDO: one ordinary-looking file holding another file's bytes, its real name, its size and its dates behind a password - and carrying nothing at all that says so, which is the point of them. Until now the program simply had no idea what they were. Now they appear in the folder like everything else and are counted in `N/total`; the first one you stop on asks for the password once, and from then on every other container in that sorting run opens by itself. What comes out is treated as what it actually is - a photograph zooms, gets its perspective background and its on-image translation, a video gets the seek bar, the tracks and the volume - because the real name is read out of the container and classified exactly as a file on disk would be. **Nothing is ever written to disk on the way**: there is no temporary copy, no unpacked file in a cache folder, nothing left behind if the program is killed - the picture is decoded straight out of memory and the video is played from a stream that is decrypted a block at a time as the player reads it. That is also why the picture editor, "replace with video" and "translate in the browser" are not offered for a container: each of them would have to write the decrypted file out. A container you have not unlocked shows a padlock with its name and one line saying what it needs - it is not an error, and a slideshow skips past it instead of stopping on a dialog nobody is there to answer. Holding an arrow key across a folder of them asks nothing until you settle on one, and a container you cancel is not asked about again while you stay in that folder. When something does go wrong the program says which of three things it was, and never the wrong one: the password may be wrong (**or the file was never a container, or somebody changed it** - these genuinely cannot be told apart, and claiming otherwise would be a lie half the time), or the file is damaged, which the password is never blamed for (that includes a container whose hidden name could pass for a folder path or a device such as `CON`, or whose recorded size is impossible - such a file is refused, never opened under an altered name), or it was made by a newer version of the format, which is refused by name rather than called damage. Settings -> "Files and system" -> **"Protected files"** holds the four choices: whether to list them at all, how long the password is remembered (it is held in memory only and is written nowhere - not the registry, not a file), whether the hidden file's real name is shown on screen at all, and an **"Open with"** entry for Explorer that adds this program to the menu without taking `.fd-sec` away from whatever owns it now. The middle-click menu also offers **"Forget the password"** whenever one is being held, and **"Check the whole container"** for the occasions when you want every block read and the signature verified rather than just the parts you looked at. The 32-bit program for Windows 7/8.1 does not list these files at all.

- **Downloads show their progress and can be cancelled (64-bit program).** The OCR engine, VLC support, FFmpeg, OCR language packs, the Ollama installer and Ollama models now download in one small window with a real progress bar and a Cancel button. Cancelling leaves no half-downloaded file behind and is reported as cancelled, not as an error; a failed download says why and offers Retry.
- **"Send the log to the author" in the Share Manager.** The tray menu and the manager's settings now have their own entry, so the log of a sharing problem no longer has to be sent from the viewer's settings. It packs the same archive, shows what is inside before anything happens, and hands it to your own mail client.
- **Sharing can be switched off completely from the Share Manager.** Manager settings - Network - "Switch off server features.." stops sharing and, with one administrator prompt, removes the Windows Firewall permission the feature added. The folder list and the password are kept for when you switch it back on.

### Changed
- **Translation plates are opaque by default.** A new installation draws the plate so that it fully covers the original text, which is what makes the translation read cleanly; the "Panel opacity" slider still lowers it if you want the picture to show through. An existing installation keeps the opacity it already had.
- **"Translate in the browser" lets doc-html-translate detect the script itself.** With the source language on "Auto", the button used to pass three guessed languages as if you had chosen them, which switched off doc-html-translate's own script detection. It now passes nothing in that case, so a page in a script those three do not cover gets a clean page instead of nonsense; a language you chose is still passed.
- **Error messages say what happened and what to do (64-bit program and Share Manager).** Instead of the system's own error text, a failure now names its cause - no connection, a disk or network folder not answering, a full disk, a missing file, a file in use or without permission, damaged data - and the next step. Anything unexpected keeps its error code and points to the log you can send. The Share Manager now writes the failures it used to drop into its log.
- **OCR language packs are downloaded only when you agree (64-bit program).** Recognition used to fetch a missing language pack silently - and with automatic translation on, that happened just by turning to the next image. Now a manual translation asks first, and automatic translation skips an image it cannot read and says which pack is missing.
- **A deletion that cannot be undone always asks (64-bit program).** The "Never" choice for delete confirmation is gone: it also silenced the question for files that do not go to the Recycle Bin. A previous "Never" now means "ask only when the file will not reach the Recycle Bin". "Don't ask again" before "Replace with video" (which deletes the original past the Recycle Bin) now lasts until the program closes.
- **The Share Manager asks before the changes that cannot be taken back.** Removing a shared folder (its PIN and filters go with it), unticking the last folder while sharing, resetting the counters and removing the server role now ask first. The listen port is changed with its own "Apply port" button, which says beforehand that every QR code and router rule already handed out will stop working.
- **The permission request for sharing tells the whole story.** Before switching sharing on, the Share Manager now also mentions that it asks the router to open a port and checks through check-host.net whether that port is reachable, unless "LAN only" is ticked, and that folders opened for writing can be written over the network.
- **Smaller fixes around editing and settings (64-bit program).** The image editor's "Save" waits until something was actually edited; importing a settings file with nothing different says so instead of asking; the Explorer "Open with" entry for `.fd-sec` files is a button that says what it will do.
- **Arabic and Urdu, and screen readers (64-bit program and Share Manager).** The settings window, the thumbnail panel, the video dialogs and the enlarged QR code now follow the right-to-left direction of Arabic and Urdu, while the video playback bar always runs left to right. Toolbar buttons that show only a symbol, the Share Manager's copy buttons and the QR code have names a screen reader can read in the interface language.
- **One picture and one name per action, in more places (64-bit program and Share Manager).** A picture no longer stands for two different things: the Translate button marks automatic mode with the word "(auto)" instead of the refresh arrow the folder button already uses; the Share Manager shows a read-only folder with a padlock instead of a check mark (a check mark reads as "fine"), its status line with the shared "OK / needs attention / off" marks instead of a coloured dot, and its foldable sections with the standard expand/collapse arrows. A thumbnail that cannot be decoded now shows a picture or video symbol instead of a red square. The image editor draws its crop, brush, rectangle and oval tools from the same icon set. The same action now also has the same name everywhere - "Во весь экран", "Переместить в", "Редактирование изображения", "Слайд-шоу" in Russian, "Diashow" in German.
- **The Edit button and the read-only padlock follow the current icon catalog (64-bit program and Share Manager).** Four shared pictures had been redrawn in the catalog since they were copied in - Edit, the padlock, the phone and "back to top" - and the program still showed the old drawings. They are re-imported, and a check now compares the copies against the catalog itself, so a redrawn picture can no longer fall behind unnoticed. On the website the "back to top" button and the "All releases" link now show the same pictures as the apps instead of text arrows.
- **Toolbar symbols stay readable on any photo (64-bit program).** With the background colour taken from the picture, the toolbar chose black or white by adding up the colour's channels, which picked white on a bright green and left the symbols barely visible. It now picks by perceived brightness, so the contrast never drops below the level recommended for readable text.
- **A translated caption is never cut short any more, and it is drawn at the size of the text it replaces.** Two things about the on-image translation changed together. When a translation came out longer than the sentence it covers, the program shrank the lettering as far as it dared, grew the plate down as far as the next plate allowed, and then - out of room - simply ended the line with "..", losing the tail of a sentence you were reading. It no longer trims anything: at that point the plate is released and grows to whatever height the text needs, stopping only at the bottom edge of the picture. A released plate can reach the plate below it, and what happens then is now a fixed rule rather than luck: plates are drawn in reading order, so the lower one is drawn last and stays fully readable. Separately, the size of the lettering is now taken from the median height of the recognized **words** rather than of the whole line. A line box is stretched by whatever fell inside it - a speck of the drawing read as a comma, a stray descender - and one such artifact used to set the type size for the entire plate.
- **When the source language was only guessed, the program now refuses instead of covering the picture in nonsense.** With the source language left on "auto", text recognition runs a fixed ladder of languages and answers in one of their alphabets whatever the page really says - so a page in a script none of them covers came back as debris, and some of that debris was drawn over artwork that had been perfectly readable a moment earlier. When the language was guessed and almost everything the recognizer produced was then thrown away as not-language, the overlay is now not drawn at all and the status line says what would fix it: choose the language of the original in the OCR settings. A language you chose yourself is never second-guessed, and a page that mostly read fine keeps its translation however much texture noise came along beside it.
- **"LAN only" is now a setting of the whole share, and a code can leave out the internet address on its own (Share Manager).** The checkbox in the window that builds an access code looked like an option of that one code, but it was the switch that stops the program asking the router to open a port - for every code - and it only took effect at the next start. Ticking it for one friend therefore left the router port open until then, and quietly took the internet address away from every code handed out before. The two meanings are now two controls. In that window, **"Do not put the internet address into this code"** shapes only the code being made. **Manager settings - Network - "LAN only (no access from the internet)"** is the server-wide switch; it applies the moment you change it, and asks first while sharing is running, since it ends the internet path of every code already handed out. Your previous choice carries over to both.
- **An access code can no longer promise more - or less - than the server enforces (Share Manager).** The "Read only" and "Destination" columns of the access-code window only changed what the code *said*: a code could call a folder read-only while the login inside it could still write and delete there, or call a folder writable that the server serves read-only, so moving files into it failed on the phone. These two columns now show the folder's own setting (changed with "Edit.." in the main window) and a folder the server serves read-only is always read-only in the code.
- **Back from the Windows service to ordinary sharing, inside the app (Share Manager).** "Return to the User edition.." used to open a web page. It now does the move itself, with one administrator prompt: the service is stopped and removed, the folders, settings and host key come back, and the firewall rule points at the program again - phones keep connecting without pairing anew. "Remove server role" in an ordinary installation also puts that firewall rule back instead of leaving sharing with no inbound permission.

### Fixed
- **On-image translation: failures are no longer remembered as translations.** When the translator was not ready - no model downloaded yet in Ollama, a model too big for memory, a LibreTranslate server that does not know the language - the original text was shown on the plates with no message, saved to the cache as if it were the translation, and served "from cache" on every later visit, with T only hiding and showing it. Now such a result is shown with a status line that says what went wrong and "T will retry", nothing is cached, and T really runs it again. A translator that takes longer than two minutes to answer (a slow machine loading a large model) now says so instead of leaving "Translating.." on screen forever and throwing the recognized text away. Everything cached by earlier versions is recognized afresh once.
- **On-image translation keeps correct translations that contain "please", "sorry" or "I can't".** The check that throws away a model's refusal looked for those everyday words (in English and in Russian), so "Please wait!" translated into Russian, or a Russian "Sorry, I can't" translated into English - among the most common lines in comics - were discarded and replaced by the untranslated source. A refusal is now recognised by the model talking about the request itself. Names, brands and text that is already in the target language are no longer sent back to the model twice more for nothing. Quoted lines with curly quotes, dashes and ellipses no longer count as recognition noise.
- **Turning a picture no longer brings back the translation plates of the unturned one.** After R (or Shift+R) the plates of the upright picture could come straight back from the cache in the wrong places, and a recognition still running when you turned the picture painted its result over the turned one. Each orientation now has its own result.
- **Long webtoon and manga strips are recognised.** A tall strip was shrunk by its length before recognition until its lettering was a few pixels high and nothing was found; it now keeps readable lettering. Recognition also prepares one copy of the picture at a time instead of several at once, which on the 32-bit program for Windows 7/8.1 could run out of memory on a large photo - and if preparing the picture still fails, it now says so instead of doing nothing.
- **A missing OCR language pack is named.** The status line now says which language's recognition data is missing and where to download it (Settings -> OCR & translation -> Recognition), where the 32-bit program said "OCR engine unavailable".
- **Translating into Belarusian, Bengali or Urdu (64-bit program).** With a Bengali or Urdu interface the translation target was that language, but the settings showed "English" and the translator was asked for a language code it could not interpret; Belarusian had the same problem. All three are now named properly and Bengali and Urdu can be chosen in the list. LibreTranslate is sent the codes it actually uses (Traditional Chinese, Norwegian) and refuses Belarusian up front with a message instead of a silent failure.
- **Arabic, Persian, Hebrew and Urdu translations are laid out right to left on the plates**, so punctuation and numbers sit at the correct end.
- **The OCR cache size limit applies at once (64-bit program)** instead of after a restart.
- **Closing the program no longer waits for a recognition in progress**, which with the "best" OCR models could hang the window for seconds.
- **The Ollama installer is started only when it is genuinely signed by Ollama.** It is downloaded under a fresh random name into the program's own folder, and a file without Ollama Inc.'s valid signature is deleted and the Ollama download page opened instead.
- **Uninstalling removes the folder-sharing firewall rule again.** An installation made for you only could not delete the Windows Firewall rule that sharing had added - deleting one needs administrator rights, the uninstaller did not ask for them, and the rule stayed behind in silence. It now says what it is about to remove and asks Windows once; answer No and it tells you where the rule can be deleted later. A silent uninstall (such as `winget uninstall`) still cannot ask and leaves the rule in place, so switch sharing off in the Share Manager first. Removing sharing - on uninstall or with "Switch off server features.." - now touches only this installation's rule, and no longer also the rule of the same name the Server edition or an always-on service relies on.
- **The viewer no longer tries to install the Visual C++ runtime behind your back.** When the OCR or video runtime needs Microsoft's Visual C++ Redistributable and it is missing, the program used to download Microsoft's installer and start it silently without administrator rights - which always failed. It now names the runtime (and whether you need the x64 or the x86 one) and offers to open Microsoft's download in your browser; the installer asks for its own rights when you run it.
- **Settings - About opens the privacy policy again, and explains the Windows warnings (64-bit program).** The privacy link pointed at a page that does not exist; it now opens the policy. A new "Why Windows warns" link beside it opens the page on SmartScreen, what to click and what administrator rights are used for, in the language the program is using.
- **An access code treats its password as a key (Share Manager).** The QR code and the `.fmscfg` file carry the sharing password and any folder PIN; the access-code window now says so in a line that is always visible. "Send by email.." adds the same warning to the message and no longer leaves a copy of the file in the temporary folder - one left there by earlier versions is removed on the next send. A saved `.fmscfg` is readable by your Windows account only (where the drive supports permissions), and folder PINs no longer appear in the Share Manager's log, which "Send the logs to the author" can pack. The "Do not include the password" option no longer promises that the phone will ask for the password: whether it accepts such a code depends on the Android app version.
- **A destination folder is never shown to the phone as read-only (Share Manager).** Ticking the soft "read-only hint" on a folder that is also a copy/move destination produced a code the Android app reads as writable, while the Share Manager said read-only. A destination now ignores the hint - the checkbox and the grid cell are greyed while "destination" is on, and the hint comes back if the folder stops being a destination.
- **After a move the next file appears again, and the next arrow no longer skips one (32-bit program; 64-bit with "stay").** Since 26.8.13 the 32-bit program left the screen blank after every move, and the next arrow press stepped past the file that had slid into the moved one's place, so it was never looked at. The next file now appears at once, in both programs and in every "after an operation" mode.
- **"Go to the next file after copying" works again (64-bit program).** The checkbox had been saved and ignored, so filing one picture into several folders with Shift + digit copied a different picture each time. Unticked, the view now stays on the copied file; ticked, it moves on only once the copy has really happened. The "replace" name-collision setting now warns once per session before it first overwrites a file.
- **A copy is written the safe way, like a move (both programs).** Closing the program during a long copy to a network folder, a crash or a power cut used to leave a cut-short file under the real name in the destination folder, looking like the real thing - and with "replace", the old file there was already cut short too. A copy now goes to a temporary `*.fms-part` file first and takes its real name only when complete; the thumbnail panel's bulk copy and move go the same way.
- **A read-only photo (a camera's "protected" picture) can be moved from a memory card.** The copy used to land, the original refused to be deleted, the move was reported as failed and the file sat in both places; each retry made another "(2)" copy.
- **An action always hits the file it was started on.** A copy finishing, or a file opened from Explorer, while a question was on screen (the rename box, the name-collision question, the 32-bit delete confirmation) could switch the file underneath it - so another file was renamed, moved under the first one's name, or, on the 32-bit program, permanently deleted. The action is now cancelled if the file on screen changed while the question was open.
- **Undo is honest about what it can do (64-bit program).** U while operations are still queued now says to wait instead of taking back an older operation; a failed undo no longer adds wrong rows to the list and can be pressed again; and finishing operations, rollbacks and undos no longer edit the list of a folder you have switched to since.
- **A deletion "to the Recycle Bin" that Windows silently made permanent is now reported as permanent (64-bit program).** On a `subst` drive, a disk mounted into a folder or some virtual disks, Windows deletes for good instead of recycling and says nothing; the program now checks the Recycle Bin afterwards and says so.
- **Shift+DEL no longer leaves a "permanent" flag behind (64-bit program).** A Shift+DEL that was refused (inside a ZIP, or a moment after flipping) used to turn the next plain DEL into a deletion past the Recycle Bin.
- **Keys with Ctrl or Alt are no longer read as plain keys (both programs).** Alt+F4 opened the file chooser instead of closing the window, Alt+Space flipped a file instead of opening the window menu, Ctrl+1 moved a file and Alt+D deleted one. Holding a sort digit or DEL now acts once instead of sorting a run of files, and a double-click on a row of the floating destination list moves one file, not two.
- **Touchpads and free-spinning wheels flip one file per wheel notch (both programs),** instead of one file per tiny scroll message - a swipe used to rush past dozens of files.
- **Custom shortcuts fully own their keys (64-bit program).** A digit bound to an action now works even when that sort slot has no folder, and moving "Delete file" (or a sort slot, or "next file") to another key also retires the other factory keys it answered to - D, Shift+D, the NumPad digit, Space, PageDown.
- **Rename accepts only a name.** Typing `..\x` or `D:\other\x` moved the file to another folder or drive; now a name with `\ / : * ? < > |` is refused with a message, a change of letter case only (photo -> Photo) is allowed, and rename is refused inside a ZIP like the other file operations.
- **Error messages name the right cause (64-bit program).** A name taken at the destination or a file held open by another program is no longer reported as "no connection to the folder"; a destination slot that points at a file, or was typed with a stray space, now says what is wrong with it.
- **File associations (both programs).** `.tif` files now open like `.tiff`; in the Store version the "default viewer/player" buttons open Windows Settings instead of claiming a registration that Windows ignores there; the image button's tooltip says what it really does; old unused code that could write machine-wide associations is removed.
- **Sharing two folders with the same name, or a whole drive, no longer takes all sharing down - and no longer blames the port (Share Manager).** `D:\2024\Photos` next to `E:\Backup\Photos`, a whole drive such as `D:\`, or a label with a slash in it made the sharing worker refuse the entire list, at every start; the window then said the port was taken by another program and suggested changing it, which would have broken every router rule and code handed out without fixing anything. Names are now made unique ("Photos (2)"), a drive is named after its label or letter, and the port warning appears only when the port really could not be taken - otherwise the window shows the worker's own reason.
- **Security of the sharing service and its administrator steps (Share Manager and Server edition).** The elevated helper no longer runs the sharing program straight out of the (in a personal installation, user-writable) program folder, but only the copy it has placed in an administrators-only folder. A service start, restart, repair or upgrade re-applies folder permissions only to folders an administrator has already approved, never to whatever the share list happens to name; system folders and other accounts' profiles are refused. The service is verified to run under the LOCAL SERVICE account and is never started under any other. The manager checks that whoever answers on its control channel really is its own sharing program before sending anything, and it no longer contacts the router on its own when the window opens - only when you ask for router details - with the router's text shown as plain text.
- **The administrator steps of the Share Manager say what happened (Share Manager and Server edition).** "Grant the service access" said "Done." even when nothing had been granted; it now reports the folders it could not grant and why (a mapped network drive, for example, can never be served by the service - the manager now says so before you add one). Any failure of those steps leaves its reason in the log, and repairing the service updates it in place instead of deleting it first, which could leave the machine with no service at all. The window no longer freezes while such a step runs.
- **Smaller Share Manager fixes.** Unexpected errors are written to its log instead of showing a raw error dialog; the main window follows "Stop sharing" from the tray instead of still showing "running"; another copy of the program started once (a portable copy, a download) no longer takes over the start-with-Windows entry; a second Windows account without access to the share is told so instead of "cannot reach the companion"; installing or updating the viewer no longer stops the always-on service's sharing; withdrawing the sharing permission also removes the firewall rule Windows itself added on the first prompt; and the Share Manager now reports the same version as the viewer instead of 1.0.0.0.
- **"Send the logs to the author" no longer carries your sharing PINs, your folders or your Windows user name.** The diagnostic report used to copy every value the program keeps in the registry and hid only those whose names looked like a password. That missed the Share Manager's per-folder settings, which hold the PIN of each protected share and the paths of the shared folders, and it also sent the recently opened folders and files, the last played file and the destination folders of the sort keys. The report now lists only settings known to be harmless - switches, numbers, modes, window sizes, languages - with their values; lists of paths become a count ("3 entries, not sent"), a sort-key destination says only whether it is set, and anything else is summed into one "not sent" line. The per-folder share settings are not mentioned at all. Your user folder (`C:\Users\<name>`) is replaced by `<USER>` in the report and in the attached logs. The dialog before sending still lists exactly what is in the archive, and the program still hands it to your own mail client rather than sending anything itself (64-bit program).
- **"Share this folder.." and the "Share Manager.." button work again when the Share Manager is already running (64-bit program).** With the manager sitting in the tray, both did nothing at all - no window came forward, no folder was handed over, and nothing was logged. The call that wakes the manager named a Windows function that does not exist, failed on every click, and the failure was swallowed. It now uses the right function, waits at most two seconds for an answer so a frozen manager cannot freeze the viewer too, and if no window takes the request it starts the manager with the folder instead, so the click is never lost. A test now checks every such declaration in both programs against what Windows actually provides.
- **Escape in the settings window closes the settings window - not the whole program.** The settings window passes keys on to the viewer so that photos can be flipped while it stays open, and it passed on almost everything: Escape with a checkbox focused closed the program, and D or Delete deleted the file on screen. Only paging keys reach the viewer now (arrows, Page Up/Down, Home, End); Escape closes the settings window, the same as its close box, and D, Delete, X, Q and the sort digits do nothing to the file on screen. Both the 64-bit and the 32-bit programs are fixed.
- **The main window remembers its size when closed maximized (64-bit program).** Closing the window maximized or in full screen used to overwrite its normal size with the size of the screen; it now comes back maximized, and un-maximizing returns to the size it had. A window whose monitor has been unplugged opens on the nearest remaining one. The thumbnail panel now remembers its position on monitors to the left of or above the main one.
- **A malformed translation can no longer close the program.** Formatting a translated message with a missing value could end the program from inside a click; it now shows the message with a gap instead. Both the 64-bit and the 32-bit programs are fixed.
- **The Share Manager remembers where its window was after "Exit" from the tray.** The window saves its position and size when it closes, and "Exit" disposed of it without closing it, so the next start opened it at the old place and size.
- **A caption split across a gap in the page no longer breaks into separate plates for the wrong reason.** Where the program could not work out the page's line spacing from enough evidence - two or three lines of text and nothing else - it fell back to measuring the blank between the ink instead. That measurement is misleading on exactly the lettering it was most often applied to: capitals with no descenders sit in a box much shorter than their own line, so the blank looks large and one caption came apart. The line spacing is now always what is measured; with little evidence the program simply allows more slack, and where there is no spacing to measure at all - two phrases side by side rather than one above the other - it keeps them apart instead of merging them into one plate across the picture.
- **The Share Manager now says "update the app" when the sharing worker is newer than it is.** The worker and the manager speak a versioned protocol and the worker has always refused a version it does not know; the manager read the worker's version number and compared it against nothing, so a newer worker dropped into an older install was read as though it were the expected one - quietly, with whatever that produced. It now refuses cleanly and names both versions, and that sentence actually reaches you: in the main window, in the window that builds the QR code and settings file, and as a tray notification, and in the Server edition it names the Windows service. Before, the refusal was mistaken for "the worker is not running", so the window said it could not reach the companion and then tried to start a second worker next to the one that had just answered - it no longer starts anything once a worker has answered.
- **The Share Manager now notices when the sharing worker says no.** Every request to the worker comes back with a yes or a no, and the manager used to ignore the answer. Three places now read it. If **"LAN only"** is on and the running worker is too old to understand that setting, the main window says plainly that LAN only is **not** being enforced and that you should update or turn sharing off - before, the switch looked on while the worker could still open a router port and publish an internet address. If the worker refuses the folder list or refuses to start, you see its reason instead of "started, address not confirmed", and a refused folder list is no longer followed by a start that would have served the previous list. And "Reset counters" says when the reset did not happen, leaving the numbers as they were.
- **A cancelled Windows shutdown no longer erases your ten destination folders (both programs).** When a shutdown or sign-out was started and then cancelled (another program held it up and you chose Cancel), the viewer had already half closed itself: pictures turned into a red cross, and a minute of browsing later it saved all ten sort-key folders as empty. It now only saves on the shutdown question and closes itself down only when Windows really goes ahead.
- **Opening a file while the viewer runs as administrator (both programs).** With the viewer started from an elevated file manager, double-clicking a picture in Explorer crashed the new launch instead of handing the file over; it now opens in the running window. A file handed to a viewer that is still starting is no longer lost either - the new launch waits a few seconds for it instead of assuming it was delivered. A bare relaunch now brings the window to the front instead of only flashing the taskbar button. At the same time, an ordinary (non-administrator) viewer no longer accepts files and drops from sandboxed low-privilege programs, and only the viewer's own launches can make it open a file.
- **Importing a settings file (64-bit program).** After an import, changes made in the settings window were neither applied nor saved until the program was restarted, and the window kept showing the old values.   The honest part matters more than the bin itself. Windows keeps **no Recycle Bin at all** on a network share or a memory stick - and those are exactly the folders a sorter is opened on. The program checks where the file actually lives before it asks, and the question names the reason: to the Recycle Bin, or permanently *because it is a network drive*, *because it is removable media*, *because the bin is switched off for this drive*, *because the file is larger than the bin holds*, or simply because you held Shift. Deleting inside an archive still refuses, as before. The 32-bit program for Windows 7/8.1 is unchanged: there DEL is still final.

That middle one is what a fast sorting session wants - filing away hundreds of pictures with a question in front of every one of them is what made people switch confirmations off entirely, and switching them off meant losing the question in front of the one deletion that cannot be undone. Above it sits a switch for the Recycle Bin itself, for anyone who would rather DEL always be final; turn it off and the program says the deletion is permanent *because you asked for it*, which is the truth. The line thickness is in the picture's own pixels, not the window's, so the same setting draws the same line whatever size the window is. Closing with unsaved work asks first - and that question is deliberately not silenced by the "no confirmations" setting, which is about file operations rather than about work that exists nowhere else.

The frame then stays and waits - drag it whole, pull any of its eight handles, take as long as you like - because nothing is cut until you say so, with **Enter**, a double click inside the frame, or the "Apply crop" button that appears only while there is a frame to apply. **Esc** takes the frame away. Undo puts the picture back at its old size, and the cut itself is exact: the pixels you kept are the pixels that were there, untouched and unresampled, transparency included. Your photo's EXIF is carried over with the recorded picture size corrected to the new one, and the embedded thumbnail - which still shows the *uncropped* frame and is what Explorer would have preferred - is dropped.

- **Mutual launch from the tray**: "Open Fast Media Sorter" from the Share Manager, and the reverse call to the Share Manager from the viewer - both go through the same single-instance mechanism (the window of the already-open program simply comes to the front).
- **Opt-in server features and a firewall rule**: sharing over SFTP with an open port is an explicit, deliberate action. You can enable it with a checkbox during installation or with a button in the Share Manager - a single UAC prompt adds a Windows Firewall rule for the worker module. Until it is enabled, the program works only as a viewer/sorter and the server does not start.
- Per-folder share parameters for the phone (.fmscfg schema v2): in the Share Manager you can set resource parameters for each folder - the name shown on the phone, the type (audio library, video library, photo storage, documents, all files), the exact set of media types, scan conditions (subfolders, hidden files), a comment, a PIN, and a slideshow interval. The PIN locks the resource on the phone and always goes into the file/QR when set - if you would rather not transmit it in the code, leave the field empty and set the PIN on the phone. The file stays in the old format (v1) until a parameter is changed, so older Android app versions keep understanding it; configured parameters require an updated app.
- If there are so many settings that the QR code no longer fits, the program honestly offers to save and send the .fmscfg file instead of scanning (previously the QR-code area simply went blank).
- A "Do not include the password in the file/QR" checkbox: the access file goes out without a password, the phone asks for it on import, and the password itself is shown in the status bar - share it with the recipient separately.
- Clicking the QR code opens it in a separate window 4x larger - handy for scanning from a distance. Close it by clicking the code, pressing Esc, or using the regular close button.
- A "Show barcode" item was added to the tray icon menu - it shows the current share's QR code large, in a separate window, so you can scan it with a phone without opening the main window.
- Android sharing, one code for everything: the QR code and the .fmscfg file carry all of the PC's addresses at once - local (Wi-Fi), IPv6, and the address from the internet - and the phone connects over whichever is reachable (preferring the fast local one). A single scan works both at home and away; no need to pick a network in advance. The "Local network only" checkbox leaves only the local address in the code.
- The IPv6 address (if the PC has one) is added to the code/file and works even behind CGNAT, where ordinary port forwarding is powerless.
- A phone on the same Wi-Fi finds the PC on its own, by the host key fingerprint (mDNS announcement) - so it reconnects even if the PC's local address changed after scanning (a new DHCP lease, a Wi-Fi reconnect).
- Honest external-access check: after opening a port (UPnP), the program checks from outside whether it actually answers, and reports the real state ("works from the internet" / "port does not answer - check forwarding on the router") instead of promising access that does not exist. A short reachability note is added to the file/code - the phone shows it if it cannot connect.
- A "Login/password" button copies the SFTP login and password to the clipboard - so you can pass them separately from the file/QR.

### Changed
- The installer (offline .exe) now shows the new name "Fast Media Sorter for Windows" on every screen, in shortcuts, and in the file properties. In "Add or remove programs" the entry deliberately stays "FastMediaSorter LITE" - so that winget/Microsoft Store and updates (winget upgrade) keep working as before.
- The viewer no longer minimizes to the tray or holds the sharing worker module - the Share Manager is fully responsible for that. Closing the viewer during an active share closes it immediately, while the Share Manager tray icon stays, and the phone keeps browsing the files.
- The share is restored when the Share Manager starts, if you have used it before - previously marked folders come up automatically, without waiting for the window to open.

### Fixed
- On a config rebuild, the QR code can no longer show a stale snapshot when the new configuration failed to encode.
- On displays scaled larger than 100% (for example, 175%), the share window's elements (the QR code and the buttons) no longer run off the edge - the window expands to the needed size and everything is visible.
- The local (Wi-Fi) address no longer disappears from the exported code/file: if the primary address-detection method returned nothing (an active VPN, a virtual adapter, an IPv6-only gateway), the program now reliably finds the real network adapter. Previously, in rare cases only the internet address made it into the QR/file, and a phone on the same Wi-Fi could not connect.
- A folder marked as writable (an ordinary folder or a receiving folder) is no longer shared to the phone as read-only: previously the phone showed "Move"/"Delete" while the server rejected the file deletion.
