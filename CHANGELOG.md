# What's New / Changelog

Versions use the `YY.M.D.HHmm` format (see [BUILD_AND_RELEASE.md](docs/guides/BUILD_AND_RELEASE.md)).
The `[Unreleased]` section accumulates during regular **builds**; at **release** time it moves
into a new versioned section with a date and becomes the "What's New" text for the GitHub Release / site.

Categories: `Added`, `Changed`, `Fixed`, `Removed`.

## [Unreleased]

## [26.8.19.0130] - 2026-08-19

### Added
- **A HOW TO section on the site, and five new guides in it.** The site had three guides and no place that listed them; there is now a "HOW TO" block on the front page, on every one of the twelve translated pages, in both READMEs' usage sections and inside each guide, so any one of them leads to the rest. Five guides were written for what had none: the whole **key map** with zoom, full screen and the slideshow; the **first-time setup** - default viewer, interface language, and what happens to a file when a name collides or a folder has no Recycle Bin; **recognizing and translating** the text on a picture, with the translator that runs on your own PC; the **image editor** - draw, crop, and save over the original or beside it; and reading a **ZIP or CBZ** as if it were a folder. The guide pages are in English and Russian.
- **The program can now reopen the file you were watching, and pick a video up where you stopped (64-bit program).** Settings -> "Files and system" -> **"Resume the last file"**, off unless you switch it on. With it on, starting the program without a file opens the exact file that was on screen last time, with its whole folder listed behind it, so the arrows, the slideshow and the `N/total` counter work straight away - and a video carries on from the position it was left at, which the program has always remembered during a session and until now threw away on exit. The "Open at startup" row above it was never able to do that: it restored the *number* of the file inside the folder, so deleting, renaming or re-sorting anything earlier in the list reopened a neighbour instead. If the file has since been deleted or renamed, or sits on a drive that is switched off, the window simply stays empty - no dialog and no red line for something you never asked for - and the remembered path is kept, so the same file opens again once that drive is back. Opening the program by double-clicking a file always wins over the memory, a page inside an archive is never remembered (it does not exist by the next start), and clearing the history clears it too. The 32-bit program for Windows 7/8.1 is unchanged.

### Changed
- **The Folder Share Server now sits in the same Start-menu folder as the rest of the program.** Its installer used to make a second folder of its own, so a machine with both editions installed showed "Fast Media Sorter Folder Share Server" standing on its own next to the "Fast Media Sorter for Windows" folder that holds the viewer, the Share Manager and the uninstaller. The server's shortcut and its uninstaller moved into that same folder, and the old folder is removed when you upgrade. Nothing else about the two editions is shared - each keeps its own entry in "Apps & features", its own install folder and its own winget package, so updates still go to the right one.

### Fixed
- **The recipients panel over the picture is back (64-bit program).** The floating list of destination folders - the one you click instead of pressing a digit - stopped appearing in 26.8.13 and has been missing from every version since. It was made see-through in that release so the picture shows through it, and Windows refuses to create a see-through panel *inside* another window at all: the panel was never built, silently, and switching the setting on did nothing. It is now a small window of its own, which Windows composes properly - so it is see-through as intended, it floats over a playing video as well as over a picture, and it follows the program when the window is moved, resized or minimized.

## [26.8.15.1510] - 2026-08-15

### Added
- **The settings that were listed but did nothing now do what they say (64-bit program).** Five rows in Settings had been storing a choice and changing nothing about the program: they are now wired to the behaviour they name.

  **"Scale of a new image"** decides how the next picture opens - fitted as before, at 100 %, or at the scale you last used *in that folder*, remembered for the last fifty folders. **"Reduce animation"** switches off the halo's growth animation, and is switched on by itself for as long as Windows says animations are off - without overwriting your own choice, so turning the system setting back on brings the animation back. **"Interface during the slideshow"** hides the toolbar, or the toolbar and the status bar, while a slideshow runs; moving the mouse brings them back for a few seconds without stopping the slideshow, and leaving the slideshow restores them at once. **"Interface scale"** - a new row - sets the font and control size of the settings window itself, from 90 % to 150 %, and offers to reopen the window so the change is visible rather than promised. And the **preferred audio and subtitle languages** are drop-downs over the program's language list instead of a box to type a code into; picking Russian now matches a track that calls itself `rus`, which typing `ru` never did.

- **Keyboard shortcuts can be reassigned (64-bit program).** Settings -> "Files and system" -> "Keyboard shortcuts" opens a compact window listing every action the keyboard drives - navigation, the slideshow, rotation, deletion, zoom, OCR, and each of the ten destination folders - with the combination it answers to. Select an action, press the combination you want, and it is taken; the key it was moved off stops doing the old job, which is the part that makes a reassignment real rather than an extra key doing the same thing. A combination somebody else already holds names its owner and offers to swap the two or to leave that action without one. Windows' own combinations cannot be taken, and neither can F11 and Esc - full screen and getting out of it stay where they are. "Reset" puts one action back, "Reset all" puts back the lot, and Esc leaves the capture field without recording anything. A profile that has never opened this window behaves exactly as before.

- **"File types", "Recent files and folders" and the OCR cache got the windows they needed (64-bit program).** The file-type filter was a text field of semicolons; it is now a dialog with checkboxes grouped into images, video, audio and the remaining supported formats - tick a group or a single format, and leaving everything ticked means "all supported", including formats a later version adds. The history limits sit next to a new **"Open the history"** button: a window listing the recent files and folders, where an entry can be opened, dropped on its own, or the whole list cleared - and a path that no longer exists is shown greyed rather than quietly disappearing. The OCR cache row now states how much it occupies on disk and offers to clear it, which until now could only be done as a side effect of opening the translation tab.

- **Importing settings asks what to do with them, and exporting asks before it includes anything personal (64-bit program).** An import used to replace the profile outright. It now reads and validates the file first, lists what would change, and offers **Replace** or **Merge** - the second keeping every local choice the file does not actually override, so a file exported from a fresh profile cannot reset the rest. The previous profile is written beside the imported file as a `.backup` before anything is touched, and a file that turns out to be unreadable changes nothing at all. Export still leaves out folder paths and playback positions by default; a separate, deliberately explicit checkbox includes them and warns what that means. API keys and passwords are never exported either way.

- **U now takes back more than one operation, and covers renaming too (64-bit program).** Undo used to remember exactly one move or copy, and only that: press it twice and the second press said there was no history. It now walks back through the last 50 operations, most recent first, each file returning to the folder *and the position in the list* it came from. **F6** renaming joined them - a mistyped name is one keypress away from being put back, where before it was permanent.

  **A deletion is one of the operations it takes back.** Press U after DEL and the file comes out of the Recycle Bin - back into its folder, back to its position in the list, and back on the screen. If the name has been taken in the meantime the file is returned beside it and the status line says under which name; if the folder it came from has since been deleted, that is said plainly and nothing is recreated behind your back. And where there was nothing to bring back, U says why rather than pretending there is no history: the Recycle Bin was emptied in between, or the deletion was permanent for a named reason - your own Shift+DEL, or the network drive that has no bin at all. An operation that **failed** now leaves nothing behind either: the old history was written before the work ran, so a move that could not complete still offered to "return" a file that had never left.
- **DEL now sends the file to the Recycle Bin - and says so honestly when it cannot (64-bit program).** Deleting used to be final everywhere, and the question it asked said as much. It now goes to the Recycle Bin on an ordinary disk, so a wrong keypress is one press of **U** away from being put back - or a trip to Explorer, whichever you reach for first. **Shift+DEL** deletes past the bin on purpose, the way it does everywhere else in Windows.

  The honest part matters more than the bin itself. Windows keeps **no Recycle Bin at all** on a network share or a memory stick - and those are exactly the folders a sorter is opened on. The program checks where the file actually lives before it asks, and the question names the reason: to the Recycle Bin, or permanently *because it is a network drive*, *because it is removable media*, *because the bin is switched off for this drive*, *because the file is larger than the bin holds*, or simply because you held Shift. The line in the status bar afterwards says the same thing as the question did, so "deleted" is never ambiguous about what happened. Nothing about the deletion itself changed where there is no bin - the file goes, as it always did; only the message stopped pretending otherwise.

  The picture panel (F3) follows the same rule for a whole selection, deciding once for the folder rather than asking per file, and taking the permanent wording when a selection spans places that differ. Deleting inside an archive still refuses, as before. The 32-bit program for Windows 7/8.1 is unchanged: there DEL is still final.

  **The question before a deletion is now its own setting**, on Settings -> "Files and system", with a third answer that was not available before: ask **always**, ask **only when the file will not go to the Recycle Bin**, or **never**. That middle one is what a fast sorting session wants - filing away hundreds of pictures with a question in front of every one of them is what made people switch confirmations off entirely, and switching them off meant losing the question in front of the one deletion that cannot be undone. Above it sits a switch for the Recycle Bin itself, for anyone who would rather DEL always be final; turn it off and the program says the deletion is permanent *because you asked for it*, which is the truth. If you had previously ticked the general "no confirmations" box, deleting stays silent exactly as it was - your setting is carried over rather than reset, and from then on the two are independent, so silencing one no longer silences the other.
- **A ZIP or CBZ now opens like a folder (64-bit program).** Drag a comic or a folder of scans onto the window - or pass it on the command line - and its pictures appear as an ordinary file list: the arrows flip through them, the slideshow runs, zoom, the perspective background and the on-image translation all work exactly as they do on loose files. Nothing is unpacked in advance and nothing is left behind: the program extracts the picture it is about to show plus the next one, into a private folder of its own, and deletes that folder the moment you leave the archive or close the program. If the program is ever killed outright, the leftovers are swept away the next time an archive is opened - so a browsed archive never costs you disk space you have to find and clean yourself. The archive itself is opened read-only and is never modified. Because of that, the file operations - DEL and the 0..9 destination folders - say so instead of acting while you are inside one. Entries that are not pictures or video are ignored, as are the resource forks a Mac adds to every ZIP; an entry that names its way out of the folder (`..\..\Windows\...`) lands under a safe name inside the private folder like any other, and an entry that would expand a hundredfold is refused before a byte is written. A password-protected or truncated archive gets one plain message rather than an empty window. **7z, RAR and CBR are not open yet** - they need a different reading strategy and are the next step; a `.zip` on Windows 7/8.1 (the 32-bit program) still answers "Unsupported format", as it always has.
- **A picture can now be marked up in its own editing window and written back to disk (64-bit program).** Until now the program could read images and never write one: `R` turned the picture on screen and left the file untouched, and circling something before sending it on meant a trip to Paint and back. A pencil button next to the translation buttons - and an "Edit.." entry at the top of the middle-click menu - opens the picture in a separate window. Both appear only for a still picture; a video or a running animation has neither.

  The toolbar holds a brush, a rectangle and an ellipse, each outlined or filled, with a colour (eight one-click swatches next to the full Windows colour picker) and a line thickness. Hold **Shift** while dragging a shape for an exact square or circle. **Ctrl+Z** and the **Undo** button step back through what you have drawn; **Esc** during a drag abandons that stroke rather than the window. The line thickness is in the picture's own pixels, not the window's, so the same setting draws the same line whatever size the window is. Closing with unsaved work asks first - and that question is deliberately not silenced by the "no confirmations" setting, which is about file operations rather than about work that exists nowhere else.

  **Cropping is there too - the thing most trips to Paint are actually about.** Pick the crop tool and drag a frame: everything outside it dims, so what you are keeping is what you see. The frame then stays and waits - drag it whole, pull any of its eight handles, take as long as you like - because nothing is cut until you say so, with **Enter**, a double click inside the frame, or the "Apply crop" button that appears only while there is a frame to apply. **Esc** takes the frame away. Undo puts the picture back at its old size, and the cut itself is exact: the pixels you kept are the pixels that were there, untouched and unresampled, transparency included. Your photo's EXIF is carried over with the recorded picture size corrected to the new one, and the embedded thumbnail - which still shows the *uncropped* frame and is what Explorer would have preferred - is dropped.

  **Save** writes over the original; **Save as..** puts the result beside it in any of the six formats the program writes (PNG, JPEG, BMP, TIFF, WebP). Three things are deliberate about how it writes. Your photo's EXIF - the capture date, the camera, the coordinates - is carried across, which a naive re-save silently erases; the embedded thumbnail is dropped instead, because it is a picture of the file *before* the edit and Explorer and phones prefer it to the real pixels. The result is written beside the original and swapped in, so a share that blinks or a disk that fills leaves the photo whole rather than half of it. And **Save** is switched off, with the reason in plain words, when the original cannot be replaced - a read-only file, a format the program deliberately does not write (GIF, ICO, WMF), or a file another program is holding - while **Save as..** stays available in every one of those cases. Re-saving a JPEG asks once per session before it re-compresses, since that part cannot be undone.

  Two things this window deliberately does not do. It never zooms or scrolls: the picture is always fitted to the window, which on a 24-megapixel photo means one screen pixel covers about five of the picture's - enough to circle, crop and point at something, not enough to retouch it. And **adding text is not there yet**; it is the next step.
- **The Share Manager now has its own entry in the Start menu.** The program that drives folder sharing - and, on a machine running the always-on service, manages it - could only be reached from inside the viewer or by its tray icon. Close that icon, or have the logon autostart not fire, and there was no way left to open it short of hunting down the exe in Program Files. It now sits in the program's Start-menu group next to the viewer itself, and clicking it opens the manager window instead of starting it silently into the tray - which is what clicking a Start-menu item is asking for.

### Changed
- **The Share Manager's folder buttons now say what they do and switch off when they cannot do it.** The button that opens a shared folder's parameters was called "Options.." and stayed clickable with nothing selected, where it silently did nothing; it is now called **Edit**, in all 13 languages, and is available only while a row is selected. The list also keeps a row selected for you - the folder you added or edited last, or the most recently added one when the window opens - so the button is ready rather than greyed out on arrival. The settings button beside the header was a bare gear icon; it now carries the word **Settings** next to it.

### Fixed
- **The frame around a photo blinked off between pictures (64-bit program).** With the animated halo on, every press flipped the background to flat colour first and only then grew the new frame across it - so the frame went out and came back on each file. The frame that is on screen now stays there and dissolves into the new one as it grows, so nothing goes blank between two photos. Once the growth has finished the picture is identical to what it always was, down to the pixel - only the way it gets there changed.

- **The "Tracks" button sat in the toolbar of an empty window (64-bit program).** It is meant to appear only while a video with something to choose between is playing - more than one soundtrack, or any subtitles - and to disappear again over the next picture. It did both, but only from the first video onwards: before anything had ever been played, the button was simply there, on an empty window and over still pictures, and clicking it opened an empty menu. It now starts collapsed like the other buttons that depend on what is on screen.

- **A brief network hiccup used to shred the file list of a perfectly healthy folder (64-bit program).** Sorting off a network share or a NAS, a few seconds of the connection dropping was enough: every file the program failed to read was thrown out of the session's list before anything asked *why* it had failed. So one press of Space removed one file, the automatic skip moved to the next, that one failed for the same reason and was removed too, and the chain ran until the program announced "No readable files in this folder" - about a folder in which every file was fine. The list and your position in it came back only by re-reading the folder, and any file you had passed was silently no longer there to go back to.

  A failed read is now classified before anything touches the list. A file that will not decode is still dropped, exactly as before - that is what the skip is for. But a dropped connection, a share that stopped answering, a file another program is holding open, or a read that takes so long it has to be abandoned all leave the list untouched: the program says what happened, stops skipping instead of running down the folder, and keeps the file. When the share comes back, the next press carries on where you were, with all your files still in the list. The same question is now asked in the one other place that removed entries - the check that runs when moving to the next file, which on a dropped share is the one that fires first. The 32-bit program for Windows 7/8.1 is unchanged.

- **Switching folder sharing to the always-on Windows service could leave every shared folder unreadable while the app reported that sharing was working.** The service runs under its own Windows account rather than yours, so every shared folder has to be granted to that account - a step the Share Manager performs when you pick a folder, and when you make the switch from inside the app. The Server edition's installer had no folder list to pass on, and that was read as "there are no folders yet": true for a first installation, but not for the case that installer explicitly supports - installing over an ordinary installation that was already sharing. There the folder list came across with everything else, the service started, published all of it, and had permission on none of it. On the phone every folder refused to open; on the PC the Share Manager showed the green "Sharing from this PC is on" with the internet address next to it, and nothing anywhere said what was wrong. Three things change. The installer now grants the folders it has just migrated, before the service starts, so the share never comes up in that state. Every start, restart and repair of the service grants whatever the share list holds, so an installation that already came up without those permissions heals itself instead of staying broken until somebody finds the right button. And the app no longer calls that state working: while any shared folder is unreadable by the service, the status line says so instead of turning green, the folders in question are marked in the list and explain themselves on hover, and opening the Share Manager offers to put it right with one administrator prompt.

- **Two rows in Settings -> "Files and system" showed their internal names instead of a caption.** The rows that export and import your settings to a file read `settings_export` and `settings_import` - in every one of the 13 interface languages, right next to correctly translated buttons. Both now have a proper name and a line explaining what they do: the export deliberately leaves personal data out, and the import saves your previous profile beside the file it reads.

- **"Start with Windows" could stay ticked while Windows was quietly refusing to honour it.** Switching a startup item off in Task Manager - or in Settings -> Apps -> Startup - does not delete the entry a program wrote. Windows leaves it exactly where it is and records a veto beside it, then skips it at every logon. The Share Manager only ever read the entry itself, so it reported autostart as on: the setting looked right, the entry was right, and no tray icon appeared at logon, morning after morning, with nothing anywhere to point at. The checkbox now reports whether the program will actually start, so a veto shows up as unticked; and ticking it lifts the veto instead of rewriting an entry Windows had already decided to ignore.

- **The longest caption in the Settings window was cut off when the window was wide enough to show two columns.** "After copying or moving" needed four pixels more than it was given, so its last letters were clipped at a specific range of window widths. The gap between a caption and its control was wider than the row's own margin; it now matches, which gives every caption in every language those pixels back.

## [26.8.14.1510] - 2026-08-14

### Changed
- **Setup's "turn folder sharing on" checkbox is no longer greyed out when you install without administrator rights.** It used to be disabled with a note telling you to enable sharing later from the Share Manager, because switching sharing on writes a Windows Firewall rule. But that rule is the *only* part of the installation that needs administrator rights, so withdrawing the whole option was too blunt. Tick it now and everything installs as usual; at the very end Windows asks for approval once, for that one rule. Decline it and the program is still completely installed - it says so plainly and points at where to switch sharing on later, which takes the same single prompt. Unattended installs are unchanged: that page is never shown there, so nothing is ever enabled - and no prompt ever appears - unless a person ticks the box.

- **Setup's options page no longer runs off the bottom of the window.** The recommended companion project (doc-html-translate) took a heading, a paragraph and a bare winget command line at the end of that page, and on an ordinary display the text was cut off mid-sentence - so what the reader actually saw was a truncated advertisement with the link below the edge. It is now a single link in the same list as the two Android links above it.

### Fixed
- **On a PC that has the separate Server edition, uninstalling the ordinary app could offer to remove a service that is not its own.** Both now stage their worker in the same machine folder, so the path alone no longer identifies whose service it is; the ordinary installer now recognises its own role by the absence of the Server edition and leaves that product's service alone.

## [26.8.14.1400] - 2026-08-14

### Added
- **Round-the-clock folder sharing no longer needs a second download.** Serving folders after a reboot, with nobody signed in, meant installing a separate Server edition - a different package for what is the same program doing the same job under a different host. Now the Share Manager can make the switch itself: **"Manage hosting.." -> "Switch sharing to a Windows service.."**. One administrator prompt performs the whole move and says beforehand exactly what it will do: your folders, settings and the host key move into the machine-wide store, the service is registered and started, a firewall rule is added, and the folders you already share are granted to the service account - which is a separate account from you, and the step most easily forgotten when it is left for later. The host key is never re-issued, so phones that are already paired keep connecting. Coming back is the same window's "Return to the User edition..". The separate Server edition remains, unchanged, for machines that are set up without ever opening the app; the Microsoft Store version cannot register services and says so, pointing at the installer from the site.

### Fixed
- **Installing through winget left you with the bare viewer - no offline video codecs, no OCR language models, and no folder sharing at all.** The installer offers those three as optional parts, and then refused to write any of them unless Setup was running with administrator rights. An unattended install never is: winget starts the package silently and without elevation, which is exactly the case that was being excluded. So you downloaded the full package - around 370 MB - and what reached the disk was the two viewer programs and nothing else. The codecs and the OCR models at least healed themselves by downloading on first use, but the Share Manager and its sharing worker had no such path: the button reported that the program should be reinstalled, and reinstalling it the same way produced the same result. None of those parts ever needed administrator rights - they are ordinary files, and a personal install writes them into your own folder like everything else. They now install in both cases, and the components page in the wizard is a free choice in both as well, instead of being locked to "viewer only" without administrator rights. Administrator rights are still asked for exactly one thing, and only if you want it: turning folder sharing on, which adds a Windows Firewall rule - that stays a deliberate choice, in the wizard or later in the Share Manager.
- **On a machine running the always-on sharing service, the app could never be updated again through winget.** The installer refuses an unattended install when it finds that service, so the state of a working server is not changed without a word - but it applied that to updates as well, and winget passes no flag to say otherwise, so `winget upgrade` failed every time, for good. An update of an installation that is already on the machine now proceeds: it replaces viewer files and touches nothing the service owns. A first unattended install still stops, so a deployment script cannot quietly add a second sharing host to a server.
- **Removing the app no longer leaves a sharing server running with nothing to manage it.** If folder sharing was switched to the Windows service, uninstalling now offers to take that role away too, in the same step. Say no and it keeps serving exactly what you published; either way your settings and the host key stay, so a later reinstall does not mean re-pairing the phones.

### Changed
- **When the sharing component genuinely is missing, the program now offers to fetch it instead of saying "reinstall".** Sharing is an optional part of the installer, so a perfectly healthy installation can be without it - a compact install, a cleared checkbox, or any of the unattended installs described above. "Please reinstall" was both vague and, for the most common cause, wrong: reinstalling the same way brought back the same gap. The message now says which component is missing, explains that running the full installer over the current version adds it with your settings kept, and offers to open the download page.

## [26.8.13.2350] - 2026-08-13

### Added
- **Share Manager: a click on the enlarged QR code now also saves it as a picture and puts it on the clipboard.** Until now the code could only be looked at - to get it to someone you had to photograph the screen or save the `.fmscfg` file and explain what to do with it. Now the same left click that enlarges the code also writes it as a PNG into `Pictures\Fast Media Sorter\` and refreshes the clipboard, so `Ctrl+V` in Telegram, WhatsApp, Word or an email pastes the code as an image, and `Ctrl+V` in Explorer or an attachment area drops the file itself. Nothing is taken away: the click still steps the zoom, and repeated clicks overwrite the same file instead of leaving five copies. The picture is the code's own clean square - at least 512 pixels, never smoothed, with its white margin kept - regardless of how far the window happens to be zoomed. `Ctrl+C` copies without writing a file and `Ctrl+S` writes without touching the clipboard. Since the code is the key to your folders, the first save says so once, and if the Pictures folder cannot be written the picture goes to a temporary folder and the window tells you where.
- **The halo around a photo can now appear at three speeds, and by default it is twice as fast as before (64-bit program).** When "Perspective background ▸ Dynamic halo ▸ Animated" is on, the halo grows out of the photo's edge every time a new picture opens. That growth used to take a fixed third of a second, which on a fast sorting run meant the background was still catching up when you had already moved on. A new "Halo animation speed" drop-down sits right under the Animated checkbox with three choices: **Slow** is exactly the old timing, **Medium** is twice as fast and is what you get now, and **Fast** is four times as fast. Only the arrival changes - the halo looks identical once it has settled, at every speed, and window resizing and zooming still draw it instantly as before. The setting is remembered, and changing it applies to the next photo rather than jolting an animation already under way.

### Changed
- **The translation plate now takes its colours from the picture underneath it (64-bit program).** It used to be the same nearly-white rectangle with black text on every image, which on a dark page or a coloured panel was the most obvious blemish the feature had. The program now samples the paper and the ink from the area the text occupied and paints the plate in those, so a translation over a dark comic panel stays dark and one over a yellowed page stays on paper. Heavy display lettering, where the strokes cover more of the box than the background does, would fool a naive reading into painting everything inside out, so the decision is made from what surrounds the block rather than from the block itself; and if the pair it finds would be too faint to read, it falls back to plain dark-on-light or light-on-dark rather than producing a pretty, unreadable plate. Your overlay transparency setting still applies exactly as before. The 32-bit program keeps the old light plate.
- **Zooming and resizing a picture full of translated text got noticeably lighter.** Choosing the size of the overlay text used to walk down from 200 pixels one pixel at a time, measuring the text at each step, for every block, on every single frame - up to about a hundred and ninety measurements per block whenever the window was resized or the picture zoomed. It now tries about nine sizes instead, stepping down by eight per cent from the size of the original text.

### Fixed
- **A speech balloon comes out as one plate again, and a heading is no longer glued to the paragraph under it.** One balloon regularly broke into two or three plates. The program measured the empty space between the recognized boxes, and a line set in small capitals has no descenders, so its box is visibly shorter than the line and the space beneath it looks like a paragraph break. The translator then got three fragments instead of one sentence, so it was not only the layout that suffered but the translation itself. Lines are now grouped by the distance from the top of one line to the top of the next, which does not care how tall the ink happens to be, and a line joins a plate only if it is set in roughly the same size - which is what keeps a headline from being swallowed by the text below it.
- **A screenshot or a form no longer arrives as one plate covering most of the picture.** When separate areas of a page are set in one size, at one spacing, in one column - a list of accounts, a form, an application window - nothing about any single line says where one area ends and the next begins, and the whole page was coming back as a single plate covering four fifths of the image with the original completely hidden behind it. Such a plate is now split into one plate per line. Nothing is thrown away in the process: every recognized line still gets its translation, and an ordinary paragraph or a large dense inscription is left as the one plate it should be.
- **A long translation no longer loses its tail, and the text no longer spills outside its own plate.** If the translation did not fit, the end of it was quietly cut off and nothing said so. The program now first reduces the text size, then lets the plate grow downwards - never past the edge of the picture and never into the plate below it, so plates cannot overlap - and only if neither is enough is anything trimmed. - **Failed operations no longer lose the file from view.** A move or copy that fails (a name clash in the destination, a lock, a network glitch) used to remove the file from the list anyway. The file now stays, and undo won't offer to "return" something that never left.
- **Undo undoes what was actually done.** After moving a file, switching to copy mode and pressing U **deleted** it at the destination - the only copy left - instead of moving it back. Undo now reverses the operation that happened. Undoing the move of a folder's last file no longer crashes, and a second file operation pressed while the first is still running is refused with a clear message instead of breaking the first one.
- **Sequential slideshow reaches the end of the folder.** It used to park on the last file for good - the timer still running, the file re-read from disk on every tick - instead of returning to the start.
- **Pressing S (or I / F5) again really does halve the interval**, as documented; only the toolbar button did before.
- **Random slideshow no longer slows browsing down afterwards.** Stopping it with the mouse left preloading switched off for the rest of the session, so every step decoded from scratch.
- **Random is random.** The random slideshow replayed the same files in the same order in every session.
- **Fast browsing shows the right picture.** Under a fast flip on a slow folder, the preloaded image could appear under the wrong file's name - and a delete then acted on the file you weren't looking at.
- **Jumps (Home/End, arrows, +-10/100/1000 clicks) keep the counter and the picture in step**, even when a jump can't be carried out at that moment.
- **N** opens "jump to file number" again (it was unreachable), cancelling that dialog no longer reports an error, and a key press with a toolbar button focused no longer does its action twice.
- **The file counter after opening a single file from Explorer** counted every file in the folder, not just the media - so it announced the wrong total, End could break navigation, and DEL could empty the view.
- **Video**: switching away from a video while the player was still starting no longer lets the old video jump back over your picture a second later; two videos in quick succession no longer start two independent players (which left the first file locked); a folder with a video that only VLC can play (AVI, ZMBV, VP9, MKV) can now be sorted on the 32-bit build too - DEL and move hotkeys used to fail on it.
- **Zoom resets for each new file** (64-bit build): a zoomed-in shot left the next one shown at a wrong scale with a wrong readout, and left-click stopped browsing until you reset zoom by hand.
- **Panning follows the mouse.** Dragging a zoomed picture moved it at roughly half the speed of the hand and stuttered; grabbing it again without moving the mouse first made it jump.
- **Closing during a file operation** froze the window for about five seconds and released resources under the still-running operation.
- **The window comes back where you left it** on large and multi-monitor desktops (positions past a 1366x768-era limit, or on a monitor left of the main one, were thrown away).
- **The last-viewed position is remembered** even when you leave a folder on its first file (it used to restore a position from a previous folder).
- **Files with "-noback" in the name open.** `photo-noback.jpg` was cut down to `photo.jpg` - "file not found" - and could not be opened at all.
- Opening a file that can't be reached no longer kills navigation in the folder you already had open; a file that's still downloading is no longer opened minutes later, on top of whatever you moved on to, and is dropped properly if it disappears meanwhile; a corrupt sort setting in the registry no longer crashes startup; file sizes labelled KiB/MiB are now actually computed in KiB/MiB.

### Changed
- **Folder sharing is now noticeably more robust and safer by default**, following a security review:
  - "LAN only" now genuinely keeps the share off the internet - it stops the program from opening any router port (UPnP/NAT-PMP) or advertising an external address, not just hiding it from the QR code. It is re-applied automatically when a share is restored at startup.
  - Abandoned connections are closed after a few hours of inactivity, and a connection that stalls during the handshake is dropped within seconds - both free up the server for real use. (An updated Android app reconnects on its own on the next tap, so an open folder just keeps working.)

  - Symbolic links or junctions inside a shared folder can no longer be used to reach files outside it.

The install-mode screen now explains this choice up front, and the components that need administrator rights are shown greyed out in a per-user install. The codecs and OCR models skipped this way still download on demand later; folder sharing, however, is only added by re-running setup with administrator rights.

- The Settings window no longer forces itself to stay on top of other windows.

- **Mutual launch from the tray**: "Open Fast Media Sorter" from the Share Manager, and the reverse call to the Share Manager from the viewer - both go through the same single-instance mechanism (the window of the already-open program simply comes to the front).
- **Opt-in server features and a firewall rule**: sharing over SFTP with an open port is an explicit, deliberate action. You can enable it with a checkbox during installation or with a button in the Share Manager - a single UAC prompt adds a Windows Firewall rule for the worker module. Until it is enabled, the program works only as a viewer/sorter and the server does not start.
- Per-folder share parameters for the phone (.fmscfg schema v2): in the Share Manager you can set resource parameters for each folder - the name shown on the phone, the type (audio library, video library, photo storage, documents, all files), the exact set of media types, scan conditions (subfolders, hidden files), a comment, a PIN, and a slideshow interval. The PIN locks the resource on the phone and always goes into the file/QR when set - if you would rather not transmit it in the code, leave the field empty and set the PIN on the phone. The file stays in the old format (v1) until a parameter is changed, so older Android app versions keep understanding it; configured parameters require an updated app.
- If there are so many settings that the QR code no longer fits, the program honestly offers to save and send the .fmscfg file instead of scanning (previously the QR-code area simply went blank).
- A "Do not include the password in the file/QR" checkbox: the access file goes out without a password, the phone asks for it on import, and the password itself is shown in the status bar - share it with the recipient separately.
- Clicking the QR code opens it in a separate window 4x larger - handy for scanning from a distance. Close it by clicking the code, pressing Esc, or using the regular close button.
- A "Show barcode" item was added to the tray icon menu - it shows the current share's QR code large, in a separate window, so you can scan it with a phone without opening the main window.
- Android sharing, one code for everything: the QR code and the .fmscfg file carry all of the PC's addresses at once - local (Wi-Fi), IPv6, and the address from the internet - and the phone connects over whichever is reachable (preferring the fast local one). A single scan works both at home and away; no need to pick a network in advance. The "Local network only" checkbox leaves only the local address in the code.
- The IPv6 address (if the PC has one) is added to the code/file and works even behind CGNAT, where ordinary port forwarding is powerless.
- A phone on the same Wi-Fi finds the PC on its own, by the host key fingerprint (mDNS announcement) - so it reconnects even if the PC's local address changed after scanning (a new DHCP lease, a Wi-Fi reconnect).
- Honest external-access check: after opening a port (UPnP), the program checks from outside whether it actually answers, and reports the real state ("works from the internet" / "port does not answer - check forwarding on the router") instead of promising access that does not exist. A short reachability note is added to the file/code - the phone shows it if it cannot connect.
- A "Login/password" button copies the SFTP login and password to the clipboard - so you can pass them separately from the file/QR.
