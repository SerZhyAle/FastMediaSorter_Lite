ALWAYS-ON · FOLDER SHARE SERVER

Keep your folders reachable from your phone, even when nobody is signed in

The Server edition installs a Windows service that publishes the folders you choose over SFTP. It starts with Windows, survives logoff, and restarts itself if it ever fails. Same SFTP, same QR pairing, same Android app - only the host is different.

Four optional parts: a media and file manager that views and sorts photos and videos with one key and manages files in local folders, on servers and on connected devices; a local sharing service that shares folders over SFTP and connects this PC to an exchange account; scheduled file operations that run copy, move, delete and archive on a timetable, installed together with the Share Manager; and a Media Exchange Server that you run yourself, through which your devices reach each other - start with the manager or with the folder-sharing server, and add the rest only if you want it. This page is the server-first way in: the folder-sharing service for a machine that has to stay reachable, with the manager as an optional extra. Scheduled file operations come with this edition's Share Manager and run in the signed-in session, not in the Windows service. If you came to sort photos and videos, start with the manager instead.

Which download do you need?

Share while you are signed in - the full package

The regular installer carries the Share Manager and the SFTP worker as an optional component (ticked in the Full type, left out by Compact). Install it, open the Share Manager from the viewer or the Start menu, pick the folders and scan the QR code on the phone. No administrator rights; it serves while you are signed in. The manager is simply the rest of the same package. Download the full package · Network and router, step by step

Always on - the Server edition (the rest of this page)

A focused package for a machine whose job is to stay reachable: the same server as a Windows service that starts with Windows and serves with nobody signed in. The media and file manager is also inside, as an optional component that stays off unless you tick it on the components page. FileDO disk hosting, a capability of sharing, is the other optional extra and is ticked by default.

Do you actually need this?

Install the Server edition only when the machine's job is to stay available: a dedicated server, a VPS, a NAS-like Windows box, an always-on home server. On an ordinary PC the regular installer already shares folders while you are signed in, needs no administrator rights, and is the better choice.

Install

Download FastMediaSorter-26.10.25.1830-windows-x64-server-setup.exe from the latest release and run it as administrator. Each release ships a .sha256 sidecar next to the installer - verify it before running:

Server setup (.exe) All releases v26.10.25.1830 · 2026-10-25 · SHA-256: server-setup.exe 102.2 MB c71ca84771c8f5db36532186184a92530fad9be7691d44c72f8445d0504091a6 
Get-FileHash .\FastMediaSorter-26.10.25.1830-windows-x64-server-setup.exe -Algorithm SHA256

Windows will warn about the download - it is not code-signed - and the installer asks for administrator rights once. What the warning is, exactly what to click, everything the administrator rights are used for and how to take each back.

Or install it with winget:

winget install --id SerZhyAle.FastMediaSorter.Server
winget upgrade --id SerZhyAle.FastMediaSorter.Server
winget uninstall --id SerZhyAle.FastMediaSorter.Server

Requirements: Windows 10 version 1607 or newer, Windows 11, or Windows Server 2016 or newer, 64-bit, and administrator rights. The default Server package contains the Share Manager and the SFTP worker only - no video codecs, no OCR models. The media and file manager is an optional component, off unless you tick it on the components page (silent install: /COMPONENTS="server,filedo,viewer"); it is not offered while the User edition is installed, which already has its own viewer.

You may not need this package at all

If the ordinary version is already installed, open the Share Manager → Manager settings → SFTP sharing → Hosting → Switch sharing to a Windows service... One administrator prompt performs the whole move: the settings and the host key go into the machine store, the worker is staged under %ProgramData%\FastMediaSorterCompanion\bin (a service account cannot run an executable out of a user profile), the service is registered and started, and the folders you already share are granted to it. This Server package is the same service installed straight away, for a machine that is set up without ever opening the app. The Microsoft Store build cannot register a Windows service - there, use the installer from this site.

A silent Server install refuses to run when the User edition is present, because it would migrate your state unattended. Pass /MIGRATEFROMUSER=yes to allow it explicitly - the winget package already does.

First-time setup

The service never guesses which folders to publish. After installation it is running and sharing nothing until you choose.

Approve the installation

Setup asks for administrator rights once. It registers the FastMediaSorterCompanionSFTP service (delayed automatic start, running as LOCAL SERVICE), creates a machine state directory with a restricted ACL, and adds one program-scoped inbound firewall rule for the worker executable.

Pick the folders

The Share Manager opens at the end of setup. Add the folders to publish and tick the ones that should be visible on the phone. Use Edit for read-only access, a PIN, allowed media types and a destination folder for copies.

Grant the service access to those folders

The service runs as LOCAL SERVICE, which is not you - a folder inside your user profile is invisible to it until it is granted read access. In the Share Manager open Manager settings → SFTP sharing → Hosting and use Grant the service access to the shared folders. It adds a single read-and-execute entry per folder and records exactly what it added, so removing the server role can take back only that.

Pair the phone

Start sharing, then press Share to get the QR code or the .fmscfg file. On the phone: FastMediaSorter → Add resource → SFTP/FTP → Import from companion.

Verify it really survives a reboot

This is the test that matters, and it is the one most easily skipped. Reboot the machine and do not sign in. From the phone, open the paired resource. If it lists files, the whole chain works. From another PC you can also check the service state:

sc query FastMediaSorterCompanionSFTP

What the four states mean

The Hosting console keeps these apart on purpose, because they fail differently and a phone that cannot connect looks the same in all four:

  • Service installed - the registration exists. It may still be stopped.
  • Service running - the process is alive and answering the control channel.
  • SFTP serving - the SFTP listener is up. A running service is not automatically serving.
  • No folders configured - everything is healthy and there is simply nothing to serve.

The console also shows which host is answering right now - the Windows service or this program's own background process - and the shared state directory both of them use.

Switching between editions

Both directions preserve the host key, so a successful migration keeps the same host-key fingerprint and paired phones do not need re-pairing. If the identity cannot be validated, the migration stops before the service is registered rather than minting a replacement key.

User → Server

Run the Server installer. It stops the user-session worker, copies and validates the state into the machine store, sets the ACLs and the firewall rule, then registers and starts the service. The viewer stays installed and keeps working.

Server → User

Share Manager → Manager settings → SFTP sharing → Hosting → Return to the User edition.., or uninstall the Server package. The service is stopped and deleted, the folder permissions this product added are taken back, and the state stays where the user-session worker can pick it up.

Permissions, network and limits

  • Network paths do not work. LOCAL SERVICE presents anonymous credentials on the network, so a \\server\share root cannot be served under it - no permission change on your side can fix that. Use a local path.
  • The firewall rule is program-scoped, not port-scoped - it keeps working when the listen port changes - and it covers the domain, private and public profiles, because a server's network is usually classified Public.
  • Root confinement still applies. The service account decides what the worker can open; it never lets a phone browse outside the folders you configured.
  • Access from the internet still needs a port forward or a working UPnP, exactly as in the User edition. The Share Manager can test it from outside; if it reports CGNAT, port forwarding cannot help.

Backup and restore

Everything worth keeping lives in one directory:

%ProgramData%\FastMediaSorterCompanion\

It holds the host key, the SFTP credential, the folder list, the port and the usage counters. Copy it, as administrator, to restore the same identity onto a rebuilt machine - the phones reconnect without re-pairing. Two rules: keep the backup at least as protected as the original (it contains the private host key and the SFTP password, which is why the directory's permissions are restricted in the first place), and never publish it or paste its contents into a bug report.

Uninstall

Uninstalling stops and deletes the service before any file is removed, takes back the folder permissions it recorded, and removes the firewall rule - leaving no listening port and no orphaned service registration. The state directory is deliberately kept, because it holds the identity your phones trust. Delete it by hand only if you want every paired phone to pair again.

If something goes wrong

  • Share Manager → Manager settings → SFTP sharing → Hosting has Start, Stop, Restart and Repair the service registration. Repair re-registers the service with the correct command line, account, start type and recovery actions, whatever an older version or a hand edit left behind.
  • Every elevated action appends to %ProgramData%\FastMediaSorterCompanion\install-share-service.log; the service host writes failures to service.log in the same folder.
  • After a reboot the service may come up before the network is ready. It retries discovery and reachability on its own with a widening delay - no restart needed - so give it a minute before assuming it is broken.
Microsoft Store

Store installs provide User mode only. The Server edition is obtained from GitHub, from this page, or through winget - it needs a machine service, machine data permissions, folder permission grants and an administrator-led deployment, which are outside what the Store product does.
